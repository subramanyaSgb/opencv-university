# 11.5 Level and bit-plane slicing

<Definition term="Level slicing and bit-plane slicing">two ways of picking out part of the grey-value information. Level slicing highlights all pixels whose value lies in a chosen band. Bit-plane slicing splits each 8-bit value into its 8 binary digits and looks at one digit (one "plane") at a time.</Definition>

Both are point operations that answer "where are the pixels with these values?" Level slicing is the direct ancestor of thresholding (Module 13); bit planes show how the information is spread over the bits, which matters for compression, watermarking (4.6) and quantisation (3.2).

## 1. An analogy

Level slicing is a highlighter pen on a contour map: colour everything between 300 m and 400 m altitude. Bit-plane slicing is like reading a price by its digits: the thousands digit tells you most, the cents digit almost nothing.

## 2. Level slicing

- **Binary version**: a mask of the band, exactly `cv2.inRange(img, low, high)`.
- **Keep-background version**: highlight the band, leave the rest visible for context.

<CurveLab kinds={["identity", "slice", "threshold"]} initial="slice" caption="Level slicing: choose the band and whether the other values are kept or set to black. A threshold is the special case with a band from t + 1 to 255." />

Use cases: highlight a material with a known grey range (a solder joint, a glue bead) for display; build a mask of a range for measurement; check which pixels are near saturation (band 250–255).

## 3. Bit planes

An 8-bit value is a sum of powers of two: v = b₇·128 + b₆·64 + … + b₁·2 + b₀·1. Plane k is the image of bit bₖ for every pixel.

| Plane | Weight | What it shows |
| --- | --- | --- |
| 7 (most significant) | 128 | a binary image: ≥ 128 or not (a threshold at 128) |
| 6, 5 | 64, 32 | coarse structure |
| 4 … 2 | 16 … 4 | finer shading |
| 1, 0 (least significant) | 2, 1 | mostly noise; a hiding place for watermarks (4.6) |

<BitPlaneLab caption="Each pixel's 8 bits, one plane at a time. The top planes show the scene, the bottom ones look like noise." />

The top 4 planes alone reconstruct the image with an error of at most 15 grey levels (PSNR about 29 dB): this is what reducing a camera from 8 to 4 bits per pixel would do (3.2).

## 4. Industrial example

A dispensing-check station displays the camera image with the glue bead's grey band (95–130) highlighted in a strong colour, keeping the rest visible: operators see immediately where the bead is too thin (band breaks) or too wide. The measurement itself uses the binary slice (`inRange`) to compute bead width per column. A second, "near saturation" slice (250–255) is shown in red during set-up to make sure the lighting does not clip the glossy bead.

## Code

Two examples: level slicing and bit planes from scratch, and the OpenCV equivalents.

### 1. From scratch: slices and planes

```python
import numpy as np
import cv2

img = cv2.imread("sample-scene.png", cv2.IMREAD_GRAYSCALE)
lo, hi = 100, 150
band = (img >= lo) & (img <= hi)
binary = np.where(band, 255, 0).astype(np.uint8)                 # level slicing, others black
keep = np.where(band, 255, img).astype(np.uint8)                 # level slicing, others kept
print(f"pixels in {lo}..{hi}: {band.mean():.1%} | binary values {np.unique(binary).tolist()} | kept-version max outside band {int(keep[~band].max())}")

planes = [(img >> k) & 1 for k in range(8)]                      # bit planes 0 (LSB) .. 7 (MSB)
print("fraction of 1s per plane 0..7:", [round(float(p.mean()), 2) for p in planes])
rebuilt = sum(p.astype(np.uint16) << k for k, p in enumerate(planes)).astype(np.uint8)
top4 = sum(planes[k].astype(np.uint16) << k for k in range(4, 8)).astype(np.uint8)
print("rebuilt == original:", np.array_equal(rebuilt, img), f"| top 4 planes only: max error {int(np.abs(img.astype(int) - top4).max())}, PSNR {cv2.PSNR(img, top4):.1f} dB")
```

Output:

```text
pixels in 100..150: 23.6% | binary values [0, 255] | kept-version max outside band 255
fraction of 1s per plane 0..7: [0.5, 0.5, 0.5, 0.5, 0.53, 0.58, 0.46, 0.44]
rebuilt == original: True | top 4 planes only: max error 15, PSNR 29.2 dB
```

- The low planes contain 1s exactly half the time: they behave like random noise. The high planes reflect the scene's brightness distribution.
- `img >> k & 1` extracts bit k; shifting back (`<< k`) and summing rebuilds the image exactly.

### 2. OpenCV: inRange and bitwise operations

```python
import numpy as np
import cv2

mask = cv2.inRange(img, lo, hi)                                    # level slicing = inRange on one channel
print("inRange == band:", np.array_equal(mask > 0, band))
msb = cv2.bitwise_and(img, 0x80)                                   # keep only bit 7 (value 128 or 0)
print("bit 7 via bitwise_and:", np.unique(msb).tolist(), "| equals img >= 128:", np.array_equal(msb > 0, img >= 128))
quant = cv2.bitwise_and(img, 0xF0)                                 # zero the 4 low bits: 16 grey levels
print("levels after & 0xF0:", len(np.unique(quant)))
```

Output:

```text
inRange == band: True
bit 7 via bitwise_and: [0, 128] | equals img >= 128: True
levels after & 0xF0: 16
```

- `cv2.bitwise_and(img, 0xF0)` keeps the top 4 planes: a fast 16-level quantisation.
- Plane 7 is exactly a threshold at 128.

## OpenCV API notes

**Level slicing**: `cv2.inRange(src, low, high)` (inclusive); combine with `np.where` or `cv2.bitwise_or` / `cv2.copyTo` to highlight on top of the original.

**Bit planes**: `cv2.bitwise_and(img, 1 << k)`; NumPy `(img >> k) & 1`; `np.unpackbits` for all planes at once.

**Display**: multiply a 0/1 plane by 255 to see it.

## Where it fails

- **Noise at band edges**: pixels near `low` or `high` flicker in and out; smooth first or use hysteresis (13.6).
- **Uneven lighting** moves materials out of their band (global slicing assumes stable lighting).
- **Bit planes of non-8-bit data** need more planes (12-bit: 12) and their meaning depends on the encoding.

## ⚠️ Common mistakes

<Callout kind="mistake">

- **Exclusive vs inclusive limits** (inRange includes both).
- **Showing a 0/1 bit plane without scaling** (it looks black).
- **Signed shifts on int8 data** or Python ints instead of uint8 arrays.

</Callout>

### Gray code planes

In plain binary, a step from 127 to 128 flips all 8 bits, so every plane changes at that edge. In the Gray code (gᵢ = bᵢ XOR bᵢ₊₁), neighbouring values differ in exactly one bit: the planes are smoother and compress better with binary methods. JBIG and some lossless image coders use Gray-coded bit planes for this reason [1].

</GoDeeper>
