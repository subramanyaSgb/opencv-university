# 15.6 Augmentation

<Definition term="Data augmentation">creating extra training images by applying random, label-preserving changes (flips, rotations, scaling, brightness, noise, occlusion) to the images you have, so that a model learns to ignore those changes.</Definition>

A model learns from examples. If every training image of a good part was taken under the same light, at the same angle, the model may learn the light and the angle along with the part. Augmentation shows it the same parts under many plausible variations, so that it has to rely on what really matters. It is preprocessing in reverse: instead of removing variation at inference time (15.1–15.5), you add it at training time.

## 1. An analogy

Teaching a child what a cup is: you show cups from above and from the side, in sunlight and lamplight, half behind a book. After that, the child recognises a cup in any kitchen, not just the one in the photo.

## 2. Two kinds of augmentation

<Flow
  steps={[
    { label: "Training image + its label (class, box, mask)", tone: "data" },
    { label: "Random geometric change: flip, rotate, scale, shift, perspective", tone: "process" },
    { label: "Random photometric change: brightness, contrast, gamma, colour, noise, blur", tone: "process" },
    { label: "Optional occlusion: cutout / random erasing", tone: "process" },
    { label: "Augmented image + transformed label → training", tone: "result" },
  ]}
/>

- **Geometric** changes move pixels; labels with positions (boxes, masks, keypoints) must be transformed **with the same matrix**.
- **Photometric** changes alter values only; positions stay, class labels stay.
- Each epoch draws new random parameters, so the model rarely sees exactly the same image twice.

<AugLab caption="Eight random variants of the same labelled image. Switch augmentations on and off and change the strength. The magenta box is the label of the red disc, transformed with the image: it must keep surrounding the disc." />

## 3. Label preservation: only augment what does not change the answer

| Augmentation | Safe when | Breaks the label when |
| --- | --- | --- |
| Horizontal flip | objects are mirror-symmetric in meaning | text, left/right parts, chirality ("b" ↔ "d") |
| Rotation | parts appear at any angle | the angle is the defect ("tilted label" class) |
| Scale | camera distance varies | size is the criterion ("hole too small") |
| Brightness/contrast | lighting varies in production | brightness is the criterion ("too dark print") |
| Colour/hue shift | colour does not matter | colour is the class (red vs orange caps, 10.7) |
| Cutout | partial occlusion happens | the cut-out covers the small defect that defines the label |

The rule: augment with the variations that **occur in production** and that **do not change the answer**. A cap sorter that classifies by colour must not use hue shifts; a scratch detector can use rotations freely.

## 4. Real numbers: labels follow the image

Four random geometric + photometric variants of `sample-color.png` (rotation ±20°, scale 0.7–1.3, random flip, gain 0.6–1.4, offset ±40), with the disc's box transformed by the same matrix:

| Sample | Transformed box (x, y, w, h) | Pixel at the box centre (B, G, R) |
| --- | --- | --- |
| 0 | (23, 61, 102, 102) | (32, 32, 222) |
| 1 | (−6, 62, 132, 132) | (4, 4, 151) |
| 2 | (−13, 22, 123, 123) | (5, 5, 255) |
| 3 (flipped) | (196, 23, 109, 109) | (11, 11, 255) |

The box centre is always on the red disc. Two details matter in practice: the box of a rotated object grows (it encloses the rotated corners), and boxes can leave the image (x = −13) and must be clipped, or dropped if too little remains.

## 5. Industrial example

A weld-defect classifier had 300 labelled images from one station. Augmentations were chosen from the station's real variation: small rotations (±5°, the fixture tolerance), brightness ±15 % (lamp ageing, measured over a month), slight blur (focus drift) and sensor-like noise. Flips were allowed (welds are symmetric in meaning); colour changes were not used (monochrome camera). Validation used images from a different week, never augmented. The aim: a model that keeps its accuracy when the lamp is replaced or the fixture wears, which is checked on validation images taken after such a change.

## Mini exercise

**Q1.** A model reads digits on labels. Is a horizontal flip a good augmentation? A rotation of ±5°?

<Solution>

**Flip: no**, mirrored digits are not valid digits (and "2" and "5"-like shapes change). **±5° rotation: yes**, if labels are applied with small angle variation.

</Solution>

**Q2.** Why must augmented copies of an image never end up in the validation set while the original is in the training set?

<Solution>

The model has effectively seen that image; validation then measures memory, not generalisation, and the score is too optimistic.

</Solution>

## Code

Two examples: a seeded geometric + photometric augmentation with box transformation, then masks and clipping.

### 1. Augment an image and its box

```python
import numpy as np
import cv2

img = cv2.imread("sample-color.png")
h, w = img.shape[:2]
box = np.array([[25, 50], [115, 50], [25, 140], [115, 140]], np.float32)   # corners of the red disc's box

def augment(image, rng):
    angle, scale = rng.uniform(-20, 20), rng.uniform(0.7, 1.3)
    M = cv2.getRotationMatrix2D((w / 2, h / 2), angle, scale)
    if rng.random() < 0.5:                                         # horizontal flip, folded into the matrix
        M = np.array([[-1, 0, w], [0, 1, 0]]) @ np.vstack([M, [0, 0, 1]])
    out = cv2.warpAffine(image, M, (w, h), flags=cv2.INTER_LINEAR, borderMode=cv2.BORDER_CONSTANT, borderValue=0)
    gain, offset = rng.uniform(0.6, 1.4), rng.uniform(-40, 40)
    out = cv2.convertScaleAbs(out, alpha=gain, beta=offset)         # photometric: positions unchanged
    pts = cv2.transform(box[None], M)[0]                            # same matrix for the label
    x0, y0 = pts.min(0)
    x1, y1 = pts.max(0)
    return out, (x0, y0, x1 - x0, y1 - y0), M

rng = np.random.default_rng(42)                                      # seeded: reproducible augmentations
for i in range(4):
    out, b, M = augment(img, rng)
    disc = out[int(b[1] + b[3] / 2), int(b[0] + b[2] / 2)]
    print(f"sample {i}: box ({b[0]:.0f}, {b[1]:.0f}, {b[2]:.0f}, {b[3]:.0f}) | pixel at box centre {disc.tolist()}")
```

Output:

```text
sample 0: box (23, 61, 102, 102) | pixel at box centre [32, 32, 222]
sample 1: box (-6, 62, 132, 132) | pixel at box centre [4, 4, 151]
sample 2: box (-13, 22, 123, 123) | pixel at box centre [5, 5, 255]
sample 3: box (196, 23, 109, 109) | pixel at box centre [11, 11, 255]
```

- The flip is the matrix [[−1, 0, w], [0, 1, 0]] applied after the rotation; combining them into one matrix means one `warpAffine` (one interpolation) and one label transform.
- `cv2.transform(points[None], M)` applies a 2 × 3 matrix to an array of points.

### 2. Masks and clipped boxes

```python
import numpy as np
import cv2

mask = np.zeros((h, w), np.uint8)
cv2.circle(mask, (70, 95), 42, 255, -1)                             # segmentation label of the disc
rng = np.random.default_rng(42)
out, b, M = augment(img, rng)
mask_aug = cv2.warpAffine(mask, M, (w, h), flags=cv2.INTER_NEAREST)  # nearest: keep the mask binary
red = (out[..., 2] > 100) & (out[..., 1] < 80)
print(f"mask pixels {cv2.countNonZero(mask)} -> {cv2.countNonZero(mask_aug)} | values {np.unique(mask_aug).tolist()} | mask on red: {red[mask_aug > 0].mean():.1%}")

for b in [(-6, 62, 132, 132), (-13, 22, 123, 123), (300, 10, 40, 40)]:
    x0, y0 = max(b[0], 0), max(b[1], 0)
    x1, y1 = min(b[0] + b[2], w), min(b[1] + b[3], h)
    kept = max(0, x1 - x0) * max(0, y1 - y0) / (b[2] * b[3])
    print(f"box {b} -> clipped ({x0}, {y0}, {x1 - x0}, {y1 - y0}), {kept:.0%} of its area inside", "| drop" if kept < 0.4 else "")
```

Output:

```text
mask pixels 5525 -> 5122 | values [0, 255] | mask on red: 99.9%
box (-6, 62, 132, 132) -> clipped (0, 62, 126, 132), 95% of its area inside 
box (-13, 22, 123, 123) -> clipped (0, 22, 110, 123), 89% of its area inside 
box (300, 10, 40, 40) -> clipped (300, 10, 20, 40), 50% of its area inside 
```

- Masks are warped with `INTER_NEAREST` so they stay 0/255; the image is warped with `INTER_LINEAR`. The mask still covers the disc: 99.9 % of its pixels are red in the augmented image (its pixel count changed with the random scale).
- A common rule drops boxes with less than a set fraction (here 40 %) of their area left inside the image.

## OpenCV API notes

**Geometry**: `cv2.getRotationMatrix2D`, `cv2.warpAffine(img, M, (w, h), flags, borderMode, borderValue)`, `cv2.flip(img, 1)` (horizontal), `cv2.warpPerspective` for perspective changes; `cv2.transform` for points.

**Photometric**: `cv2.convertScaleAbs` (gain/offset, saturating), `cv2.LUT` for gamma (11.3), HSV shifts with `cvtColor` (10.2), `cv2.GaussianBlur`, `cv2.randn` / NumPy for noise.

**Libraries**: Albumentations, torchvision.transforms v2 and Kornia implement these (with box and mask handling) on top of OpenCV or tensors; the principles are the same.

## Where it fails

- **Label-changing augmentations** (flipped text, recoloured colour classes) teach wrong answers.
- **Unrealistic variation** (strong rotations for a fixtured part) wastes capacity and can lower accuracy.
- **Interpolation artefacts**: repeated warps blur images; combine transforms into one matrix.
- **Augmentation is not new data**: it cannot create defect types, backgrounds or lighting conditions that never appear in the originals.

## ⚠️ Common mistakes

<Callout kind="mistake">

- **Transforming the image but not the label** (or with a different matrix).
- **Warping masks with linear interpolation** (non-binary edges).
- **Augmenting the validation or test set.**
- **Not seeding** the random generator, making experiments irreproducible.

</Callout>

## 🔍 Go deeper

<GoDeeper>

### Why augmentation works

Augmentation encodes prior knowledge about invariances into the training data. Simard, Steinkraus and Platt (2003) showed large gains on handwritten digits from elastic distortions; Krizhevsky et al. (2012) used random crops, flips and PCA colour jitter to train AlexNet [2, 3]. Shorten and Khoshgoftaar (2019) survey the many variants since, including cutout, mixup and learned augmentation policies [4].

### Test-time augmentation

At inference, averaging a model's predictions over a few augmented versions (e.g. original and flipped) often improves accuracy slightly at the cost of several forward passes; it uses the same invariances in the other direction.

</GoDeeper>

### Exercise 2 (coding)

Generate 100 augmented samples with the `augment` function (seed 0) and report the fraction of boxes that extend outside the image and the mean box area relative to the original 90 × 90 box.

<Solution>

```python
import numpy as np
import cv2

rng = np.random.default_rng(0)
outside, areas = 0, []
for _ in range(100):
    _, b, _ = augment(img, rng)
    outside += b[0] < 0 or b[1] < 0 or b[0] + b[2] > w or b[1] + b[3] > h
    areas.append(b[2] * b[3] / (90 * 90))
print(f"boxes partly outside: {outside}% | mean area ratio {np.mean(areas):.2f}")
```

Output:

```text
boxes partly outside: 25% | mean area ratio 1.33
```

A quarter of the boxes need clipping. The mean area grows by about a third: partly from the scale range, partly because a rotated square's axis-aligned box is larger than the square. For tight labels, transform the mask or polygon instead and recompute the box from it.

</Solution>
