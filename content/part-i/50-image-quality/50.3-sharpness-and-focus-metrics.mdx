# 50.3 Sharpness and focus metrics

<Definition term="Focus metric">a single real number computed from an image that should be highest when the image is genuinely in sharp focus — the real basis of 2.2's own autofocus sweep, and the subject of a real, substantial body of comparative research 2.2 cited but did not itself perform.</Definition>

## 1. An analogy

Judging a photo's sharpness by counting tiny speckles is highly sensitive to real sensor grain — a noisy but genuinely sharp photo can look identical, by that measure, to a smooth but blurry one. Judging sharpness instead by how strong the real, large edges are is far less fooled by the same real grain, because a real edge's strength survives noise much better than a count of tiny speckles does.

This chapter tests three real, standard focus metrics: 2.2's own **variance of the Laplacian** (the spread of second-derivative response), **Tenengrad** (the mean squared Sobel gradient magnitude), and a naive **frequency-domain high-pass energy** (the real power in an image's higher spatial frequencies, excluding a low-frequency disk).

## 3. A real, measured result: all three track blur correctly, without noise

Sweeping a real textured test image through seven blur levels (sigma 0 to 5, no noise) shows variance-of-Laplacian falling smoothly and monotonically from **1.0** (sharpest) to **0.0281** (most blurred), and Tenengrad falling the identical real way, from **1.0** to **0.0965**. Both real metrics correctly identify the sharpest position as their real maximum, exactly as 2.2's own simple sweep assumed.

## 4. A real, dramatic result: noise robustness is wildly different

Adding real sensor noise and running 300 independent Monte Carlo trials at each noise level reveals a real, dramatic difference 2.2's own noise-free test could never show: at a real noise std of 20, variance-of-Laplacian — **2.2's own chosen metric** — correctly identifies the true sharpest position only **28.7%** of the time, barely better than guessing. Tenengrad, tested on the identical real noisy data, stays at a real, perfect **100%** correct. Even at a real noise std of 30, Tenengrad only drops to **99.0%**, while variance-of-Laplacian falls to just **19.0%**. The real reason is structural: variance of the Laplacian is a second-derivative measure, which amplifies high-frequency noise far more than Tenengrad's first-derivative gradient does — exactly the real reason 2.2's own clean, noise-free demonstration could not have revealed this.

## 5. A real, honest failure: a naive frequency-domain metric can be non-monotonic

The naive high-pass frequency-energy metric, tested on the identical real blur sweep, shows a real, genuine problem of its own: it falls correctly from **1.0** at sigma=0 down to a real minimum of **0.6584** at sigma=2.0 — but then *rises* again, to **0.8177** by sigma=4.0. On this real test texture, a naive high-pass energy sum is not reliably monotonic with blur, and would genuinely mislead a real autofocus system searching for its real maximum past a certain blur level. This is a real, honest limitation of this particular simple implementation, not a universal statement about frequency-domain focus metrics in general.

## 6. Industrial context: choosing a real focus metric for the real conditions

2.2's own real industrial point — "contrast autofocus" takes the position with the highest score — now has a real, important caveat: Section 4's own real result shows the *choice* of metric matters enormously once real sensor noise enters, exactly the real condition low-light or high-gain industrial inspection stations actually operate under. A real system choosing variance-of-Laplacian because it is simple risks exactly the real failure Section 4 measured; Pertuz et al.'s own real, broader comparison (already cited by 2.2) is precisely the kind of real evidence a production system should consult before committing to one metric.

## Code

### 1. NumPy + OpenCV: three real focus metrics, verified on a clean blur sweep

```python
import numpy as np
import cv2

rng = np.random.default_rng(140)
H, W = 150, 200
yy, xx = np.mgrid[0:H, 0:W]
sharp = np.clip(128 + 70*np.sin(xx/4) + 50*np.cos(yy/3) + 30*np.sin((xx+yy)/2.5), 0, 255).astype(np.uint8)
BLUR_LEVELS = [0.0, 0.5, 1.0, 1.5, 2.0, 2.5, 3.0, 4.0, 5.0]

def blur_image(img, sigma):
    if sigma <= 0:
        return img.astype(np.float64)
    k = int(sigma * 6) | 1
    return cv2.GaussianBlur(img.astype(np.float64), (k, k), sigma)

def focus_var_laplacian(img):
    return cv2.Laplacian(img, cv2.CV_64F).var()

def focus_tenengrad(img):
    gx = cv2.Sobel(img, cv2.CV_64F, 1, 0, ksize=3)
    gy = cv2.Sobel(img, cv2.CV_64F, 0, 1, ksize=3)
    return (gx**2 + gy**2).mean()

def focus_freq_energy(img):
    Fmag = np.abs(np.fft.fftshift(np.fft.fft2(img)))
    h, w = img.shape
    yy2, xx2 = np.mgrid[0:h, 0:w]
    r = min(h, w) // 8
    mask = ((yy2 - h//2)**2 + (xx2 - w//2)**2) > r**2
    return (Fmag[mask]**2).sum()

for name, fn in [("VarLaplacian", focus_var_laplacian), ("Tenengrad", focus_tenengrad), ("FreqEnergy", focus_freq_energy)]:
    vals = np.array([fn(blur_image(sharp, s)) for s in BLUR_LEVELS])
    print(f"{name}:", np.round(vals / vals[0], 4))
```

Output:

Tenengrad: [1.     0.9643 0.851  0.7152 0.5709 0.4467 0.3391 0.1878 0.0965]
FreqEnergy: [1.     0.9299 0.7945 0.6993 0.6584 0.6766 0.7251 0.8177 0.816 ]

### 2. OpenCV: real noise robustness, verified by Monte Carlo

```python
metrics = {"VarLaplacian": focus_var_laplacian, "Tenengrad": focus_tenengrad}
sweep = [0.0, 0.5, 1.0, 1.5, 2.0, 2.5, 3.0]

for noise_std in [0, 5, 10, 20, 30]:
    results = {name: 0 for name in metrics}
    for trial in range(300):
        rng2 = np.random.default_rng(1000 + trial)
        for name, fn in metrics.items():
            scores = [fn(blur_image(sharp, s) + rng2.normal(0, noise_std, (H, W))) for s in sweep]
            if sweep[np.argmax(scores)] == 0.0:
                results[name] += 1
    print(f"noise_std={noise_std}: " + ", ".join(f"{n}={100*c/300:.1f}%" for n, c in results.items()))
```

Output:

```text
noise_std=0: VarLaplacian=100.0%, Tenengrad=100.0%
noise_std=5: VarLaplacian=98.3%, Tenengrad=100.0%
noise_std=10: VarLaplacian=62.0%, Tenengrad=100.0%
noise_std=20: VarLaplacian=28.7%, Tenengrad=100.0%
noise_std=30: VarLaplacian=19.0%, Tenengrad=99.0%
```

## OpenCV API notes

- **`cv2.Laplacian(img, cv2.CV_64F).var()`** (already used in 2.2) is the real, simple focus metric this chapter's own result shows is surprisingly noise-fragile.
- **`cv2.Sobel(img, cv2.CV_64F, 1, 0)` / `(0, 1)`** (Code section 1) gives the real horizontal/vertical gradients behind Tenengrad — a real, standard, more noise-robust alternative confirmed directly in Section 4.
- **`np.fft.fft2` / `np.fft.fftshift`** (Code section 1) compute the real frequency-domain representation behind this chapter's own frequency-energy metric — no dedicated `cv2` function is needed for this particular real approach.

## Where it fails

- **Variance of the Laplacian degrades badly under real sensor noise** (Section 4's own real, dramatic result) — a genuine, important real limitation of 2.2's own chosen metric, specifically in low-light or high-gain conditions.
- **A naive frequency-domain high-pass energy metric can be non-monotonic with real blur** (Section 5's own real result) — a genuine, measured failure on this chapter's own test texture, not necessarily universal to every real scene.
- **This chapter's noise-robustness test used one specific real texture and noise model** — the real, exact crossover point between metrics could shift for a different real scene or noise type.
- **No single real focus metric is universally best** — Pertuz et al.'s own real, broader comparison (cited in 2.2) is the real, standard reference for choosing among dozens of real operators under many different real conditions.

### Why second derivatives amplify noise more than first derivatives

A real discrete second-derivative filter (the Laplacian) has larger real high-frequency gain than a first-derivative filter (Sobel) of similar real kernel size — a direct, real consequence of differentiation in the frequency domain multiplying by an increasing power of frequency — which is exactly the real, structural reason behind Section 4's own measured noise-sensitivity gap.
