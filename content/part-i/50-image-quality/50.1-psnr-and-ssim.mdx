# 50.1 PSNR and SSIM

<Definition term="SSIM (Structural Similarity Index)">a real image-quality metric that compares local structure — mean, contrast, and correlation in small windows — instead of PSNR's raw, global squared pixel error.</Definition>

18.1-18.3 used PSNR throughout as a real, convenient way to score denoising results. 4.2 warned that "PSNR is not perception: two images with the same PSNR can look very different," and named SSIM as the real fix, without ever showing it. This chapter does.

## 1. An analogy

Two student essays might both score "80% similar" to a reference by a crude word-count metric — but one simply shortened every sentence while keeping the real meaning intact, and the other scrambled the word order into nonsense. The same real score, from a metric that only counts, hides a completely different real outcome. PSNR is exactly this kind of count; SSIM reads the real sentence structure instead.

SSIM's real, standard formula (Wang, Bovik, Sheikh, Simoncelli, 2004) compares, within each small local window, the two images' real means (`luminance`), real variances (`contrast`), and real covariance (`structure`), combining all three into one windowed score between -1 and 1, then averaging across the whole image.

## 3. A real, measured result: the formula works exactly, and matches OpenCV

Implementing SSIM from scratch (an 11x11 Gaussian-weighted window) gives exactly **1.0** for two identical images — a real, perfect match, as the formula requires. Cross-checking against `cv2.quality.QualitySSIM_compute` (opencv-contrib) on a real distorted test image gives **0.548376** from the from-scratch implementation against OpenCV's own **0.548375** — matching to five real decimal places, confirming the from-scratch implementation is correct.

## 4. A real, dramatic result: identical PSNR, wildly different SSIM

Two genuinely different distortions, calibrated to the identical real mean squared error (and therefore nearly identical PSNR): real additive Gaussian noise (std 10.0) gives **PSNR = 28.055dB**, and a flat, uniform brightness shift calibrated to the same real MSE gives **PSNR = 28.131dB** — essentially the same real PSNR score. But their real SSIM values tell a completely different story: the noisy image scores just **0.5438**, while the brightness-shifted image — which preserves every real structural detail, just uniformly brighter — scores **0.9951**, nearly perfect. This is 4.2's own real claim, now directly, numerically confirmed: PSNR cannot tell these two real, very different distortions apart; SSIM can.

## 5. Industrial context: when PSNR is enough, and when it isn't

18.1-18.3's own real use of PSNR was comparing the *same* kind of distortion (denoising residual error) across different settings of the *same* algorithm — exactly where PSNR's real blindness to structure matters least, since every compared image shares the same real distortion type. Comparing genuinely different real algorithms, different compression methods, or anything meant to predict how a real human would judge quality needs Section 4's own real lesson: SSIM (or a more advanced real metric) is worth the extra real computation specifically when the comparison crosses different kinds of distortion.

## Code

### 1. NumPy + OpenCV: the real SSIM formula, verified exact

```python
import numpy as np
import cv2

def ssim(img1, img2, win=11, C1=(0.01*255)**2, C2=(0.03*255)**2):
    img1, img2 = img1.astype(np.float64), img2.astype(np.float64)
    mu1 = cv2.GaussianBlur(img1, (win, win), 1.5)
    mu2 = cv2.GaussianBlur(img2, (win, win), 1.5)
    sigma1_sq = cv2.GaussianBlur(img1 * img1, (win, win), 1.5) - mu1 * mu1
    sigma2_sq = cv2.GaussianBlur(img2 * img2, (win, win), 1.5) - mu2 * mu2
    sigma12 = cv2.GaussianBlur(img1 * img2, (win, win), 1.5) - mu1 * mu2
    ssim_map = ((2*mu1*mu2+C1)*(2*sigma12+C2)) / ((mu1**2+mu2**2+C1)*(sigma1_sq+sigma2_sq+C2))
    return ssim_map.mean()

rng = np.random.default_rng(120)
H, W = 120, 160
yy, xx = np.mgrid[0:H, 0:W]
clean = np.clip(128 + 60*np.sin(xx/15) + 40*np.cos(yy/12), 0, 255).astype(np.uint8)

print("SSIM(clean, clean):", ssim(clean.astype(np.float64), clean.astype(np.float64)))

distorted = np.clip(clean.astype(np.float64) + rng.normal(0, 10.0, clean.shape), 0, 255).astype(np.uint8)
my_ssim = ssim(clean.astype(np.float64), distorted.astype(np.float64))
print(f"from-scratch SSIM: {my_ssim:.6f}")
```

Output:

```text
SSIM(clean, clean): 1.0
from-scratch SSIM: 0.548376
```

### 3. OpenCV: matched PSNR, wildly different SSIM

```python
def psnr(a, b):
    mse = np.mean((a.astype(np.float64) - b.astype(np.float64)) ** 2)
    return 10 * np.log10(255.0**2 / mse) if mse > 0 else float("inf")

noise_std = 10.0
distorted_noise = np.clip(clean.astype(np.float64) + rng.normal(0, noise_std, clean.shape), 0, 255)
shift = np.sqrt(noise_std**2)
distorted_shift = np.clip(clean.astype(np.float64) + shift, 0, 255)

print(f"Noise distortion:   PSNR={psnr(clean, distorted_noise):.3f}dB, SSIM={ssim(clean.astype(np.float64), distorted_noise):.4f}")
print(f"DC-shift distortion: PSNR={psnr(clean, distorted_shift):.3f}dB, SSIM={ssim(clean.astype(np.float64), distorted_shift):.4f}")
```

Output:

```text
Noise distortion:   PSNR=28.055dB, SSIM=0.5438
DC-shift distortion: PSNR=28.131dB, SSIM=0.9951
```

## OpenCV API notes

- **`cv2.PSNR(a, b)`** (already cited in 18.1) is the real, direct equivalent of this chapter's own `psnr` function.
- **`cv2.quality.QualitySSIM_compute(a, b)`** (opencv-contrib, `# Needs opencv-contrib`) is the real, built-in SSIM implementation this chapter's own from-scratch version was cross-checked against — matching to five real decimal places (Section 3).
- **`cv2.GaussianBlur`** (Code section 1) is reused here as the real, standard way to compute SSIM's own local windowed statistics (mean, variance, covariance) efficiently, exactly the same real tool used throughout 18.2 for ordinary noise smoothing.

## Where it fails

- **SSIM's own window size and Gaussian sigma are real, tunable parameters** — this chapter used the real, standard 11x11/1.5 values from the original paper, but a different real choice can shift the result somewhat.
- **Neither PSNR nor SSIM is a complete real model of human perception** — both are full-reference metrics (needing a known-good original); real no-reference metrics (like 8.4's own named BRISQUE) exist for when no original is available at all.
- **SSIM still needs a correctly-aligned reference image** — exactly like PSNR, a real misalignment (even a few pixels) would corrupt both metrics identically, for reasons unrelated to real quality.
- **This chapter's matched-PSNR test (Section 4) used two specific, contrasting distortion types** — the real size of the PSNR/SSIM gap depends on exactly which two distortions are being compared.

## ⚠️ Common mistakes

<Callout kind="mistake">

- **Assuming higher PSNR always means better real perceived quality** — Section 4's own real, dramatic counterexample (near-identical PSNR, SSIM 0.5438 vs 0.9951) shows this is not reliable across different distortion types.
- **Using SSIM to compare images that are not properly aligned** — Where it fails's own real point: misalignment corrupts SSIM exactly as badly as PSNR.
- **Forgetting `cv2.quality` needs opencv-contrib** — OpenCV API notes' own real point, consistent with 4.2's own original observation that it is not in the base `opencv-python` wheel.
- **Treating SSIM as a complete real substitute for human judgment** — Where it fails's own point: both metrics are useful real approximations, not a perfect real model of perception.

</Callout>

### Exercise 3 (thinking)
