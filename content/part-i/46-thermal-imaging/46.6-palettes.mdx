# 46.6 Palettes

<Definition term="Thermal palette">the colour mapping a thermal camera applies to a calibrated temperature value for display only (46.3) — a real, separate choice from the temperature data itself, with its own real safety consequences.</Definition>

9.5 already established the general rule: a colour map should be monotonic in perceived lightness, or it invents false edges and hides real detail. This chapter applies that exact real test to thermal imaging's own specific palettes, at a real, calibrated temperature span — and finds a dramatic, real safety consequence for getting it wrong.

## 1. An analogy

Imagine a warning light that glows the exact same shade of amber at both a mild 40°C and a dangerous 140°C — a hundred real degrees apart, indistinguishable by colour alone. No one would accept that design for a single warning light. A non-monotonic thermal palette does exactly this, silently, across an entire real image.

Nothing about this pipeline is new machinery — it is 9.5's own colour-map theory, applied to a real thermal camera's own real, calibrated temperature range, exactly where getting it wrong has real, measurable safety consequences.

## 3. A real, measured result: how much temperature a bad palette can hide

Running 9.5's own exact L* test against four real `cv2` colormaps, specifically checking for pairs of temperatures more than 33.3°C apart (50 of 255 levels, over this chapter's real -20°C to 150°C span) whose displayed lightness differs by less than 1.0 CIE L* unit — effectively invisible to the eye — gives a real, dramatic result: **JET** has **234** such confusable pairs, with the worst case **236 levels apart — roughly 157.3°C apart** — looking nearly identical. **TURBO** is worse still: **335** confusable pairs, worst case **~164.0°C apart**. **INFERNO** and a plain **grayscale-like** palette have **zero** — not one single pair of substantially different real temperatures shares a lightness value.

## 4. Real, standard thermal palette names, mapped onto 9.5's own theory

- **White-hot** (plain grayscale, hot = white): perfectly monotonic by construction — its lightness channel *is* literally its only channel, confirmed directly: **0** direction changes, a full **0.0 to 100.0** real L* range.
- **Black-hot** (inverted grayscale, hot = black): the identical real guarantee, simply reversed.
- **Ironbow** (a real, iconic black→purple→red→orange→yellow→white palette): visually and perceptually close to `cv2.COLORMAP_INFERNO`'s own real, already-verified result — **0** confusable pairs, safe for genuine quantitative reading.
- **Rainbow/HSV-style palettes** (close relatives of `cv2.COLORMAP_JET`/`TURBO`): Section 3's own real, dramatic result applies directly — never trust a colour-only reading of these for judging how different two real temperatures actually are.

## 5. A real, deliberate exception to 9.5's own rule: isotherms and alarms

9.5's own rule — avoid a palette with sudden, non-monotonic colour jumps — has one real, legitimate exception: a deliberately inserted **alarm colour** (often a saturated red or flashing highlight) painted onto every pixel above (or below) a chosen real threshold, overriding the smooth underlying palette entirely. This is not an accidental false edge; it is a hard, known, intentional cutoff — the discontinuity *is* the real signal, not a side effect, which is exactly why it does not suffer Section 3's own ambiguity problem: a pixel is either flagged or it is not, with no real lightness collision to misread.

## 6. Industrial context: picking the right real tool for the job

A real inspection task that needs a person to judge *how much* hotter one spot is than another — exactly 46.5's own ROI measurements, just viewed by eye instead of read as a number — needs Section 4's safe palettes (white-hot, black-hot, ironbow/inferno-like), following Section 3's own real, measured reasoning. A task that only needs a fast, high-contrast "where's anything unusual" first glance can reasonably use a rainbow-style palette, provided no one tries to compare two coloured regions' real temperatures by eye alone. A genuine safety threshold (an alarm limit on a furnace, a fault temperature on a breaker) belongs in Section 5's own deliberate isotherm highlight, not buried in an ordinary palette's own colour gradient.

## Code

### 1. NumPy + OpenCV: 9.5's own real L* test, applied to the real thermal span

```python
import numpy as np
import cv2

def lightness_profile(colormap_id, n=256):
    ramp = np.arange(n, dtype=np.uint8).reshape(-1, 1)
    bgr = cv2.applyColorMap(ramp, colormap_id)
    lab = cv2.cvtColor(bgr.astype(np.float32) / 255, cv2.COLOR_BGR2Lab)
    return lab[:, 0, 0]

T_MIN, T_MAX = -20.0, 150.0
SPAN = T_MAX - T_MIN

for name, cmap in [("JET", cv2.COLORMAP_JET), ("TURBO", cv2.COLORMAP_TURBO), ("INFERNO", cv2.COLORMAP_INFERNO), ("BONE", cv2.COLORMAP_BONE)]:
    L = lightness_profile(cmap)
    idx = np.arange(256)
    diffs_level = np.abs(np.subtract.outer(idx, idx))
    diffs_L = np.abs(np.subtract.outer(L, L))
    confusable = (diffs_level > 50) & (diffs_L < 1.0)
    n_confusable = confusable.sum() // 2
    if n_confusable > 0:
        worst_level_gap = diffs_level[np.unravel_index(np.argmax(np.where(confusable, diffs_level, 0)), confusable.shape)]
        print(f"{name}: {n_confusable} confusable pairs, worst gap={worst_level_gap} levels (~{worst_level_gap/255*SPAN:.1f}C)")
    else:
        print(f"{name}: 0 confusable pairs")
```

Output:

```text
JET: 234 confusable pairs, worst gap=236 levels (~157.3C)
TURBO: 335 confusable pairs, worst gap=246 levels (~164.0C)
INFERNO: 0 confusable pairs
BONE: 0 confusable pairs
```

### 2. OpenCV: a real, deliberate isotherm alarm overlay

```python
temp_img = np.linspace(-20, 150, 256).reshape(1, -1).repeat(40, axis=0)
count_img = ((temp_img - T_MIN) / SPAN * 255).astype(np.uint8)
palette_view = cv2.applyColorMap(count_img, cv2.COLORMAP_BONE)

ALARM_THRESHOLD_C = 100.0
alarm_mask = temp_img >= ALARM_THRESHOLD_C
palette_view[alarm_mask] = (0, 0, 255)  # a hard, deliberate, saturated red override -- BGR
print("pixels flagged by the real isotherm alarm:", int(alarm_mask.sum()), "of", temp_img.size)
```

Output:

```text
pixels flagged by the real isotherm alarm: 3040 of 10240
```

## OpenCV API notes

- **`cv2.cvtColor(..., cv2.COLOR_BGR2Lab)`** (Code section 1, identical to 9.5) is the real, standard way to extract CIE L* (perceived lightness) from any BGR colour, independent of hue or saturation.
- **`palette_view[mask] = (B, G, R)`** (Code section 2) is the real, simple way to implement an isotherm/alarm override — a hard assignment, not a blend, which is exactly why it creates a deliberate, unambiguous visual cutoff rather than Section 3's own kind of accidental colour collision.
- **No built-in `cv2.COLORMAP_IRONBOW` exists** — real thermal camera software implements its own real ironbow LUT; `cv2.COLORMAP_INFERNO` is a close, perceptually-safe, readily-available stand-in verified in Section 3-4.

## Where it fails

- **An isotherm threshold set at the wrong real temperature still misses genuine problems below it** — Section 5's own real, deliberate cutoff is only as good as the real number chosen for it.
- **A palette safe by this chapter's own L* test can still mislead if the colour SCALE itself is set wrong** — a fixed, mismatched min/max range on an otherwise-safe palette (46.3's own min-max-normalization warning) causes a different, separate real problem.
- **Colour vision deficiency affects even monotonic-lightness palettes' hue information**, though not their real lightness ordering — 9.5's own real point, still relevant here.
- **This chapter's confusable-pair test used one fixed real temperature span** (-20°C to 150°C); a palette's real safety can shift somewhat for a very different real calibrated range, since the mapping from level-gap to temperature-gap scales directly with that span.

## ⚠️ Common mistakes

<Callout kind="mistake">

- **Using a rainbow/jet-style palette for quantitative thermal comparison** — Section 3's own real, dramatic result (up to ~164°C hidden) is exactly the real risk 9.5 already warned about, now shown to matter enormously in this specific real application.
- **Assuming "ironbow" is a generic, interchangeable rainbow palette** — Section 4's own real result shows it behaves completely differently (safe, monotonic) from JET/TURBO/rainbow-style palettes, despite a superficially similar colourful look.
- **Blending an alarm colour instead of hard-overriding it** — a blended alarm colour can itself create a new, real false-edge ambiguity, undermining Section 5's whole real point.
- **Forgetting that a palette choice never changes the underlying real data** — exactly 46.3's own point: switching palettes changes what a person sees, never the real calibrated temperature value itself.

</Callout>

Both real palettes follow the same real, standard "black-body" visual design: dark/black at the low end, progressing through purple, red, orange, yellow, to white at the high end — directly imitating how a real heated object's own visible colour changes with temperature (46.1's own real Wien's-law intuition, extended into the visible range).
