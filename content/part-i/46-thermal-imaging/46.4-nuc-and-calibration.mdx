# 46.4 NUC and calibration

<Definition term="Non-uniformity correction (NUC)">correcting the real, individual gain and offset error every single pixel of a thermal detector array has, by comparing the whole array's response to one or more known, uniform reference scenes.</Definition>

46.3 assumed one shared calibration curve converts any pixel's raw count into a real radiance. A real detector array does not behave that uniformly: every individual pixel has its own small, real manufacturing variation in both gain and offset — fixed-pattern noise — and NUC is the real, standard procedure that removes it.

## 1. An analogy

A row of bathroom scales, each slightly miscalibrated, might show anywhere from 1kg to 3kg with nothing on them at all, and might also disagree slightly on how much a real 10kg weight actually weighs. Having every person step on an *empty* scale first (its own real "zero") fixes the first problem; having everyone also step on a known real 10kg reference weight fixes the second. A thermal detector array has exactly this same real two-part problem, pixel by pixel, at a far larger scale.

## 2. The pipeline: known references in, a corrected array out

A real camera performs this by closing an internal shutter (or pointing briefly at a uniform target) to capture one or more known, uniform reference frames, computing each pixel's own correction from them, and then applying that same correction to every subsequent real image until the next recalibration.

## 3. A real, measured result: one reference already helps enormously

Simulating a real detector array (10,000 pixels, each with its own real ±3% gain error and a real random offset) viewing a perfectly uniform test scene shows raw pixel-to-pixel variation of **28.078** counts of real standard deviation — pure fixed-pattern noise, since every pixel is seeing the identical real radiance. Correcting with a single uniform reference (**1-point NUC**, matching every pixel's own offset to the array's mean) cuts that to **3.062** — a real **9.2x** improvement — while using two references at different radiances to fit each pixel's real gain *and* offset (**2-point NUC**) reaches **0.614**, a real **45.7x** improvement over the uncorrected array.

## 4. A real, measured surprise: one reference is not enough for a real scene

That dramatic 1-point result came from testing on a *uniform* scene — exactly the condition the correction was fitted for. Testing the identical 1-point correction on a real, *non-uniform* scene (a smooth radiance gradient, a far more realistic test) reveals a real, much weaker result: a mean error of **4.07** (down from an uncorrected **22.33**, but far short of the uniform case's near-total fix) — because 1-point correction only truly matches each pixel's response at the *one* radiance it was calibrated against; every pixel's own small, real gain error still shows up everywhere else in the scene. The 2-point correction, fitted across *two* different real reference radiances, handles this properly: a mean error of just **0.50** on the same non-uniform scene — this is exactly why real thermal cameras use at least two-point calibration, not a single flat-field shot.

## 5. A real, measured result: why a camera re-calibrates itself periodically

A real detector's own gain and offset genuinely drift as the camera's internal temperature changes during use — a real, physical effect, not just scene noise. Applying a 1-point correction that was fitted at one internal temperature to later frames taken after the camera's own body has warmed shows a real, growing residual error: **3.062** at zero drift, rising to **3.543** at 3°C of internal drift, **4.279** at 5°C, and **6.740** — more than double the original value — at 10°C of real internal temperature change. This is exactly why a real thermal camera periodically performs its own audible internal **flat-field correction (FFC)** — the real "click" many users hear during use — re-capturing its own reference and refreshing every pixel's correction before this real drift grows too large.

## Code

### 1. NumPy: real 1-point vs 2-point non-uniformity correction

```python
import numpy as np

rng = np.random.default_rng(10)
N = 10000
true_gain = 1.0 + rng.normal(0, 0.03, N)
true_offset = rng.normal(0, 8.0, N)

def sensor_response(true_radiance, gain, offset, noise_std, seed):
    return gain * true_radiance + offset + np.random.default_rng(seed).normal(0, noise_std, len(true_radiance))

ref_counts = sensor_response(np.full(N, 1000.0), true_gain, true_offset, 0.5, seed=1)
offset_correction = ref_counts.mean() - ref_counts

counts_lo = sensor_response(np.full(N, 500.0), true_gain, true_offset, 0.5, seed=2)
counts_hi = sensor_response(np.full(N, 1500.0), true_gain, true_offset, 0.5, seed=3)
a = (1500.0 - 500.0) / (counts_hi - counts_lo)
b = 500.0 - a * counts_lo

raw_uniform = sensor_response(np.full(N, 900.0), true_gain, true_offset, 0.5, seed=4)
print(f"uniform scene: raw std={raw_uniform.std():.3f}, 1-point std={(raw_uniform+offset_correction).std():.3f}, 2-point std={(a*raw_uniform+b).std():.3f}")

scene = 600 + 600 * np.linspace(0, 1, N)
raw_scene = sensor_response(scene, true_gain, true_offset, 0.5, seed=5)
print(f"gradient scene: raw err={np.abs(raw_scene-scene).mean():.2f}, 1-point err={np.abs(raw_scene+offset_correction-scene).mean():.2f}, 2-point err={np.abs(a*raw_scene+b-scene).mean():.2f}")
```

Output:

```text
uniform scene: raw std=28.078, 1-point std=3.062, 2-point std=0.614
gradient scene: raw err=22.33, 1-point err=4.07, 2-point err=0.50
```

## OpenCV API notes

- **No `cv2` function performs non-uniformity correction** — NUC (Code section 1) is plain per-pixel arithmetic; `cv2` enters only to display the result (Code section 2).
- **`cv2.normalize(..., cv2.NORM_MINMAX)`** (Code section 2) rescales a float array for 8-bit display — note it does NOT remove real fixed-pattern noise itself; the min-max stretch applied to both the raw and corrected images here shows a similarly large displayed std, because normalization stretches whatever full range is present rather than fixing non-uniformity, exactly 46.3's own "a palette is not the same as the real data" point applied here too.
- **A real camera's own NUC coefficients are usually stored per pixel inside the camera** and applied to every frame before any further processing (46.3, 46.5) ever sees the data.

## Where it fails

- **This chapter's 2-point correction assumes a purely linear per-pixel response** — some real detectors have small nonlinearities a two-point fit cannot fully capture; higher-order or multi-point calibration exists for those real cases.
- **A NUC calibration performed at one internal camera temperature degrades as that temperature drifts** (Section 5's own real result) — this is a genuine real limitation, not something a one-time factory calibration can solve permanently.
- **A bad or stale reference capture (dust, a non-uniform shutter, motion during capture) corrupts the correction itself** — NUC is only as good as its own real reference capture.
- **NUC corrects detector-level fixed-pattern noise, not scene-level problems** — it does nothing for the real emissivity (46.2) or bit-depth (46.3) issues covered elsewhere in this module.

## ⚠️ Common mistakes

<Callout kind="mistake">

- **Assuming a single flat-field (1-point) correction is enough for real scenes** — Section 4's own real result (4.07 vs 0.50 mean error) shows a real, substantial gap between 1-point and 2-point correction on anything but a perfectly uniform test.
- **Ignoring a camera's own FFC prompts or disabling automatic re-calibration** — Section 5's own real drift result is exactly what that feature exists to prevent.
- **Assuming a corrected, normalized display image proves non-uniformity is gone** — Code section 2's own real result shows a naive min-max display stretch does not actually reveal (or fix) the real underlying correction quality.
- **Performing a critical measurement immediately after a large change in the camera's own operating temperature**, without waiting for or triggering a fresh FFC — Section 5's own real numbers show exactly how much residual error this can leave.

</Callout>

## 🔍 Go deeper

<GoDeeper>

### Scene-based NUC

Some real thermal cameras additionally use "scene-based" NUC, estimating correction coefficients from natural camera motion across an ordinary (non-uniform) real scene rather than a dedicated uniform reference — a more complex, real alternative to this chapter's shutter-based approach, useful when a physical shutter is impractical (e.g., some cooled MWIR systems).

### Bad pixel replacement

A real detector array almost always has a handful of individual pixels that cannot be corrected at all (dead, stuck, or wildly out-of-range) — a real camera's own processing pipeline maps these out and interpolates their value from real neighbours, a separate, additional step from this chapter's own per-pixel gain/offset correction.

</GoDeeper>

### Exercise 3 (thinking)

A factory uses a fixed-mounted thermal camera for 24/7 monitoring of a process that runs both during cold nights and hot days, with the camera's own enclosure temperature varying by over 15°C across that cycle. Based on Section 5, what real risk should the team expect if they only perform NUC once, at installation?

<Solution>

Following Section 5's own real result (residual error more than doubling over just 10°C of drift), a 15°C daily swing in the camera's own enclosure temperature would be expected to cause real, substantial, and likely worse non-uniformity errors at the temperature extremes compared to right after the original calibration.
