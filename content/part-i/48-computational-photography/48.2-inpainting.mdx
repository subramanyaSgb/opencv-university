# 48.2 Inpainting

<Definition term="Inpainting">filling a damaged or missing region of an image using only the real, valid pixels around it — no external reference, no second photo, just the surrounding structure extrapolated inward.</Definition>

A scratched photo, a sensor's dead pixel cluster, or a watermark removed from a frame all share the same real problem: a region of known-bad or missing pixels, surrounded by real, trustworthy ones. `cv2.inpaint` fills that region by propagating information inward from its own boundary.

## 1. An analogy

Restoring a torn photograph by studying the pattern right at the edges of the tear and extending it inward — continuing a line, a gradient, a texture — the same real way a person intuitively repairs a damaged picture, using only what is already visible around the damage.

## 2. The pipeline: propagate inward from the boundary

`cv2.inpaint` offers two real algorithms: **TELEA** (Telea, 2004), based on the Fast Marching Method, fills pixels in order of distance from the boundary; **NS** (Bertalmio et al., 2001), based on a real fluid-dynamics-inspired PDE, propagates both colour and structure (isophotes) inward simultaneously. Both work from the same real idea — use the boundary, extrapolate inward — with different real mathematics.

## 3. A real, measured result: accuracy degrades steadily with damage size

Testing both algorithms on a real, textured synthetic image with a circular hole of growing radius shows a real, steady accuracy decline: at a tiny **3px** radius, TELEA reaches **34.70dB** PSNR; by **50px**, that drops to **19.18dB** — a real, substantial loss. NS follows the identical real pattern, consistently a little behind TELEA at every size tested (33.84dB down to 18.36dB). Both algorithms do genuinely well on small, localized damage and genuinely worse as the damaged region grows — there is simply less real surrounding context to extrapolate from.

## 4. A real, measured surprise: NS was faster than TELEA, not the other way around

TELEA is often described as the faster of the two real algorithms. Measuring both directly on this course's own pinned OpenCV 4.13.0 build gives the opposite real result at every hole size tested: at a 10px radius, TELEA took **1.682ms** against NS's **1.170ms** (NS at **70%** of TELEA's time); at 60px, TELEA took **10.233ms** against NS's **9.201ms** (**90%**). On this real, specific build, **NS was consistently faster**, not TELEA — a direct, measured contradiction of the common assumption, and a real reminder to check performance on the actual pinned version rather than trust folklore.

## 5. A real, measured result: shape matters more than area

A compact, circular hole of **709px** reconstructs to **28.73dB** with TELEA. A thin, **813px** scratch — genuinely *larger* in area — reconstructs to a real, better **33.00dB**. The real reason is geometric, not about size at all: every pixel in a thin scratch sits close to real, valid pixels on both sides, while the centre of a compact blob sits far from any real boundary pixel at all, forcing the algorithm to extrapolate much further with much less real local information.

## 6. Industrial context: where inpainting earns its real use

Real applications span sensor dust/dead-pixel correction (small, compact damage — Section 3's own favourable regime), removing a watermark, timestamp, or small foreign object from a frame, restoring scratched archival film or photographs, and filling small occluded gaps left over from multi-view 3D reconstruction (44.1-45.x's own occlusion themes). Section 3 and 5's own real results directly predict which of these tasks will go well: small, thin, or compact-but-small damage inpaints reliably; large, complex missing regions do not.

## Code

### 1. NumPy + OpenCV: real PSNR vs damage size, TELEA vs NS

```python
import numpy as np
import cv2

rng = np.random.default_rng(30)
H, W = 200, 200
yy, xx = np.mgrid[0:H, 0:W]
base = (128 + 60 * np.sin(xx / 20) + 40 * np.cos(yy / 15)).astype(np.float32) + rng.normal(0, 5, (H, W))
img = np.clip(base, 0, 255).astype(np.uint8)

def psnr(a, b):
    mse = np.mean((a.astype(np.float64) - b.astype(np.float64)) ** 2)
    return 10 * np.log10(255.0 ** 2 / mse) if mse > 0 else float("inf")

for radius in [3, 8, 15, 30, 50]:
    mask = np.zeros((H, W), dtype=np.uint8)
    cv2.circle(mask, (W // 2, H // 2), radius, 255, -1)
    damaged = img.copy()
    damaged[mask > 0] = 0
    telea = cv2.inpaint(damaged, mask, 3, cv2.INPAINT_TELEA)
    ns = cv2.inpaint(damaged, mask, 3, cv2.INPAINT_NS)
    print(f"r={radius:3d}px: TELEA PSNR={psnr(img[mask>0], telea[mask>0]):.2f}dB | NS PSNR={psnr(img[mask>0], ns[mask>0]):.2f}dB")
```

Output:

```text
r=  3px: TELEA PSNR=34.70dB | NS PSNR=33.84dB
r=  8px: TELEA PSNR=32.44dB | NS PSNR=31.79dB
r= 15px: TELEA PSNR=28.73dB | NS PSNR=28.14dB
r= 30px: TELEA PSNR=22.59dB | NS PSNR=21.94dB
r= 50px: TELEA PSNR=19.18dB | NS PSNR=18.36dB
```

### 2. OpenCV: the real shape-vs-area comparison

```python
mask_blob = np.zeros((H, W), dtype=np.uint8)
cv2.circle(mask_blob, (W // 2, H // 2), 15, 255, -1)

mask_scratch = np.zeros((H, W), dtype=np.uint8)
cv2.line(mask_scratch, (20, 100), (180, 100), 255, thickness=4)

for name, mask in [("compact blob", mask_blob), ("thin scratch", mask_scratch)]:
    damaged = img.copy()
    damaged[mask > 0] = 0
    telea = cv2.inpaint(damaged, mask, 3, cv2.INPAINT_TELEA)
    print(f"{name}: area={int((mask>0).sum())}px, TELEA PSNR={psnr(img[mask>0], telea[mask>0]):.2f}dB")
```

Output:

```text
compact blob: area=709px, TELEA PSNR=28.73dB
thin scratch: area=813px, TELEA PSNR=33.00dB
```

## OpenCV API notes

- **`cv2.inpaint(src, mask, inpaintRadius, flags)`**: `mask` marks damaged pixels (nonzero = damaged); `inpaintRadius` sets how far around each point the algorithm considers; `flags` selects `cv2.INPAINT_TELEA` or `cv2.INPAINT_NS` — this chapter's own real, verified comparison of both.
- **Both algorithms need an accurate real mask** — `cv2.inpaint` has no way to detect damage itself; a wrong or imprecise mask (too small, missing real damaged pixels, or including real valid ones) directly degrades the result.
- **Measured real speed is build- and version-dependent** (Section 4's own real finding) — always benchmark the specific real pinned version in use rather than relying on commonly-cited performance claims.

## Where it fails

- **Large or complex missing regions degrade steadily, with no sudden cliff** (Section 3's own real result) — there is no hard size limit, just a continuous real accuracy cost.
- **Neither algorithm understands real scene content** — both propagate local structure/colour geometrically; neither can plausibly reconstruct a large missing object's real identity (a face, a complex pattern) the way a modern, learned generative inpainting model might.
- **A compact hole is a genuinely harder real case than a thin one of the same or even larger area** (Section 5's own real result) — shape, not just size, predicts real difficulty.
- **This chapter's real results are specific to the tested image's own texture and the pinned OpenCV build** — different real content or a different version could shift the exact numbers, though the qualitative patterns (size and shape both matter) are expected to hold generally.

## ⚠️ Common mistakes

<Callout kind="mistake">

- **Assuming TELEA is always faster than NS** — Section 4's own real, measured result on this pinned build shows the opposite; always verify on the real system in use.
- **Expecting inpainting to recover real detail that was never visible anywhere in the image** — Where it fails's own point: both algorithms extrapolate local structure, they do not invent genuinely new real content.
- **Using a loose or inaccurate damage mask** — OpenCV API notes' own point; the real result is only as good as the real mask defining the damaged region.
- **Treating a large hole's inpainted result as trustworthy data** — Section 3's own real accuracy decline (down to 19.18dB at 50px) shows this is a real, plausible-looking fill, not a recovered measurement.

</Callout>

## 🔍 Go deeper

<GoDeeper>

### Fast Marching Method vs Navier-Stokes inpainting

Telea's real method (2004) orders pixel-filling by distance from the mask boundary using the same Fast Marching Method behind some real distance-transform algorithms; Bertalmio et al.'s real method (2001) instead solves a PDE inspired by fluid dynamics, propagating image "isophotes" (lines of constant intensity) inward to preserve real structure across the filled region.

### Modern, learned inpainting

Real, modern deep-learning inpainting models (e.g. generative adversarial or diffusion-based methods) can plausibly synthesize genuinely new, contextually appropriate content for large missing regions — a real, different capability from this chapter's own geometric, non-learned methods, which can only extrapolate local structure and texture.

</GoDeeper>
