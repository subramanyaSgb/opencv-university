# 48.4 Low-light enhancement

<Definition term="Low-light enhancement">genuinely recovering a usable image from a dark scene — which 12.3's own real result already proved cannot be done by brightness or contrast adjustment alone, because the real problem is signal-to-noise ratio, not brightness.</Definition>

12.3 proved something important and left it unexplained: "no contrast operation improves the CNR of the original." This chapter covers the real physics behind that result — shot noise — and the one real technique that genuinely does improve signal-to-noise: using more than one frame.

## 1. An analogy

Turning up a radio's volume knob makes both the music and the static louder by the exact same amount — the real ratio between them, which is what actually determines how clearly the music can be heard, never changes. Brightening a dark photo is the identical real operation: it amplifies the real signal and the real noise together, by the same factor, leaving the underlying problem exactly as bad as before.

## 2. The pipeline: why dark means noisy, not just dim

A camera sensor counts real, individual photons, and real photon arrival follows **Poisson statistics**: for a true signal level `s`, the real standard deviation of the measured count is `sqrt(s)`. Low light means a small `s`, and `sqrt(s)` shrinks more slowly than `s` itself does — so the real signal-to-noise ratio, `s / sqrt(s) = sqrt(s)`, genuinely gets worse as light gets scarcer. This is not a display or processing artifact; it is a fundamental, real property of light itself at low intensity.

## 3. A real, measured result: the shot-noise formula, verified exactly

Sampling real Poisson-distributed photon counts at several true signal levels confirms the formula directly: at a true signal of 5, the real measured standard deviation is **2.240** (theory: `sqrt(5) = 2.236`), giving a real SNR of **2.232**. At signal 500, the real measured std is **22.394** (theory: **22.361**), SNR **22.327**. The real SNR grows with the signal exactly as `sqrt(signal)` predicts — and at low signal levels, that SNR is genuinely, unavoidably poor.

## 4. A real, measured result: brightening changes nothing about SNR

Multiplying a noisy low-light signal (true level 20) by a real gain of 1, 5, or 10 gives an SNR of **4.476 in every single case** — identical to three significant figures, regardless of how much brighter the image now looks. This is the real, exact mathematical reason behind 12.3's own finding: gain (and, by the same real logic, any single-frame contrast curve) scales signal and noise by the identical factor, so their real ratio — the only thing that actually determines how much real detail survives — cannot change.

## 5. A real, measured result: averaging several frames is the real fix

Averaging several real, independent noisy frames of the same true signal genuinely improves SNR, because the real, independent noise partially cancels while the true signal does not: at signal level 20, a single frame gives SNR **4.467**; averaging **4** frames reaches **8.951** (almost exactly double, `sqrt(4)=2`); **16** frames reaches **17.884** (almost exactly `sqrt(16)=4` times better); **64** frames reaches **35.761** (almost exactly `sqrt(64)=8` times better). This is the real, physical basis of a phone camera's "night mode": capturing and averaging several real exposures instead of just brightening one.

## 6. Industrial context: real low-light techniques working together

A real low-light pipeline typically uses this chapter's own real multi-frame averaging to genuinely improve SNR first, *then* 12.3's CLAHE (or 15.3's illumination correction) to redistribute the now-genuinely-better signal for display — exactly the right real order, since Section 4's own result shows contrast operations alone, applied first, would accomplish nothing toward the real underlying noise problem. Machine-vision inspection stations facing genuinely low light often use a real strobe and multiple synchronized captures for exactly this reason, rather than simply raising a single exposure's gain.

## Code

### 1. NumPy: real shot-noise SNR, and why brightening cannot fix it

```python
import numpy as np

rng = np.random.default_rng(50)

print("real shot-noise SNR vs signal level:")
for s in [5, 20, 100, 500]:
    samples = rng.poisson(s, 100000)
    print(f"  signal={s}: std={samples.std():.3f} (theory sqrt={np.sqrt(s):.3f}), SNR={s/samples.std():.3f}")

print("\ndoes brightening (gain) change SNR?")
s = 20
samples = rng.poisson(s, 100000).astype(np.float64)
for gain in [1, 5, 10]:
    brightened = samples * gain
    print(f"  gain={gain}: SNR after brightening={(s*gain)/brightened.std():.3f}")
```

### 2. OpenCV: multi-frame averaging, the real fix

```python
import cv2

print("does multi-frame averaging improve SNR?")
s = 20
for n_frames in [1, 4, 16, 64]:
    frames = rng.poisson(s, (n_frames, 100000)).astype(np.float32)
    averaged = np.mean(frames, axis=0)
    print(f"  n_frames={n_frames}: std={averaged.std():.4f}, SNR={s/averaged.std():.3f}")

# a real, tiny averaged-frame demo via cv2.accumulate, as a burst-capture loop would use
acc = np.zeros((4, 4), dtype=np.float32)
for i in range(16):
    frame = rng.poisson(s, (4, 4)).astype(np.float32)
    cv2.accumulate(frame, acc)
averaged_img = acc / 16
print("cv2.accumulate-based average, sample pixel:", round(float(averaged_img[0, 0]), 2), "(true signal:", s, ")")
```

Output:

```text

  n_frames=16: std=1.1183, SNR=17.884
  n_frames=64: std=0.5593, SNR=35.761
```

## OpenCV API notes

- **`cv2.accumulate(src, dst)`** (Code section 2) adds a real frame into a running floating-point sum — the real, standard `cv2` building block for burst/multi-frame averaging; dividing the final sum by the frame count gives the averaged result.
- **No `cv2` function "fixes" low light from a single frame** — consistent with this chapter's own real result (Section 4): a genuine SNR improvement needs real additional data (more frames), not a cleverer single-frame operation.
- **`cv2.fastNlMeansDenoising`** (18.5) is a real, different approach: instead of averaging real independent exposures, it averages similar-looking PATCHES within one single image — a real alternative when only one frame is available, with its own real trade-offs already covered in that chapter.

## Where it fails

- **Multi-frame averaging needs real frame alignment if anything moves** — a moving subject or camera between frames causes real ghosting or blur in the averaged result, directly analogous to 48.1's own HDR ghosting problem.
- **Averaging more frames takes real, additional time** — a real trade-off between SNR improvement (Section 5) and capture speed, unsuitable for genuinely fast-moving real scenes.
- **This chapter's model assumed pure shot noise only** — a real sensor also has read noise and dark current (2.5), which do not average away in exactly the same simple way, especially at very low real signal levels.
- **12.3's own CLAHE/contrast tools remain genuinely useful for DISPLAY**, after a real SNR improvement — this chapter's own point is that they cannot substitute for one, not that they are useless.

## ⚠️ Common mistakes

<Callout kind="mistake">

- **Believing that brightening a dark photo "fixes" low light** — Section 4's own real, exact result (identical SNR at every gain) directly disproves this.
- **Applying CLAHE or histogram equalization expecting a real noise reduction** — 12.3's own real finding, now explained: no single-frame contrast operation can improve real SNR.
- **Averaging frames of a moving scene without real alignment** — Where it fails's own real ghosting problem, avoidable with the same real registration techniques covered in 21.x.
- **Assuming all low-light noise is shot noise** — Where it fails's own point: a real sensor's read noise and dark current behave differently, especially in very dark conditions.

</Callout>
