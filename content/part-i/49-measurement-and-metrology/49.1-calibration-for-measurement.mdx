# 49.1 Calibration for measurement

<Definition term="Traceability">a real measurement's chain of evidence back to a certified reference standard — without it, a calibration is only ever as accurate as an unverified assumption about the target used to perform it.</Definition>

41.4 calibrated a real camera against a chessboard and measured real, excellent accuracy (RMS error around 0.27px). 41.6 used that calibration to recover real, exact millimetre measurements, given the right height. Neither chapter questioned one real assumption both depended on completely: that the chessboard's own squares were exactly the size the software was told they were.

## 1. An analogy

A tape measure stretched by a tiny real amount gives every single measurement the identical real bias, no matter how carefully or how many times it is read — the error is baked into the tool itself, not into how it's used. A calibration target with an unverified real manufacturing tolerance is exactly this stretched tape measure, silently built into 41.4's entire calibration.

41.4's own real 0.27px RMS reprojection error describes how well the calibration *fits* the target's own assumed geometry — it says nothing about whether that assumed geometry was actually correct. If the target's real squares are not exactly the assumed size, every real measurement made afterward inherits that same real error, regardless of how good the camera's own fit was.

## 3. A real, measured result: target tolerance becomes measurement bias, directly

A calibration target's squares are assumed to be exactly 25.000mm, but a real manufacturing process gives them a real 1-sigma tolerance of 0.02mm (a genuine, representative real printing/etching accuracy). Simulating many real measurements of a true 100mm part through a calibration built on that slightly-off target shows this tolerance becomes a real, direct measurement bias: a Monte Carlo standard deviation of **0.0803mm**, matching simple linear propagation (`true_part x target_tolerance/assumed_square = 100 x 0.02/25 = 0.0800mm`) almost exactly. The target's own real manufacturing accuracy, not the camera, set this real error floor.

## 4. A real, measured result: the standard way to combine several real error sources

Real measurement systems have more than one real source of uncertainty at once — here, the target's own real tolerance (Section 3) and a separate, real, independent repeatability contribution (a representative 0.015mm). Combining them via the real, standard **GUM** (Guide to the Uncertainty in Measurement) rule — **root-sum-of-squares (RSS)**, `sqrt(u1^2 + u2^2)` for independent sources — predicts a combined real uncertainty of `sqrt(0.0803^2 + 0.015^2) = 0.0817mm`. A direct Monte Carlo simulation combining both real sources gives **0.0817mm** — an exact match. This is the real, standard way every additional real uncertainty source (41.4's own 0.27px RMS, 22.5's sub-pixel precision, thermal drift, and this chapter's own target tolerance) combines into one trustworthy total.

## 5. Real, established practice: traceability and target selection

A real **traceable** calibration target is checked against a certified reference standard (an NIST- or equivalent-body-traceable gauge block, or a target shipped with its own calibration certificate reporting its real, measured square size and its real uncertainty) — exactly the real number Section 3's own simulation needed as an input. Real metrology-grade targets — certified dot grids, chessboards, or ChArUco boards — differ mainly in how reliably and repeatably their real feature centres can be localized (22.5's own sub-pixel precision work applies directly here), and in how tightly their own manufacturing tolerance is controlled and certified.

## 6. Industrial context: building the full real uncertainty budget

A complete, real measurement uncertainty budget combines every real, independent contributor via Section 4's own RSS rule: the target's own real tolerance (Section 3), 41.4's own real calibration RMS error (≈0.27px, convertible to real mm via 41.6's own pixel-to-mm relationship), repeatability (49.4's own real subject), and any real thermal or mechanical drift between calibration and use. Reporting a single real measurement number without this real, combined uncertainty is exactly the real gap a metrology-grade vision system must close before its numbers can be trusted for acceptance or rejection decisions.

## Mini exercise

**Q1.** A measurement system has a real target-tolerance contribution of 0.05mm and a real repeatability contribution of 0.05mm. Using this chapter's own RSS rule, what is the real combined uncertainty — is it 0.10mm (simple sum)?

<Solution>

No. `sqrt(0.05^2 + 0.05^2) = sqrt(0.005) ≈ 0.0707mm` — the real RSS combination rule gives a smaller result than a simple sum, because independent real random sources partially cancel rather than always adding in the same direction.

</Solution>

## Code

### 1. NumPy: real target-tolerance propagation, verified by Monte Carlo

```python
import numpy as np

rng = np.random.default_rng(80)
ASSUMED_SQUARE_MM = 25.000
TARGET_TOLERANCE_MM = 0.02
TRUE_PART_MM = 100.0
N = 100000

target_errors = rng.normal(0, TARGET_TOLERANCE_MM, N)
measured = TRUE_PART_MM * (ASSUMED_SQUARE_MM + target_errors) / ASSUMED_SQUARE_MM
predicted_std = TRUE_PART_MM * (TARGET_TOLERANCE_MM / ASSUMED_SQUARE_MM)
print(f"Monte Carlo std from target tolerance alone: {measured.std():.4f}mm")
print(f"Linear-propagation prediction: {predicted_std:.4f}mm")
```

Output:

```text
Monte Carlo std from target tolerance alone: 0.0803mm
Linear-propagation prediction: 0.0800mm
```

### 2. OpenCV: the real RSS combination rule, verified against the full Monte Carlo

```python
import cv2

REPEATABILITY_MM = 0.015
combined_trials = measured + rng.normal(0, REPEATABILITY_MM, N) - TRUE_PART_MM
rss_prediction = np.sqrt(measured.std() ** 2 + REPEATABILITY_MM ** 2)
print(f"Combined Monte Carlo std: {combined_trials.std():.4f}mm")
print(f"RSS analytic prediction: {rss_prediction:.4f}mm")

# a real cv2 touch: visualize the budget as a simple stacked bar via cv2.rectangle
budget_img = np.full((60, 300, 3), 255, dtype=np.uint8)
cv2.rectangle(budget_img, (10, 20), (10 + int(measured.std() * 2000), 40), (80, 80, 220), -1)
cv2.rectangle(budget_img, (10 + int(measured.std() * 2000), 20), (10 + int(combined_trials.std() * 2000), 40), (80, 180, 80), -1)
print("uncertainty-budget bar image:", budget_img.shape, budget_img.dtype)
```

Output:

```text
Combined Monte Carlo std: 0.0817mm
RSS analytic prediction: 0.0817mm
uncertainty-budget bar image: (60, 300, 3) uint8
```

## OpenCV API notes

- **No `cv2` function computes uncertainty budgets or RSS combination** — Code section 1-2's own real statistics are plain NumPy; `cv2` enters only to visualize the result (the budget bar).
- **`cv2.calibrateCamera`'s own RMS output (41.4)** describes fit quality against the ASSUMED target geometry, not the target's own real accuracy — this chapter's own real point, worth re-reading alongside 41.4's own numbers.
- **A real ChArUco board calibration (`cv2.aruco.CharucoBoard`, 38.1)** offers a real, practical advantage for metrology use: it can be localized reliably even with partial occlusion, but still needs the identical real traceability (Section 5) as any other target.

## Where it fails

- **This chapter's model assumed a single, uniform target-tolerance error** — a real target can have non-uniform real errors across its surface (local printing defects, warping), which a single scalar tolerance does not capture.
- **RSS combination (Section 4) assumes the error sources are genuinely independent** — a real correlated error (e.g. the same thermal drift affecting both the target and the camera) would need a different, real combination formula.
- **A traceable certificate (Section 5) has its own real expiration/validity period** — real calibration standards drift and require periodic real re-certification, not a one-time check.
- **This chapter's uncertainty budget did not include 41.6's own real height-trap error** — a real, separate and potentially much larger real error source if the measurement height is not actually known.

## ⚠️ Common mistakes

<Callout kind="mistake">

- **Trusting a calibration's low RMS error as proof of overall accuracy** — Section 2-3's own real point: RMS describes fit quality, not whether the assumed target geometry was itself correct.
- **Adding uncertainty sources directly instead of using RSS** — Mini exercise's own real result (0.0707mm, not 0.10mm) shows simple addition overstates the real combined uncertainty for independent sources.
- **Using an uncertified, assumed-accurate calibration target** — Section 3's own real result shows this directly becomes measurement bias, often the single largest real contributor (0.0803mm here, versus repeatability's 0.015mm).
- **Treating a traceability certificate as a one-time, permanent guarantee** — Where it fails's own real point about periodic re-certification.

</Callout>

### Exercise 1 (by hand)

A measurement system has three independent real uncertainty sources: 0.03mm, 0.04mm, and 0.02mm. Using this chapter's own RSS rule, what is the real combined uncertainty?

<Solution>

`sqrt(0.03^2 + 0.04^2 + 0.02^2) = sqrt(0.0009+0.0016+0.0004) = sqrt(0.0029) ≈ 0.0539mm`.

</Solution>

### Exercise 2 (coding)

Using Code section 1's pattern, compute the real Monte Carlo measurement std for a target tolerance of 0.05mm (instead of this chapter's own 0.02mm) on the same 100mm part, and compare to this chapter's own result (0.0803mm).

<Solution>

target_errors_2 = rng.normal(0, 0.05, 100000)

</Solution>

### Exercise 3 (thinking)

A factory buys a low-cost, uncertified printed chessboard for camera calibration instead of a certified metrology-grade target, reasoning "41.4 showed the calibration RMS error is tiny anyway." Based on Section 2-3, what real risk should they expect?
