# 32.1 Sliding comparison

<Definition term="Template matching">finding where a small reference image (the template) appears in a larger image, by placing the template at every possible position, measuring how similar the covered patch is, and picking the position(s) with the best score.</Definition>

When you know exactly what you are looking for, a fiducial mark, a logo, a component, a connector, the simplest detector is a picture of it. Template matching compares that picture with every patch of the image. It needs no training, works with one example and is easy to understand; its limits (rotation, scale, lighting, 32.4) decide when you need more.

## 1. An analogy

Looking for a jigsaw piece's place in the finished picture: you hold the piece over the picture and slide it around, comparing it with what is underneath at every position. Where the piece and the picture agree best, that is its place.

## 2. The procedure

<Flow

    { label: "Image W × H, template w × h", tone: "data" },

The simplest score is the **sum of squared differences** (SSD): 0 for a perfect match, larger for worse ones. Chapter 32.2 compares SSD with correlation scores that tolerate lighting changes.

The score map is smaller than the image: position (x, y) means the template's **top-left corner** is at (x, y), so the match covers x … x + w − 1 and y … y + h − 1. Its centre is at (x + w/2, y + h/2).

## 3. A worked example by hand

A 1-D signal 3, 7, 2, 8, 9, 1 and the template 8, 9:

| Position | Patch | SSD |
| --- | --- | --- |
| 0 | 3, 7 | (3 − 8)² + (7 − 9)² = 25 + 4 = 29 |
| 1 | 7, 2 | 1 + 49 = 50 |
| 2 | 2, 8 | 36 + 1 = 37 |
| 3 | 8, 9 | **0** |
| 4 | 9, 1 | 1 + 64 = 65 |

Five positions (6 − 2 + 1), and the minimum, 0 at position 3, is the match. In 2-D the same happens for every (x, y).

## 4. On a circuit board

The board image (240 × 150) contains five identical chips, plus altered copies (rotated, scaled, brighter, upside down). The template is the top-left chip, 31 × 27 pixels. The score map has 210 × 124 = 26 040 positions, each comparing 837 pixels: about 22 million multiplications for one search.

With SSD (`TM_SQDIFF`):

| Position (chip centre) | SSD |
| --- | --- |
| reference chip (40, 35) | 1 (the template itself; noise rounding) |
| identical chips | 16 150 to 54 387 (noise only) |
| upside-down chip (40, 122) | 138 030 |
| brighter chip (195, 110) | 598 899 |
| rotated chip (90, 80) | 2 333 750 |
| scaled chip (195, 45) | 3 188 800 |

The five identical chips stand out clearly. The brighter chip is the same shape, but SSD penalises the brightness change heavily: that is the main weakness of plain SSD.

## 5. Industrial use

- **Fiducial location** on PCBs and wafers for alignment before placement or inspection.
- **Presence checks**: is the label, connector or screw there (score above a threshold at the expected position)?
- **Counting identical items** on trays, in blister packs, on a print sheet.
- **Tracking** a patch from frame to frame in video (with the previous frame's patch as the template).

## Code

Three examples: the 1-D SSD, the board with OpenCV, and SSD from scratch.

### 1. The worked example

```python
import numpy as np
import cv2

signal = np.array([[3, 7, 2, 8, 9, 1]], np.float32)
template = np.array([[8, 9]], np.float32)
ssd = cv2.matchTemplate(signal, template, cv2.TM_SQDIFF)
print("SSD:", ssd.ravel().tolist(), "| best position:", int(np.argmin(ssd)))
```

Output:

```text
SSD: [29.0, 50.0, 37.0, 0.0, 65.0] | best position: 3
```

### 2. Matching on the board

```python
board = cv2.imread("sample-board.png", cv2.IMREAD_GRAYSCALE)
tpl = board[22:49, 25:56].copy()                                       # the reference chip, 31 × 27
h, w = tpl.shape
result = cv2.matchTemplate(board, tpl, cv2.TM_SQDIFF)
print("result map:", result.shape, "(rows, columns) =", (board.shape[0] - h + 1, board.shape[1] - w + 1))
min_val, max_val, min_loc, max_loc = cv2.minMaxLoc(result)
print("best (lowest) SSD:", min_val, "at top-left", min_loc, "-> centre", (min_loc[0] + w // 2, min_loc[1] + h // 2))
for name, (cx, cy) in [("identical (90, 35)", (90, 35)), ("brighter (195, 110)", (195, 110)), ("rotated (90, 80)", (90, 80))]:
    print(f"{name}: SSD {result[cy - h // 2, cx - w // 2]:.0f}")
```

Output:

```text
result map: (124, 210) (rows, columns) = (124, 210)
best (lowest) SSD: 1.0 at top-left (25, 22) -> centre (40, 35)
identical (90, 35): SSD 24312
brighter (195, 110): SSD 598899
rotated (90, 80): SSD 2333750
```

- `cv2.minMaxLoc` returns positions as (x, y); NumPy indexing is [row, column] = [y, x].

### 3. SSD from scratch, and several matches

```python
crop = board[10:70, 10:110].astype(np.float64)                         # small part of the board, for speed
ch, cw = crop.shape
mine = np.array([[((crop[y:y + h, x:x + w] - tpl) ** 2).sum() for x in range(cw - w + 1)] for y in range(ch - h + 1)])
ocv = cv2.matchTemplate(crop.astype(np.float32), tpl.astype(np.float32), cv2.TM_SQDIFF)
print("largest difference from OpenCV, relative to the largest score:", f"{np.abs(mine - ocv).max() / mine.max():.0e}")

good = result < 100_000                                                # threshold on SSD
local_min = result == cv2.erode(result, np.ones((9, 9), np.uint8))      # one point per match
ys, xs = np.nonzero(good & local_min)
print("matches:", sorted((int(x) + w // 2, int(y) + h // 2) for x, y in zip(xs, ys)))
```

Output:

```text
largest difference from OpenCV, relative to the largest score: 1e-06
matches: [(40, 35), (40, 80), (90, 35), (140, 35), (140, 80)]
```

- OpenCV computes in float32 (via correlation and box sums), so tiny rounding differences remain.
- The SSD threshold finds exactly the five identical chips; the brighter one (SSD 598 899) is rejected.

## OpenCV API notes

- **`cv2.matchTemplate(image, templ, method, mask=None)`** → float32 map of size (H − h + 1) × (W − w + 1). `image` and `templ`: 8-bit or float32, 1 or 3 channels (channels are summed). `mask` (optional, same size as `templ`) excludes template pixels from the comparison (32.4).
- **`cv2.minMaxLoc(result)`** → (min, max, minLoc, maxLoc); use min for `TM_SQDIFF*`, max for the others.
- **Multiple matches**: threshold the map, then keep local extrema (erode for minima, dilate for maxima) or suppress neighbours greedily.
- **Speed**: OpenCV uses DFT-based correlation for large templates; downscale both images first (32.3) for coarse search.

## Where it fails

- **Rotation and scale**: a template matches only objects at the same orientation and size (32.3, 32.4).
- **Lighting**: plain SSD fails when brightness or contrast changes; use normalised scores (32.2).
- **Clutter and occlusion**: partly hidden objects score badly.
- **Repeated patterns**: several equally good positions; add context or a larger template.

## ⚠️ Common mistakes

<Callout kind="mistake">

- **Taking the maximum of a SQDIFF map**: for SSD the best match is the minimum.
- **Reading the location as the centre**: it is the top-left corner.
- **Swapping (x, y)**: minMaxLoc gives (x, y); arrays index [y, x].
- **Template larger than the image**: the result map would be empty; OpenCV raises an error.

</Callout>

## 🔍 Go deeper

<GoDeeper>

### SSD and correlation

Expanding the square, SSD(x, y) = Σ I² − 2 Σ I·T + Σ T²: the template term is constant, the image term is a box sum (computed with an integral image, 17.5), and only the cross-correlation Σ I·T needs the full sliding product, which the FFT computes for all positions at once (30.5). This is how OpenCV and this course's lab compute all methods quickly.

### Sub-pixel location

The score map is sampled at whole pixels. Fitting a parabola (or a 2-D quadratic) to the best value and its neighbours gives the peak to a fraction of a pixel, the same trick as for sub-pixel edges (22.5).

</GoDeeper>

Time how long `cv2.matchTemplate` takes on the board compared with the Python loop of Code 3 on the whole board (estimate the loop from the crop). Print the ratio only as an order of magnitude.

<Solution>

```python
# Needs a timing run (results vary by machine)
import time
t0 = time.perf_counter(); cv2.matchTemplate(board, tpl, cv2.TM_SQDIFF); t1 = time.perf_counter()
_ = [[((crop[y:y + h, x:x + w] - tpl) ** 2).sum() for x in range(cw - w + 1)] for y in range(ch - h + 1)]; t2 = time.perf_counter()
```
