# 25.2 Region statistics

<Definition term="Region statistics">numbers computed for every labelled component: its area (pixel count), bounding box, centroid, and from them derived features such as equivalent diameter, aspect ratio and fill ratio; plus statistics of the original image inside each component, such as mean brightness. They turn a label image into a table with one row per object.</Definition>

Labelling (25.1) says which pixel belongs to which object. Most decisions need numbers per object: is it big enough to be a particle and not noise, too big to be a single particle, too dark, too elongated? `cv2.connectedComponentsWithStats` returns the basic table in the same pass as the labels; NumPy adds anything else without looping over pixels.

## 1. An analogy

A census. Labelling is drawing the boundary of every household; region statistics are the census form: how many people (area), where the house is (centroid), how big the plot is (bounding box), the average age (mean brightness). With the forms filled in, questions like "how many households have more than five people" are a single query.

## 3. Grey-value statistics per component

`np.bincount(labels.ravel(), weights=image.ravel())` sums the image values per label in one pass; dividing by the areas gives the mean brightness of every component. With `weights=image**2` the same gives variances; with other images (a depth map, a temperature image, 46.5) it gives mean depth or temperature per object. For minimum and maximum per label, sort or use `scipy.ndimage` functions, or loop over the bounding boxes (which are small).

Typical derived features:

- **Equivalent diameter** 2√(A/π): size of a disc with the same area.
- **Aspect ratio** of the box (or of the minAreaRect, 24.4, for rotated objects).
- **Fill ratio (extent)** A / (w · h); **solidity** needs the hull (24.5).
- **Mean, standard deviation of brightness** inside the object: contrast, uniformity, colour (per channel).
- **Touches the border**: left = 0, top = 0, left + width = W or top + height = H: partly visible objects, usually excluded from measurements.

## 4. Industrial example

Particle-size analysis of powders, sand or pellets labels each particle and reports the distribution of equivalent diameters (often as d10, d50, d90 percentiles), discarding components that touch the image border (their size is unknown) and flagging those with low fill ratio (agglomerates). Defect inspection does the same with defect candidates: area in mm², mean contrast against the surrounding surface, elongation; a rule or a classifier (36) on these few features decides "scratch", "spot" or "dust".

## Code

Two examples: the stats table with derived features, then grey statistics per component.

### 1. Stats and derived features

```python
import numpy as np
import cv2

img = cv2.imread("sample-particles.png", cv2.IMREAD_GRAYSCALE)
_, mask = cv2.threshold(img, 0, 255, cv2.THRESH_BINARY + cv2.THRESH_OTSU)
mask = cv2.morphologyEx(mask, cv2.MORPH_OPEN, np.ones((3, 3), np.uint8))
n, labels, stats, centroids = cv2.connectedComponentsWithStats(mask, connectivity=8)
s = stats[1:]                                                        # drop the background row
area = s[:, cv2.CC_STAT_AREA]
w, h = s[:, cv2.CC_STAT_WIDTH], s[:, cv2.CC_STAT_HEIGHT]
diameter = 2 * np.sqrt(area / np.pi)
aspect = np.maximum(w, h) / np.minimum(w, h)
fill = area / (w * h)
print("components:", n - 1, "| area min/median/max:", int(area.min()), int(np.median(area)), int(area.max()))
print("equivalent diameter median:", round(float(np.median(diameter)), 1))
merged = (fill < 0.72) | (aspect > 1.3)
print("suspected touching pairs:", int(merged.sum()), "| their boxes:", s[merged][:, :4].tolist())
border = (s[:, 0] == 0) | (s[:, 1] == 0) | (s[:, 0] + w == img.shape[1]) | (s[:, 1] + h == img.shape[0])
print("touching the image border:", int(border.sum()))
```

Output:

```text
components: 35 | area min/median/max: 112 244 948
equivalent diameter median: 17.6
suspected touching pairs: 4 | their boxes: [[272, 10, 23, 36], [81, 55, 34, 55], [264, 112, 37, 27], [277, 143, 33, 19]]
touching the image border: 0
```

### 2. Grey-value statistics per component

```python
import numpy as np
import cv2

counts = np.bincount(labels.ravel(), minlength=n)
mean = np.bincount(labels.ravel(), weights=img.ravel().astype(float), minlength=n) / counts
var = np.bincount(labels.ravel(), weights=img.ravel().astype(float) ** 2, minlength=n) / counts - mean ** 2
print("mean brightness per particle: min", round(float(mean[1:].min()), 1), "max", round(float(mean[1:].max()), 1))
print("background mean:", round(float(mean[0]), 1), "| particle std (median):", round(float(np.median(np.sqrt(var[1:]))), 1))
k = int(np.argmax(stats[1:, cv2.CC_STAT_AREA])) + 1
print(f"largest component #{k}: area {stats[k, cv2.CC_STAT_AREA]}, centroid ({centroids[k][0]:.1f}, {centroids[k][1]:.1f}), mean {mean[k]:.1f}")
```

Output:

```text
mean brightness per particle: min 170.2 max 176.8
background mean: 61.4 | particle std (median): 21.7
largest component #11: area 948, centroid (96.7, 81.6), mean 175.9
```

- Particle brightness is uniform from particle to particle (170–177); inside each particle it varies by about 22 (domes from 160 at the rim to 200 at the centre, plus noise). A particle much darker than the others would stand out in `mean` immediately.

## OpenCV API notes

**`n, labels, stats, centroids = cv2.connectedComponentsWithStats(image, connectivity=8, ltype=cv2.CV_32S)`**:
- `stats`: n × 5 int32: `CC_STAT_LEFT`, `CC_STAT_TOP`, `CC_STAT_WIDTH`, `CC_STAT_HEIGHT`, `CC_STAT_AREA` (row 0 = background).
- `centroids`: n × 2 float64 (x, y).
- `cv2.connectedComponentsWithStatsWithAlgorithm` chooses the labelling algorithm.

**Per-label statistics**: `np.bincount` (sums, counts), `cv2.mean(img, mask=(labels == k).astype(np.uint8))` for one component, `scipy.ndimage.labeled_comprehension` / `mean` / `maximum` for many.

## Where it fails

- **Merged and split objects**: statistics describe components, not objects; a touching pair looks like one big object.
- **Box-based features** (aspect, fill) depend on orientation: a diagonal bar has a low fill ratio; use minAreaRect (24.4) or moments (24.6) for rotation-independent shape features.
- **Small components**: shape features of a few pixels are meaningless.
- **Border objects**: partially visible; their size is wrong.

## ⚠️ Common mistakes

<Callout kind="mistake">

- **Including row 0** (the background) in statistics.
- **Python loops over labels with `labels == k`** for hundreds of components: slow; use bincount.
- **Mean brightness from the thresholded mask** instead of the original image.
- **Measuring objects that touch the image border**.

</Callout>

## 🔍 Go deeper

### Region properties

Libraries such as scikit-image's `regionprops` compute dozens of features per region: moments, orientation, eccentricity, solidity, Euler number, Feret diameters, intensity statistics. Each is a few lines from the labels and the moments (24.6); the art is choosing features that separate the classes you care about (36.1).

### Particle size statistics

ISO 9276 [1] standardises how particle size distributions are reported (number- or volume-weighted, d10/d50/d90). Image-based sizing measures a 2-D projection: the equivalent diameter of the projected area is one of several possible "sizes" and differs from sieve or laser-diffraction results for non-spherical particles.

</GoDeeper>

### Exercise 2 (coding)

Compute d10, d50 and d90 of the equivalent diameters of the particles, once with all components and once without the suspected touching pairs.

<Solution>

```python
import numpy as np

for name, d in [("all components", diameter), ("without touching pairs", diameter[~merged])]:
    p10, p50, p90 = np.percentile(d, [10, 50, 90])
    print(f"{name:23s} n={len(d):2d} d10 {p10:.1f} | d50 {p50:.1f} | d90 {p90:.1f}")
```

Output:

```text
all components          n=35 d10 13.1 | d50 17.6 | d90 24.9
without touching pairs  n=31 d10 13.1 | d50 16.3 | d90 23.0
```

The merged pairs shift the distribution upwards (d50 17.6 → 16.3, d90 24.9 → 23.0): agglomerates make a powder look coarser than it is. Splitting them (25.4) instead of dropping them recovers all 40 particles.

</Solution>
