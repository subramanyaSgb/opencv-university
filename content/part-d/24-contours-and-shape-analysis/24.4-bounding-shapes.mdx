# 24.4 Bounding shapes

<Definition term="Bounding shapes">simple geometric figures that enclose or approximate a contour: the upright bounding rectangle, the smallest rotated rectangle, the smallest enclosing circle, and a best-fit ellipse. They summarise a shape's position, size and orientation in a few numbers.</Definition>

A contour has hundreds of points. For many tasks you need only a box to crop around the part, its length and width regardless of how it lies, its orientation for a robot gripper, or the diameter of the smallest hole it would pass through. OpenCV provides one function for each: `boundingRect`, `minAreaRect`, `minEnclosingCircle` and `fitEllipse`.

## 1. An analogy

Packing an object for shipping. The upright box from the shelf (bounding rectangle) is quick to pick but wastes space if the object lies diagonally. Turning the object until it fits the smallest box (rotated rectangle) saves space and tells you its length and width. A round tube (enclosing circle) is what you need if it must pass through a round opening. A tailor-made oval sleeve (ellipse) follows the shape's overall elongation.

## 3. The angle of minAreaRect

`cv2.minAreaRect` returns ((cx, cy), (w, h), angle). The same rectangle can be described as w × h at angle a or as h × w at a ± 90°; OpenCV picks one, and the convention has changed between versions. In OpenCV 4.13 on these shapes the angle comes out between −90° and 0°: the bar, drawn 90 × 34 rotated by 25°, is reported as 34.89 × 90.52 at −64.89°, which is the same rectangle as 90.52 × 34.89 at 25.11°.

Rule: **normalise yourself**. If you want "length along the long axis, angle of the long axis", swap w and h when w < h and add 90° to the angle; then wrap the angle into the range you need. Or use `cv2.boxPoints(rect)` to get the four corners and compute directions from them, which does not depend on the convention.

## 4. Industrial example

Robot picking from a conveyor uses `minAreaRect` on each part's contour: the centre gives the pick point, the normalised angle of the long side gives the gripper rotation, and the width checks that the part fits between the gripper jaws. Gauging of long parts (pins, rods, profiles) measures the rotated rectangle's length and width instead of the upright box, so that a part lying at an angle is not reported as too wide. The enclosing circle is used for "go/no-go" checks of parts that must fit a round fixture.

### 1. Bounding shapes of the parts

```python
import numpy as np
import cv2

parts = cv2.imread("sample-parts.png", cv2.IMREAD_GRAYSCALE)
contours, _ = cv2.findContours(parts, cv2.RETR_EXTERNAL, cv2.CHAIN_APPROX_NONE)
names = ["oval", "star", "bar", "L-bracket", "washer", "plate"]
for name, c in zip(names, contours):
    A = cv2.contourArea(c)
    x, y, w, h = cv2.boundingRect(c)
    (cx, cy), (rw, rh), angle = cv2.minAreaRect(c)
    (ex, ey), r = cv2.minEnclosingCircle(c)
    _, (ea, eb), eang = cv2.fitEllipse(c)
    print(f"{name:9s} box {w:3d}x{h:<3d} extent {A / (w * h):.2f} | rot {rw:6.2f}x{rh:<6.2f} {angle:7.2f} deg fill {A / (rw * rh):.2f}"
          f" | circle r {r:5.2f} | ellipse {ea:6.2f}x{eb:.2f}")
```

### 2. Normalising minAreaRect

```python
import numpy as np
import cv2

def long_axis(rect):
    """Return (length, width, angle of the long side in [0, 180))."""
    (cx, cy), (w, h), a = rect
    if w < h:
        w, h, a = h, w, a + 90
    return w, h, a % 180

bar = contours[2]
rect = cv2.minAreaRect(bar)
length, width, angle = long_axis(rect)
print(f"raw: {rect[1][0]:.2f} x {rect[1][1]:.2f} at {rect[2]:.2f} deg -> length {length:.2f}, width {width:.2f}, angle {angle:.2f} deg")
corners = cv2.boxPoints(rect)                                        # 4 x 2 float32
edge = corners[1] - corners[0]
print("corners:", np.round(corners.astype(float), 1).tolist())
```

Output:

```text
raw: 34.89 x 90.52 at -64.89 deg -> length 90.52, width 34.89, angle 25.11 deg
corners: [[103.1, 184.5], [21.1, 146.1], [35.9, 114.5], [117.9, 152.9]]
```

- The bar was drawn 90 × 34 at 25°: the normalised result matches to half a pixel and 0.1°.

## OpenCV API notes

- **`cv2.boundingRect(points)`** → (x, y, w, h), integers; also works on a mask (non-zero pixels).
- **`cv2.minAreaRect(points)`** → ((cx, cy), (w, h), angle); **`cv2.boxPoints(rect)`** → 4 corners (float32).
- **`cv2.minEnclosingCircle(points)`** → ((cx, cy), r).
- **`cv2.fitEllipse(points)`** (≥ 5 points) → ((cx, cy), (axis1, axis2), angle): full axis lengths, not semi-axes. Variants `cv2.fitEllipseAMS` and `cv2.fitEllipseDirect` use other fitting criteria and behave better on partial arcs (26.4).
- **`cv2.minEnclosingTriangle(points)`** → (area, triangle); **`cv2.approxPolyDP(curve, epsilon, closed)`** for polygon approximation.
- Points: int32 or float32 arrays of shape (N, 1, 2) or (N, 2).

## Where it fails

- **Noise and spurs**: one outlying point changes the enclosing circle and the rotated rectangle; clean the contour or use a robust fit.
- **Symmetric shapes**: a square or disc has no defined orientation; the angle is arbitrary.
- **fitEllipse on non-elliptical shapes**: axes larger than the shape (the bar) or meaningless.
- **Pixel-level accuracy only**: for gauging to sub-pixel accuracy, fit lines to sub-pixel edge points (22.5, 26.4).

## ⚠️ Common mistakes

<Callout kind="mistake">

- **Using the minAreaRect angle without normalising** (and code breaking across OpenCV versions).
- **Taking fitEllipse axes as semi-axes** when drawing with `cv2.ellipse` (which wants semi-axes: divide by 2).
- **Using boundingRect to measure tilted parts**.
- **Passing a list of points with the wrong dtype** (float64) to these functions.

</Callout>

### Algorithms

`minAreaRect` uses rotating calipers on the convex hull (Toussaint 1983, after Freeman and Shapira 1975 [1]): the minimum-area rectangle has one side collinear with a hull edge, so only as many orientations as hull edges need to be tested. `minEnclosingCircle` is solved in expected linear time by Welzl's randomised algorithm [2]. `fitEllipse` minimises algebraic distances (Fitzgibbon et al. [3]).

### Orientation from moments

The orientation of the ellipse with the same second moments as the region (24.6) is another, smoother orientation estimate: it uses all pixels rather than the hull, and is less sensitive to single outlying points.

</GoDeeper>

### Exercise 1 (by hand)

A 40 × 10 rectangle rotated by 45°. What is its upright bounding box (approximately), its extent, and its minimum-area rectangle?

<Solution>

Its corners project to about (40 + 10)/√2 ≈ 35.4 pixels in x and in y: a 35.4 × 35.4 box, extent 400 / 1 250 ≈ **0.32**. The minimum-area rectangle is the rectangle itself: **40 × 10** at 45°.

</Solution>

### Exercise 2 (coding)

Crop the rotated bar upright: build a rotation matrix from the normalised minAreaRect (rotate by its angle around its centre), warp the image, and crop length × width around the centre. Report the size and the fraction of white pixels in the crop.

<Solution>

```python
import numpy as np
import cv2

(cx, cy), _, _ = rect
M = cv2.getRotationMatrix2D((cx, cy), angle, 1.0)                    # rotate the long axis to horizontal
upright = cv2.warpAffine(parts, M, (parts.shape[1], parts.shape[0]))
crop = cv2.getRectSubPix(upright, (int(round(length)), int(round(width))), (cx, cy))
print("crop size (w x h):", crop.shape[1], "x", crop.shape[0], "| white fraction:", round(float((crop > 127).mean()), 3))
```

Output:

```text
crop size (w x h): 91 x 35 | white fraction: 0.997
```

The bar now lies horizontally and almost fills the crop: a standard step before OCR on tilted labels or before measuring along a part's axis (16.1).

</Solution>
