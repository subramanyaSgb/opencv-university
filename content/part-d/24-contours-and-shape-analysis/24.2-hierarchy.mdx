# 24.2 Hierarchy

<Definition term="Contour hierarchy">the information about which contours lie inside which: an object's outer border, the borders of its holes, objects sitting inside those holes, and so on. OpenCV returns it as one row of four numbers per contour: the next and previous contour at the same level, the first child, and the parent (−1 where there is none).</Definition>

A washer has two borders: the outer edge and the hole. A plate with two holes has three. A pin lying inside one of those holes is a separate object inside a hole inside an object. 24.1 listed contours; the hierarchy says how they belong together. It answers practical questions: does this part have its holes, how many, what is its area without the holes, and is anything stuck inside a hole?

## 1. An analogy

A family tree, or folders on a disk. The image is the top folder. Each part is a folder in it; each hole is a folder inside its part; an object lying in a hole is a folder inside the hole. OpenCV stores, for each folder, its next sibling, previous sibling, first sub-folder and parent folder.

The rows for the plate branch, as `[next, previous, first child, parent]`:

| Contour | Row | Meaning |
| --- | --- | --- |
| #6 plate | [−1, 4, 7, −1] | last top-level contour (next −1, previous #4 washer); first child #7; no parent |
| #7 round hole | [8, −1, −1, 6] | sibling #8 follows; no children; parent #6 |
| #8 square hole | [−1, 7, 9, 6] | last child of #6; first child #9 |
| #9 pin | [−1, −1, −1, 8] | only child of the square hole |

Levels alternate: outer border (depth 0), hole (1), object in a hole (2), hole in that object (3), and so on. An even depth is an object, an odd depth a hole.

**RETR_CCOMP** squeezes everything into two levels: every outer border is top level, and each hole is a child of its object. The pin, though it lies in a hole, becomes a top-level contour of its own (with no parent). That is enough for "objects and their holes" and is often what you want. **RETR_LIST** gives the same 10 contours with all parent and child entries −1. **RETR_EXTERNAL** returns only the 6 outer borders: the holes and the pin are not reported at all.

## 3. Using the hierarchy

- **Holes of a part**: start at its first child (`hierarchy[i][2]`) and follow `next` (`hierarchy[j][0]`) until −1.
- **Is a contour a hole?** In TREE or CCOMP, it is a hole if its depth (number of parents) is odd.
- **Net area of a part**: outer area minus the areas of its holes. Plate: 8 000 − 474 − 1 022 = **6 504** (contour areas through pixel centres). The pin, an object of its own, is not subtracted.
- **Inspection logic**: "the washer must have exactly one hole of area 800 ± 60", "the plate must have two holes", "nothing may sit inside a hole" (any grandchild is a foreign object).

## 4. Industrial example

Gasket and stamping inspection checks that every punched hole is present: the part's contour must have the right number of child contours, each with the right area and position relative to the part's centroid. A missing hole means no child contour; a hole blocked by a slug shows up as a grandchild (an object inside the hole). The hierarchy turns these checks into a few lines of code, without any template matching.

## Code

Two examples: printing the tree, then holes and net areas.

### 1. The tree

```python
import numpy as np
import cv2

parts = cv2.imread("sample-parts.png", cv2.IMREAD_GRAYSCALE)
contours, hierarchy = cv2.findContours(parts, cv2.RETR_TREE, cv2.CHAIN_APPROX_SIMPLE)
h = hierarchy[0]                                                    # shape (N, 4)

def depth(i):
    d = 0
    while h[i][3] != -1:
        i, d = h[i][3], d + 1
    return d

for i, c in enumerate(contours):
    x, y, w, hh = cv2.boundingRect(c)
    kind = "object" if depth(i) % 2 == 0 else "hole"
    print(f"{'  ' * depth(i)}#{i} {kind:6s} row {h[i].tolist()} box ({x}, {y}, {w}, {hh}) area {cv2.contourArea(c)}")
```

Output:

### 2. Holes per part and net area

```python
import numpy as np
import cv2

def children(i):
    j, out = h[i][2], []
    while j != -1:
        out.append(int(j))
        j = h[j][0]
    return out

for i, c in enumerate(contours):
    if depth(i) % 2:                                                 # skip holes
        continue
    holes = children(i)
    net = cv2.contourArea(c) - sum(cv2.contourArea(contours[j]) for j in holes)
    inside = [k for j in holes for k in children(j)]                  # objects sitting in a hole
    print(f"#{i}: {len(holes)} hole(s), net area {net:.1f}" + (f", objects inside holes: {inside}" if inside else ""))

cc, hc = cv2.findContours(parts, cv2.RETR_CCOMP, cv2.CHAIN_APPROX_SIMPLE)
pin = [i for i, c in enumerate(cc) if cv2.contourArea(c) == 66.0][0]
print("with RETR_CCOMP the pin's row is", hc[0][pin].tolist())
```

Output:

```text
#0: 0 hole(s), net area 2622.0
#1: 0 hole(s), net area 1362.0
#2: 0 hole(s), net area 3043.0
#3: 0 hole(s), net area 2300.5
#4: 1 hole(s), net area 3564.0
#6: 2 hole(s), net area 6504.0, objects inside holes: [9]
#9: 0 hole(s), net area 66.0
with RETR_CCOMP the pin's row is [4, 2, -1, -1]
```

## OpenCV API notes

- **`hierarchy`** from `cv2.findContours`: shape (1, N, 4), int32: `[next, previous, first_child, parent]` per contour, in the same order as `contours`. `None` if there are no contours.
- **Modes**: `RETR_EXTERNAL` (only the top level, children and parents −1), `RETR_LIST` (all contours, children and parents −1), `RETR_CCOMP` (two levels), `RETR_TREE` (full), `RETR_FLOODFILL` (for 32-bit label images).
- **Drawing a part with its holes**: `cv2.drawContours(mask, contours, i, 255, -1, hierarchy=hierarchy, maxLevel=1)` fills contour i and leaves its holes empty.

## Where it fails

- **Holes touching the outline** (a C-shape instead of an O): they are not holes topologically; the outer contour goes around them and no child exists.
- **Noise inside parts**: specks of black become holes; clean the mask (23.2).
- **Touching parts**: one outer contour for two parts; their holes are children of the merged contour.
- **Order**: do not assume parts come in reading order.

## ⚠️ Common mistakes

<Callout kind="mistake">

- **Using RETR_EXTERNAL and then wondering where the holes are**.
- **Treating every contour of RETR_LIST as an object** (holes included).
- **Forgetting `hierarchy[0]`**: the array has an extra leading dimension.
- **Subtracting objects-in-holes from the part's area**: only holes (odd depth) are subtracted.

</Callout>

## 🔍 Go deeper

<GoDeeper>

### Topology of binary images

Suzuki and Abe [1] defined the "surroundness" relation between borders: outer borders and hole borders alternate along any path from the image frame inwards. With 8-connectivity for the foreground and 4-connectivity for the background (OpenCV's convention), every hole is enclosed by exactly one object and every object (except top-level ones) lies in exactly one hole, which makes the hierarchy a proper tree.

### Euler number

The Euler number of a binary image is the number of objects minus the number of holes; it is a classic topological shape feature (for the parts image: 7 objects − 3 holes = 4). It can be computed from the hierarchy or directly from 2 × 2 pixel patterns (bit-quad counting).

</GoDeeper>

Draw only the plate with its holes into an empty mask using `drawContours` with `hierarchy` and `maxLevel=1`, and count its white pixels. Compare with the net contour area.
