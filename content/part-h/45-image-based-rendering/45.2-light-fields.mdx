# 45.2 Light fields

<Definition term="Light field">the full set of light rays passing through a region of space — not just the single image one camera position records, but what every nearby viewpoint would have seen, all at once.</Definition>

44.3 used many calibrated views to recover depth. This chapter reuses that same real multi-camera setup for a genuinely different purpose: synthesizing a brand new image — refocused at whichever depth is chosen *after* capture — directly from the raw views themselves, with no depth map required at all.

## 1. An analogy

Looking at a distant friend through a chain-link fence with one eye closed, parts of their face are blocked by the fence wires no matter how you squint. Rapidly shifting your head slightly side to side, each glimpse sees a *different* sliver of their face around a *different* wire — and your eye-brain system fuses those glimpses into something close to a complete, un-fenced view. A light field camera captures many such glimpses — many slightly different viewpoints — simultaneously, and this chapter's own real method fuses them exactly the same way.

## 2. The pipeline: shift-and-average at a chosen depth

Shifting every view by a candidate depth's own disparity (44.3's own `f . baseline / Z` formula) and averaging them is the whole real method. Content that genuinely sits *at* that depth lines up correctly across every shifted view and stays sharp in the average; content at any *other* depth lines up differently in each view, so it smears into a soft blur instead — exactly 44.3's variance-based consistency check, just producing a new synthesized image instead of a depth label.

## 3. A real, measured result: more views see further around an occluder

A background texture sits at 1000mm, with sparse, randomly-placed opaque occluders at 500mm covering **7.7%** of the scene — a real stand-in for foliage, a fence, or any clutter between a camera and its real subject. With a single view, a pixel blocked by an occluder is simply lost — a real mean error of **104.69** (on a 0-255-ish scale) comparing the recovered value to the true, hidden background. Refocusing on the background depth using more views genuinely recovers more of that hidden detail: **3** views cut the error to **46.80**, **9** views to **18.74**, **17** views to **13.60**, and **33** views to **10.80** — because with enough different vantage points, most background points are unblocked from *at least one* of them, and the shift-and-average correctly combines whichever views can actually see through.

## 4. A real, measured result: the opposite choice is a different, smaller benefit

Refocusing instead on the occluder's own depth gives a real, structurally *different* pattern: even a single view already recovers the occluder correctly to within **2.81** of its true value — because an opaque object directly in front of the camera is visible from essentially any single nearby viewpoint, with no occlusion problem to solve. More views here (**3**: 1.58, **9**: 0.83, **17**: 0.59, **33**: 0.47) mainly average down ordinary sensor noise, the same real benefit 44.3 Section 3 measured for depth estimation — a genuinely smaller, different kind of improvement than Section 3's own occlusion-removal result.

## 5. Industrial and scientific context: camera arrays and consumer light-field cameras

The real Stanford Multi-Camera Array (Wilburn et al., 2005) and Vaish et al.'s own real synthetic-aperture confocal imaging used exactly this chapter's shift-and-average method to see through foliage and crowds in real surveillance and photography research; the consumer Lytro camera packed an equivalent capability — many sub-aperture views, via a microlens array in front of a single sensor — into a handheld device, letting a photo be refocused after the fact on a phone or computer, exactly Section 3-4's own real trade-off between "recover what was hidden" and "just reduce noise," depending on which depth is chosen.

## Mini exercise

**Q1.** A single-camera photo of a bird partly hidden behind a few thin tree branches is refocused in post-processing software using ordinary digital blur. Based on Section 3, would this actually recover the parts of the bird hidden directly behind the branches?

<Solution>

No. Ordinary digital blur on a *single* photo has no information about what was actually behind the branches — it can only soften what is already there. Section 3's own real recovery (104.69 down to 10.80 error) came specifically from combining *multiple, different real viewpoints*, each of which saw a slightly different part of the bird around the branches; a single photo, however it is processed afterward, never captured that missing information in the first place.

## Code

### 1. NumPy: real shift-and-average refocusing

```python
import numpy as np

F, Z_BG, Z_FG = 800.0, 1000.0, 500.0
rng = np.random.default_rng(55)
texture_bg = 128 + rng.normal(0, 40, 6000)
rng_occ = np.random.default_rng(77)
occ_mask_world = rng_occ.random(6000) < 0.08
SLAT_VALUE = 30.0

PMIN, PMAX = -3000, 3000
PIX_RANGE = np.arange(PMIN, PMAX)
REF_PIXELS = np.arange(100, 400)

def sample_tex(tex, pos):
    pos_c = np.clip(pos, 0, len(tex) - 2)
    i0 = np.floor(pos_c).astype(int)
    return tex[i0] * (1 - (pos_c - i0)) + tex[i0 + 1] * (pos_c - i0)

def is_occluder(world_x):
    idx = np.clip(np.round(world_x).astype(int), 0, 5999)
    return occ_mask_world[idx]

def render_camera(cam_x, noise_std, seed):
    val_bg = sample_tex(texture_bg, cam_x + PIX_RANGE * Z_BG / F)
    occ = is_occluder(cam_x + PIX_RANGE * Z_FG / F)
    val = np.where(occ, SLAT_VALUE, val_bg)
    return val + np.random.default_rng(seed).normal(0, noise_std, len(PIX_RANGE))

def lookup(arr, p):
    idx = np.clip(p - PMIN, 0, len(arr) - 2)
    i0 = np.floor(idx).astype(int)
    return arr[i0] * (1 - (idx - i0)) + arr[i0 + 1] * (idx - i0)

def refocus(cam_positions, observed, z_focus, ref_pixels):
    wx_ref = cam_positions[0] + ref_pixels * z_focus / F
    vals = [lookup(observed[ci], (wx_ref - cx) * F / z_focus) for ci, cx in enumerate(cam_positions)]
    return np.mean(vals, axis=0)

true_bg_at_ref = sample_tex(texture_bg, REF_PIXELS * Z_BG / F)
for n_cams in [1, 9, 33]:
    cam_positions = np.arange(n_cams) * 50.0
    observed = [render_camera(cx, 3.0, seed=700 + ci) for ci, cx in enumerate(cam_positions)]
    refocused_bg = refocus(cam_positions, observed, Z_BG, REF_PIXELS)
    err = np.abs(refocused_bg - true_bg_at_ref)
    wx_fg_ref = cam_positions[0] + REF_PIXELS * Z_FG / F
    occluded = is_occluder(wx_fg_ref)
    print(f"{n_cams} views, focus on background: error on occluded px = {err[occluded].mean():.2f}")
```

Output:

```text
1 views, focus on background: error on occluded px = 104.69
9 views, focus on background: error on occluded px = 18.74
33 views, focus on background: error on occluded px = 10.80
```

### 2. OpenCV: converting a refocused result into a displayable image

```python
import cv2

refocused_fg = refocus(cam_positions, observed, Z_FG, REF_PIXELS)
display_8bit = cv2.convertScaleAbs(refocused_fg.astype(np.float32))
print("refocused result dtype before:", refocused_fg.dtype, " after cv2.convertScaleAbs:", display_8bit.dtype)
print("sample values:", np.round(refocused_fg[:5], 1), "->", display_8bit[:5].ravel())
```

## OpenCV API notes

- **No `cv2` function performs light-field refocusing** — the whole real method (Code section 1) is NumPy shift-and-average, reusing 44.3's own disparity formula per candidate depth.
- **`cv2.convertScaleAbs(src, alpha=1, beta=0)`** (Code section 2) is the real, standard way to turn a float-valued computed result (any negative values become their absolute value, then everything clips to `[0, 255]` as `uint8`) into a normal displayable image — the last real step after any from-scratch NumPy pipeline in this course.
- **A real microlens-array light-field camera (Lytro, Ng et al. 2005) captures all of this chapter's "many views" in a single exposure**, trading sensor resolution for the ability to refocus and shift viewpoint entirely in software afterward — the real reason this chapter's camera-array simulation generalizes directly to that single-shot hardware.

## Where it fails

- **Dense occlusion (not sparse) defeats this method, not just slows it down** — this chapter's real test used 7.7% coverage; much denser clutter leaves too few unblocked viewpoints for any real number of views to recover the background cleanly (a real, structural limit, not solved by adding more cameras, similar in spirit to 44.3 Section 5's textureless-region exception).
- **The synthetic aperture (camera spread) must be wide enough relative to the occluder's own size and depth separation** — too narrow a spread (cameras too close together) barely changes viewpoint at all, and recovers little more than a single camera would.
- **This chapter assumed exact, known depths for both layers** — a real scene needs its own depth estimate first (44.3's own plane-sweep, or a dedicated light-field depth algorithm) before refocusing can target the right real depth at all.
- **Moving scene content between captured views breaks the model entirely** — like every method in this course relying on multiple views of the same static scene, any real motion during capture invalidates the whole shift-and-average assumption.

## ⚠️ Common mistakes

<Callout kind="mistake">

- **Expecting a single photo, processed afterward, to reveal information a light field's many viewpoints would have captured** — Mini exercise's own real point: there is a hard, physical difference between softening existing pixels and actually seeing around an occluder.
- **Assuming more views always help the same amount** — Section 3 and Section 4's own real, different improvement curves (10x vs 6x, starting from very different error levels) show the real benefit depends heavily on which depth is being focused on and why.
- **Confusing synthetic-aperture refocusing with simple image blurring** — the real method (Code section 1) explicitly uses each view's own real, different vantage point; a single blurred image has no such extra information to draw on.
- **Forgetting that a too-narrow camera/microlens spread limits how much occlusion can be seen through** — the real, physical aperture width of a light-field camera directly bounds this chapter's own real recovery performance.

</Callout>

### The two-plane light field parameterization

Levoy and Hanrahan ("Light Field Rendering," SIGGRAPH 1996) formalized a light field as a 4-D function `L(u, v, s, t)` — two coordinates `(u, v)` for which ray, and two more `(s, t)` for where that ray starts — of which this chapter's 1-D camera array and pixel index are a simplified, one-dimensional slice.

### Synthetic aperture confocal imaging

Vaish, Garg, Talvala, Antunez, Wilburn, Horowitz, Levoy, "Synthetic Aperture Focusing Using a Shear-Warp Factorization of the Viewing Transform" (CVPR Workshop, 2005) is the real, foundational application behind Section 3's own occlusion-removal result, used in real research for seeing through foliage, crowds, and other dense real-world clutter with a real camera array.
