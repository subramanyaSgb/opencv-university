# 42.4 Structured light

<Definition term="Structured light">projecting a known, actively-controlled pattern onto a scene, so that even a completely featureless surface gets real, identifiable "texture" — solving 42.3's exact failure case by supplying the texture itself instead of hoping the scene already has enough.</Definition>

42.1 named structured light as the real alternative to passive stereo; 42.3 measured exactly why passive stereo needs it: block matching found no confident match without real scene texture. This chapter builds and tests the real fix.

## 1. An analogy

Passive stereo is like trying to find your place on an unmarked, featureless wall by comparing two photos of it — impossible, nothing to match. Structured light is like projecting a unique, readable number onto every point of that same wall first, then reading the number back — suddenly there is something to match, because you put it there yourself.

## 2. Gray code: a real, exact binary address for every point

Seven binary patterns can uniquely identify any of `2⁷ = 128` projector columns — each pattern is simply "half the columns are bright, half are dark," arranged so that every column's 7-bit sequence is unique. Gray code [1] specifically arranges the bit sequence so that *adjacent* columns differ by only one bit, reducing real decoding errors right at a stripe's edge. Tested directly: a real encode-then-decode round trip on all 128 columns, with zero added noise, produced **zero decoding errors**.

## 3. A real, measured noise tolerance

<StructuredLightLab caption="A real, live Gray-code decode for a chosen column and noise level, plus the real measured error-rate curve across a range of real noise levels."/>

Each bit's decode is a simple threshold: brighter than half-scale (127) means `1`, darker means `0`. Testing this directly against real, added sensor noise, 500 random trials per noise level:

| Noise (std) | Decode error rate |
| --- | --- |
| 10 | 0.0% |
| 20 | 0.0% |
| 40 | 0.4% |
| 60 | 8.6% |
| 80 | 30.8% |
| 100 | 51.6% |
| 150 | 74.4% |

Decoding is **exact** (0% error) up to a real, substantial noise level — std 20, about 8% of the full 0–255 intensity range — then degrades, slowly at first, then sharply past std 60. A simple binary decision per bit is genuinely far more robust to real noise than the fine-grained, sub-pixel matching 42.3's block matching needed.

## 4. Why this fixes 42.3's exact failure case

42.3 measured `cv2.StereoBM` rejecting most matches on a synthetic texture because real block-matching needs enough local *contrast variation* to tell candidate shifts apart confidently. Structured light sidesteps that requirement entirely: the pattern itself provides the contrast, actively, regardless of what the real surface underneath actually looks like — a flat, uniformly-painted part gets exactly the same real, decodable Gray code as a richly textured one, because the "texture" never came from the surface at all.

## 5. Industrial context: what structured light costs for that robustness

A structured-light system needs a real, controllable projector, precisely synchronised with the camera, and (for this chapter's binary-code method) several sequential frames per measurement — real requirements passive stereo (42.1–42.3) does not have, since passive stereo uses only ambient light and a single simultaneous frame pair. Structured light earns its real cost specifically where 42.3's passive approach fails: smooth, uniformly-coloured, or low-contrast real parts, common in many industrial inspection settings (unpainted metal, moulded plastic) where natural texture genuinely cannot be relied on.

## Code

### 1. NumPy: real Gray code, from scratch

```python
import numpy as np

def to_gray_code(n, bits):
    g = n ^ (n >> 1)
    return [(g >> (bits - 1 - b)) & 1 for b in range(bits)]

def from_gray_code(bits_list):
    g = 0
    for b in bits_list:
        g = (g << 1) | b
    n, shift = g, 1
    while shift < len(bits_list):
        n ^= (n >> shift)
        shift <<= 1
    return n

BITS = 7
errors = sum(1 for col in range(128) if from_gray_code(to_gray_code(col, BITS)) != col)
print("columns tested: 128, decode errors (no noise):", errors)
print("column 50's real 7-bit code:", to_gray_code(50, BITS))
```

Output:

```text
columns tested: 128, decode errors (no noise): 0
column 50's real 7-bit code: [0, 1, 0, 1, 0, 1, 1]
```

### 2. The real noise-robustness test

```python
rng = np.random.default_rng(3)
pattern_bits = np.array([to_gray_code(c, BITS) for c in range(128)])

def decode_with_noise(col, noise_std):
    bits = []
    for b in range(BITS):
        intensity = 255.0 if pattern_bits[col, b] else 0.0
        noisy = intensity + rng.normal(0, noise_std)
        bits.append(1 if noisy > 127 else 0)
    return from_gray_code(bits)

for noise_std in (20, 60, 100):
    errors, trials = 0, 500
    for _ in range(trials):
        col = rng.integers(0, 128)
        if decode_with_noise(col, noise_std) != col:
            errors += 1
    print(f"noise_std={noise_std}: error rate {100*errors/trials:.1f}%")
```

Typical output (one machine, matching this chapter's own real precomputed data):

```text

noise_std=60: error rate 8.6%
noise_std=100: error rate 51.6%
```

### 3. The real cv2.structured_light module: one real surprise

```python
# Needs opencv-contrib (cv2.structured_light)
import cv2

gc = cv2.structured_light.GrayCodePattern_create(128, 1)
print("real numPatternImages for 128 columns:", gc.getNumberOfPatternImages())
ok, patterns = gc.generate()
print("generate() returned:", ok, "with", len(patterns), "images")
```

Output:

```text
real numPatternImages for 128 columns: 14
generate() returned: True with 14 images
```

OpenCV's real implementation uses **14** patterns for 128 columns, not this chapter's simplified 7 — it pairs every bit's pattern with its photometric *inverse*, and decodes each bit by comparing the two directly (which pixel is brighter) rather than against a fixed threshold like Section 3's `127`. This real refinement makes decoding robust to the scene's own overall brightness and reflectivity, something a fixed threshold cannot do — a genuine, real improvement over this chapter's own simplified teaching version, not an arbitrary implementation detail.

## OpenCV API notes

- **`cv2.structured_light.GrayCodePattern_create(width, height)`** (contrib): the real, ready-made Gray-code pattern generator; `.generate()` returns the real pattern images (14 for this chapter's 128-column example, Code section 3) — this chapter built the simpler, single-threshold version from scratch (Code sections 1-2) to show the core idea clearly, then checked it against the real library's own, more robust approach.
- **A real system also needs real camera-projector calibration** — essentially 41.8's stereo calibration, treating the projector as a second "camera" whose own intrinsics and relative pose to the real camera must be known before a decoded column can become a real depth, the same `Z = f.B/d`-style triangulation as 42.1.
- **Sinusoidal (phase-shift) patterns** are a real, different structured-light encoding from binary Gray code, trading the robust-but-coarse binary approach for finer, continuous phase information at a different real noise-sensitivity profile.

## Where it fails

- **A real reflective or very dark surface** can distort or absorb the projected pattern itself, well before sensor noise becomes the limiting factor — Section 3's noise-robustness curve assumes the pattern itself reaches the sensor reliably.
- **Ambient light competing with the projector** effectively adds real noise/bias to every decoded bit — a bright, sunlit outdoor scene can overwhelm a typical structured-light projector's real intensity range.
- **Multiple sequential patterns need a genuinely static scene** between frames (for this chapter's binary-code method) — a moving part blurs or misaligns the pattern sequence, corrupting the real decode.

## ⚠️ Common mistakes

<Callout kind="mistake">

- **Assuming structured light is immune to noise** — Section 3's own real measurement shows a genuine, if generous, noise tolerance limit, not infinite robustness.
- **Using plain binary (not Gray) coding** — a 1-bit error right at a stripe boundary in plain binary can flip the decoded value by up to half the whole range; Gray code's adjacent-columns-differ-by-one-bit property (Section 2) limits a single bit error to a small, real decoding error instead.
- **Forgetting that structured light needs real camera-projector calibration** (OpenCV API notes) — a decoded column alone is not yet a depth; it still needs the real triangulation geometry 42.1 introduced.
- **Deploying a sequential-pattern system on a moving part** without accounting for Where it fails' real static-scene requirement.
- **Assuming a fixed brightness threshold (like Section 3's `127`) is what real systems use** — the real `cv2.structured_light` module instead pairs each pattern with its own inverse and compares the two directly (Code section 3), avoiding the real problem of a fixed threshold failing on an unexpectedly dark or bright scene.

</Callout>

## 🔍 Go deeper

<GoDeeper>

### Why Gray code specifically, not plain binary

In plain binary, adjacent values (e.g. 63 = 0111111, 64 = 1000000) can differ in *every* bit — a single bit misread right at that boundary can produce a wildly wrong decoded value. Gray code is constructed specifically so adjacent values always differ in exactly one bit [1][2] — the same single-bit misread at a boundary now produces a decoded value off by at most one, a vastly smaller real error.

### Single-shot structured light

This chapter's binary-code method needs several sequential patterns, which assumes a static scene. Real single-shot methods (one pattern, decoded from local pattern structure rather than a temporal sequence) exist specifically for moving scenes or real-time use, trading some of this chapter's own noise robustness and resolution for the ability to work from just one captured frame.

</GoDeeper>
