## 3. Why can't the camera simply capture everything?

Imagine removing the lens. You have a box with a sensor inside and an open front. Light from **everywhere** would enter the camera, and every point of the sensor would receive light from every point of the scene:

<OpenSensor caption="Red rays from the top of the object and blue rays from the bottom land on every sensor point. Each point gets the same mixture, so no picture forms." />

The sensor would receive a **confusing mixture of light**. We need a way to control **where each ray of light goes**. That's where the camera's **optical system** comes in.

## 4. The simplest possible camera: pinhole camera

Before lenses existed, we can imagine a very simple camera. Take a box, put a sensor on the back wall, and make a **tiny hole** on the front side:

<PinholeDiagram object={false} f={9} caption="A closed box, a sensor on the back wall, and one tiny hole in the front." />

This is called a **pinhole camera**.

## 5. Why does the tiny hole work?

Imagine an object outside. Light travels **approximately in straight lines**. Some rays from the object enter the tiny hole. Because the hole is tiny, **only a small set of rays can pass through**, and the rays **cross at the hole**:

<PinholeDiagram caption="Only the ray from the top that passes through the hole reaches the sensor (red), and likewise for the bottom (blue). They cross at the hole, so the image is inverted." />

As a result, the image formed on the sensor is **inverted**. So one of the most important things to understand is:

<Callout kind="key">

A camera forms an image because **light rays from different points in the scene are directed to corresponding locations on the sensor**.

</Callout>

## 6. Why is the image upside down?

Let's make it even simpler. Look at one object with a **top** (red) and a **base** (blue) in the diagram above:

- Light from the **top** travels down through the pinhole and ends up at the **bottom** of the sensor.
- Light from the **base** travels up through the pinhole and ends up at the **top** of the sensor.

Therefore the image is **inverted**. The same happens left to right, so the image on the sensor is the scene turned through 180°:

## 7. The pinhole is like a traffic gate

Here's a simple analogy. Imagine thousands of cars coming toward a road. If there is a **huge opening**, cars can go everywhere. But if there is a **tiny gate**, only a restricted set of paths can pass:

<GateSketch caption="Through the tiny gate each car has one path. The pinhole does the same for light: each scene point gets one path to the sensor." />

The pinhole does something similar with light.

## 10. Perspective projection

Now we reach an extremely important concept. Suppose you have two objects that are **physically the same size**, but one is **farther away**. The farther object **appears smaller**. Why? Because of **perspective projection**.

## 11. Simple example

Imagine two identical rods, **rod A** and **rod B**. One is close; the other is far:

<PerspectiveSketch caption="Same physical size. The far rod fills a narrower angle at the camera, so it covers fewer pixels." />

Same physical size. **Different apparent size** in the image. Therefore:

<Callout kind="key">

The size of an object **in pixels** depends not only on its physical size, but also on its **distance from the camera** and the **camera's optics**.

</Callout>

This will become extremely important when we learn mm per pixel (Chapter 2.4).

## 22. Perspective in a simple formula

Eventually we'll study the pinhole camera mathematically. A simplified relationship is:

```text
x = f · X / Z
y = f · Y / Z
```

Don't worry if this looks scary. Let's translate it into English:

<Glossary
  items={[
    { term: "X, Y", desc: "The object's position (sideways and up), measured from the camera's axis.", example: "X = 2" },
    { term: "Z", desc: "Distance from the camera.", example: "Z = 5" },
    { term: "f", desc: "Focal length: the distance from the pinhole to the image plane.", example: "f = 10" },
    { term: "x, y", desc: "Where the point lands in the image.", example: "x = 4" },
  ]}
/>

The important part is that **x is proportional to X / Z** (and y to Y / Z). Meaning:

<Callout kind="key">

As distance **Z increases**, the projected object becomes **smaller**.

</Callout>

### 1. From scratch: x = f · X / Z

```python
import numpy as np

f = 10.0     # pinhole to image plane
X = 2.0      # object height
for Z in [5.0, 10.0, 20.0]:
    x = f * X / Z
    print(f"Z = {Z:4.0f}  ->  x = {x:.1f}")
```

Output:

```text
Z =    5  ->  x = 4.0
Z =   10  ->  x = 2.0
Z =   20  ->  x = 1.0
```

Every doubling of the distance halves the image size, exactly as in section 23.

### 2. OpenCV: project a billet with the pinhole model

OpenCV's camera model *is* the pinhole model. `cv2.projectPoints` takes 3-D points (in metres, say) and returns where they land in the image (in pixels).

```python
import numpy as np
import cv2

fx = fy = 1400.0           # focal length in pixels
cx, cy = 960.0, 540.0      # image centre of a 1920 x 1080 image
K = np.array([[fx, 0, cx],
              [0, fy, cy],
              [0,  0,  1]], dtype=np.float64)
rvec = np.zeros(3)          # camera not rotated
tvec = np.zeros(3)          # camera at the origin
dist = None                 # no lens distortion (ideal pinhole)

for Z in [3.0, 6.0]:
    # the two ends of a 1.2 m billet, centred in front of the camera, Z metres away
    ends = np.array([[-0.6, 0.0, Z],
                     [ 0.6, 0.0, Z]], dtype=np.float64)
    pts, _ = cv2.projectPoints(ends, rvec, tvec, K, dist)
    u = pts[:, 0, 0]
    print(f"Z = {Z} m: ends at u = {u.round(1)}, length = {u[1] - u[0]:.1f} px")
print(pts.shape, pts.dtype)
```

Output:

```text
Z = 3.0 m: ends at u = [ 680. 1240.], length = 560.0 px
Z = 6.0 m: ends at u = [ 820. 1100.], length = 280.0 px
(2, 1, 2) float64
```

- `K` is the **camera matrix**. `fx`, `fy` are the focal length expressed **in pixels**; `cx`, `cy` is where the optical axis meets the image (here the centre).
- `rvec`, `tvec` place the camera in the world. Zeros mean the camera sits at the origin looking along +Z.
- `dist = None` means no lens distortion: a perfect pinhole. Real lenses need distortion coefficients (Module 41).
- Check by hand: 1400 × 1.2 / 3 = 560 px, and 1400 × 1.2 / 6 = 280 px. Same billet, twice as far, half the pixels (Q6).
- The result has shape (N, 1, 2): one (u, v) pair per point.

### 3. The hole-size trade-off (simulation)

A pinhole of diameter *d* turns every scene point into a small disk about *d* wide, and collects light in proportion to the hole's area. We simulate both effects on the test scene from section 6.

```python
import numpy as np
import cv2

scene = cv2.imread("sample-pinhole-scene.png", cv2.IMREAD_GRAYSCALE)

def through_pinhole(scene, d, d_ref=11):
    # geometric blur: each scene point spreads into a disk d pixels wide
    k = np.zeros((d, d), np.float32)
    cv2.circle(k, (d // 2, d // 2), d // 2, 1.0, -1)
    k /= k.sum()
    img = cv2.filter2D(scene.astype(np.float32), -1, k)
    img *= (d / d_ref) ** 2               # light collected ~ hole area
    return np.clip(np.rint(img), 0, 255).astype(np.uint8)

fine = (slice(40, 90), slice(230, 245))   # the thinnest bars (3 px wide)
for d in [1, 5, 11]:
    img = through_pinhole(scene, d)
    hi, lo = int(img[fine].max()), int(img[fine].min())
    contrast = (hi - lo) / (hi + lo)       # 1.0 = bars fully separated, 0 = washed out
    print(f"hole {d:2d} px: mean brightness {img.mean():5.1f}, thin-bar contrast {contrast:.2f}")
```

Output:

```text
hole  1 px: mean brightness   0.4, thin-bar contrast 1.00
hole  5 px: mean brightness  12.9, thin-bar contrast 0.55
hole 11 px: mean brightness  63.2, thin-bar contrast 0.22
```

- The 1-pixel hole keeps the bars perfectly separate but is almost black: the bars are only value 2 on a background of 0. That is section 8's problem.
- The 11-pixel hole is bright, but the thin bars are almost washed out.
- `cv2.filter2D` with a normalized disk is the blur; multiplying by (d / d_ref)² is the light. This ignores diffraction, which makes very small holes blur *more* (Chapter 2.3).

### 4. The inverted image, and turning it back

```python
import numpy as np
import cv2

scene = np.array([[ 10,  20,  30],
                  [ 40,  50,  60],
                  [ 70,  80, 200]], dtype=np.uint8)

on_sensor = scene[::-1, ::-1]           # NumPy: reverse rows and columns
print(on_sensor)

upright = cv2.flip(on_sensor, -1)        # OpenCV: flip both axes back
print(np.array_equal(upright, scene))
print(np.array_equal(on_sensor, cv2.flip(scene, -1)))
print(cv2.flip(scene, 0))
```

Output:

```text
[[200  80  70]
 [ 60  50  40]
 [ 30  20  10]]
True
True
[[ 70  80 200]
 [ 40  50  60]
 [ 10  20  30]]
```

- The pinhole image is the scene turned through 180°: row order **and** column order reversed. The bright 200 moves from bottom-right to top-left.
- `cv2.flip(img, -1)` flips both axes and undoes it. `flipCode = 0` flips only up–down (the last print), and `1` only left–right.
- You do **not** normally do this yourself: the camera's readout and processing already deliver an upright image.

## OpenCV API notes

**`cv2.projectPoints(objectPoints, rvec, tvec, cameraMatrix, distCoeffs) → imagePoints, jacobian`**

- `objectPoints`: N × 3 float32 or float64 array of 3-D points.
- `rvec`, `tvec`: rotation (Rodrigues vector) and translation from the world to the camera frame; 3 elements each.
- `cameraMatrix`: 3 × 3 matrix `[[fx, 0, cx], [0, fy, cy], [0, 0, 1]]`, all in **pixels**.
- `distCoeffs`: lens distortion coefficients; `None` (or zeros) gives an ideal pinhole.
- Returns `imagePoints` with shape (N, 1, 2) and the same float type, plus a Jacobian (used in calibration; ignore it for now).
- Points must be in front of the camera (Z > 0) for the result to mean anything.

**`cv2.flip(src, flipCode) → dst`**

- `flipCode = 0`: flip around the x-axis (up–down). `> 0`: around the y-axis (left–right). `< 0`: both (a 180° turn).
- Works on any number of channels and dtypes; output has the same size and type.

**Focal length in pixels.** `fx` = focal length (mm) ÷ pixel pitch (mm). A 16 mm lens on a sensor with 3.45 µm pixels gives fx ≈ 16 / 0.00345 ≈ 4638 px. In practice you get `fx`, `fy`, `cx`, `cy` from calibration (Module 41).

## Where it fails

- **Lens effects.** The pinhole model has no focus, no depth of field, no distortion. Real lenses bend straight lines near the edges and blur objects outside the focused distance (Chapters 2.2, 2.3; calibration in Module 41).
- **Telecentric lenses.** These are built so that, within their working range, image size does **not** change with distance. x = f·X/Z does not apply; use an orthographic model instead. They are common in precision gauging.
- **Very small pinholes.** The geometric model says smaller is sharper forever. In reality diffraction makes tiny holes blurrier again (Chapter 2.3).
- **Objects with depth.** A billet that is tilted, or a pile of rods at different distances, has a different mm per pixel at each point. One scale for the whole image is wrong.
- **Brightness.** The model says where light lands, not how bright the pixel will be. That depends on exposure, the sensor and processing (Chapters 2.5, 2.6, 2.8).

## ⚠️ Common mistakes

<Callout kind="mistake">

- **Treating pixels as millimetres.** 1000 px is not 1000 mm. You need distance, optics and calibration.
- **Mixing units in x = f·X/Z.** X and Z must share a unit (both metres or both mm). Use f in pixels to get x in pixels.
- **Measuring Z from the camera's front face.** Z is measured from the camera centre (the pinhole, or roughly the lens), not from the housing.
- **Changing the working distance after calibration.** Move the camera or the conveyor height and every mm-per-pixel value changes.
- **Flipping images "because the sensor image is inverted".** Cameras already deliver upright images. Flip only if your mounting really turns the camera.
- **Passing integer or wrongly shaped arrays to `projectPoints`.** Use float32 or float64, shape N × 3.

</Callout>

## 🔍 Go deeper

<GoDeeper>

### Similar triangles

Put the pinhole at the origin and the image plane a distance f behind it. A point at height X and distance Z sends a ray through the origin. The triangle in front (height X, length Z) and the one behind (height x, length f) have the same angles, so x / f = X / Z, which gives x = f·X/Z. The minus sign of the inversion is usually dropped by placing a **virtual image plane** at distance f *in front of* the centre: same size, upright. Hartley and Zisserman use this convention [3].

### The camera matrix

In homogeneous coordinates the projection becomes a matrix product. With focal lengths in pixels (fx, fy) and principal point (cx, cy), a point (X, Y, Z) maps to u = fx·X/Z + cx and v = fy·Y/Z + cy. That is exactly what `projectPoints` computed in the Code section: 1400 × (−0.6)/3 + 960 = 680. The 3 × 3 matrix K holds these intrinsic parameters; rvec and tvec are the extrinsic ones [3][5].

### Why a pinhole has a best size

Geometrically, the blur spot shrinks with the hole. Optically, light spreads after passing a small opening (diffraction), and that spread grows as the hole shrinks. The sharpest pinhole is where the two balance. Chapter 2.3 treats diffraction properly.

### Light is the signal

Each sensor element collects light for the exposure time and turns it into charge, then a voltage, then a number. The pixel value is therefore a measurement with noise and a limited range, not just a colour. Chapter 2.5 and the EMVA 1288 standard describe how to characterize it.

</GoDeeper>

### Exercise 1 (by hand)

A pinhole camera has f = 10. An object is X = 3 tall. (a) What is its image height at Z = 6? (b) At Z = 12? (c) At what distance would the image be 10 tall?

<Solution>

(a) x = 10 × 3 / 6 = **5**.

(b) x = 10 × 3 / 12 = **2.5**: twice the distance, half the size.

(c) 10 = 10 × 3 / Z, so Z = **3**.

</Solution>

### Exercise 2 (coding)

With the camera from Code example 2 (fx = 1400 px), at what distance does a 1.2 m billet span exactly 700 pixels? Work it out with x = f·X/Z, then confirm with `cv2.projectPoints`.

<Solution>

Rearranging: Z = fx × L / x = 1400 × 1.2 / 700 = 2.4 m.

```python
import numpy as np
import cv2

fx, L, target = 1400.0, 1.2, 700.0
Z = fx * L / target

K = np.array([[fx, 0, 960.0], [0, fx, 540.0], [0, 0, 1]], dtype=np.float64)
ends = np.array([[-L / 2, 0.0, Z], [L / 2, 0.0, Z]], dtype=np.float64)
pts, _ = cv2.projectPoints(ends, np.zeros(3), np.zeros(3), K, None)
print(f"Z = {Z:.1f} m, length = {pts[1, 0, 0] - pts[0, 0, 0]:.1f} px")
```

Output:

```text
Z = 2.4 m, length = 700.0 px
```

</Solution>

### Exercise 3 (by hand)

A pinhole camera looks at a distant scene. You **double the hole diameter**. (a) How much more light reaches the sensor? (b) Roughly how does the blur spot change? (c) What would you do instead to get both more light and a sharp image?

<Solution>

(a) Light follows the hole's **area**, which goes with the diameter squared: **4×** as much light.

(b) For a distant scene the blur spot is about as wide as the hole, so it roughly **doubles**.

(c) Use a **lens**: it collects light through a large opening and still focuses each scene point to a small spot (Chapter 2.2).

</Solution>
