# 1.2 Pixels and the image grid

<Definition term="Image grid">the arrangement of an image's pixels into rows and columns, so every pixel has an address.</Definition>

In 1.1, we learned the most important idea: **an image is basically a collection of numbers called pixels.**

Now we're going to understand where those pixels live, how they are arranged, and how a computer finds a specific pixel.

This is extremely important because later you'll write things like `image[100, 200]`, and you need to understand exactly what `100, 200` means.

## 7. Why (row, column)?

This is very important for Python and OpenCV. When you write `image[row, column]`, you are saying: *"Give me the pixel at this row and this column."*

For example, `image[2, 1]` means **row = 2, column = 1**. Looking at our image:

<IndexedGrid values={[[10, 50, 100], [20, 80, 150], [30, 120, 200]]} show="both" highlight={[[2, 1]]} />

Therefore `image[2, 1]` gives **120**.

## Code

We now write the indexing ideas as real code. To make rows and columns easy to tell apart, the first image has 3 rows and **4** columns.

### 1. Shape, rows, columns, pixels

```python
import numpy as np

image = np.array([[10,  20,  30, 250],
                  [50,  60,  70,  80],
                  [90, 100, 110, 120]], dtype=np.uint8)

print(image.shape)
print(image.shape[0], "rows (height)")
print(image.shape[1], "columns (width)")
print(image.size, "pixels")
```

Output:

```text
(3, 4)
3 rows (height)
4 columns (width)
12 pixels
```

- `dtype=np.uint8` makes this a real 8-bit image, the same type `cv2.imread` returns.
- `image.shape` is always rows first: `(height, width)`.
- `image.size` is the total number of values: 3 × 4 = 12.

### 2. From scratch: find the brightest pixel with a loop

```python
best_value, best_row, best_col = -1, -1, -1
rows, cols = image.shape
for r in range(rows):            # every row (y) …
    for c in range(cols):        # … and every column (x) in that row
        if image[r, c] > best_value:
            best_value, best_row, best_col = image[r, c], r, c

print("brightest:", best_value, "at row", best_row, "column", best_col)
```

Output:

```text
brightest: 250 at row 0 column 3
```

The loop visits pixels row by row, left to right: the same order the pixels are stored in memory.

### 3. The same with NumPy

```python
r, c = np.unravel_index(np.argmax(image), image.shape)
print(r, c, image[r, c])
```

Output:

```text
0 3 250
```

- `np.argmax(image)` returns the position of the largest value as if the grid were one long row (here 3).
- `np.unravel_index(..., image.shape)` turns that position back into `(row, column)`.

### 4. The OpenCV way, and the (x, y) trap

```python
import cv2

min_val, max_val, min_loc, max_loc = cv2.minMaxLoc(image)
print(max_val, max_loc)
```

Output:

```text
250.0 (3, 0)
```

The same pixel, but OpenCV reports its location as **(x, y) = (3, 0)**: column first. NumPy said row 0, column 3. Both are right; they use different orders.

- `cv2.minMaxLoc(src)` returns the smallest value, the largest value, and their locations. It works on single-channel images.
- Location results and drawing points in OpenCV are **(x, y)**. NumPy indexing is **[y, x]**. To read the pixel back: `image[max_loc[1], max_loc[0]]`.

### 5. Corners, ROI and drawing on a real image

Download [sample-scene.png](/images/sample-scene.png) into the folder you run Python from.

```python
import cv2

img = cv2.imread("sample-scene.png", cv2.IMREAD_GRAYSCALE)
if img is None:
    raise FileNotFoundError("Could not read sample-scene.png. Check the path.")

h, w = img.shape
print("height:", h, "width:", w)
print("top-left:", img[0, 0], "bottom-right:", img[h - 1, w - 1])

x1, y1, x2, y2 = 35, 55, 126, 146        # a box around the bright disc
roi = img[y1:y2, x1:x2]                  # NumPy: rows (y) first, then columns (x)
print("roi shape:", roi.shape)
print("roi mean:", round(float(roi.mean()), 1), "image mean:", round(float(img.mean()), 1))

marked = cv2.cvtColor(img, cv2.COLOR_GRAY2BGR)
cv2.rectangle(marked, (x1, y1), (x2 - 1, y2 - 1), (0, 0, 255), 2)   # OpenCV points: (x, y)
cv2.imwrite("roi-marked.png", marked)
```

Output:

```text
height: 200 width: 320
top-left: 40 bottom-right: 200
roi shape: (91, 91)
roi mean: 206.2 image mean: 120.3
```

![The sample scene with a red box around the bright disc](/images/sample-scene-roi.png)

- The last pixel is `img[h - 1, w - 1]`: index 199, 319 for a 200 × 320 image.
- `img[y1:y2, x1:x2]` keeps rows 55 to 145 and columns 35 to 125. The end of a slice is not included.
- The ROI's mean (206.2) is much higher than the whole image's (120.3): the ROI holds mostly the bright disc.
- `cv2.rectangle(image, pt1, pt2, color, thickness)` takes two corner points as **(x, y)**. Its corners are inclusive, so the box that matches the slice ends at `(x2 - 1, y2 - 1)`.
- `(0, 0, 255)` is red, because OpenCV colour order is B, G, R.

## OpenCV API notes

Versions: OpenCV 4.13.0 (`opencv-python==4.13.0.92`), NumPy 2.5.3. OpenCV signatures are copied from the installed library's help text.

| Tool | Form | Gives |
|---|---|---|
| `image.shape` | NumPy attribute | `(rows, cols)` or `(rows, cols, channels)` |
| `image.size` | NumPy attribute | total number of values (rows × cols × channels) |
| `image[r, c]` | NumPy index | one value (gray) or a length-3 array (colour) |
| `image[r0:r1, c0:c1]` | NumPy slice | a region, rows `r0` to `r1 - 1`, columns `c0` to `c1 - 1` |
| `cv2.minMaxLoc` | `minMaxLoc(src[, mask]) -> minVal, maxVal, minLoc, maxLoc` | values and **(x, y)** locations |
| `cv2.rectangle` | `rectangle(img, pt1, pt2, color[, thickness[, lineType[, shift]]]) -> img` | draws in place; points are **(x, y)** |

**Order cheat sheet.**

- Anything NumPy (`shape`, indexing, slicing): **rows first**, `[y, x]`.
- OpenCV points, locations and sizes such as `minMaxLoc` results and `rectangle` corners: **x first**, `(x, y)`.
- People and camera datasheets: **width × height**, e.g. 1920 × 1080.

**Inputs and types.**

- `cv2.imread` returns rows × columns (× 3 for colour, in **B, G, R** order) of type `uint8`.
- Indexing a colour image with two numbers, `image[r, c]`, returns all three channel values at that pixel.
- `cv2.minMaxLoc` needs a single-channel image. For a colour image, split or convert it first.

**Speed.**

- A slice such as `img[y1:y2, x1:x2]` is a **view**: no pixels are copied, so taking an ROI costs almost nothing.
- Processing an ROI instead of the whole frame reduces work roughly in proportion to its pixel count.

## Where it fails

- **Pixel coordinates are not real-world positions.** `[100, 200]` says where a pixel is in the image, not where the object is on the shop floor. Turning pixels into millimetres needs calibration. *Instead:* 2.4 (mm per pixel) and 41.6 (pixel to mm).
- **A pixel is the smallest step on the grid.** Indices are whole numbers, so a plain index cannot say "this edge is at column 120.4". *Instead:* sub-pixel methods (22.5, 49.2).
- **A fixed ROI assumes the object stays put.** If the billet moves or the camera is knocked, the ROI looks at the wrong place. *Instead:* find the object first (detection or tracking, Parts F, G and J), then place the ROI around it.
- **More megapixels do not guarantee more detail.** Lens sharpness, focus, motion and lighting can blur away what extra pixels would show. *Instead:* choose camera and lens together (Module 2, 59.1, 59.2).

## ⚠️ Common mistakes

**1. Swapping x and y.** `image[x, y]` silently reads the wrong pixel when the image is not square, and fails with an `IndexError` near the right edge. Always write `image[y, x]`, or better, name them `image[row, col]`.

**2. Mixing NumPy and OpenCV order.** `cv2.minMaxLoc` gave `(3, 0)` for the pixel NumPy calls `[0, 3]`. Convert explicitly: `x, y = loc` then `image[y, x]`.

**3. Writing size the wrong way round.** A 1920 × 1080 camera gives `shape == (1080, 1920)`. Code like `width, height = image.shape` swaps them. Use `height, width = image.shape[:2]`.

**4. Off-by-one at the edge.** The last pixel is `image[h - 1, w - 1]`. `image[h, w]` raises:

```text
IndexError: index 3 is out of bounds for axis 0 with size 3
```

**5. Negative indices do not fail.** `image[-1, -1]` does **not** raise an error: Python counts from the end, so it returns the bottom-right pixel. A bug that produces a negative index reads the wrong pixel silently.

**6. Slices past the edge do not fail either.** On a 3 × 3 image, `image[0:10, 0:10]` simply returns the 3 × 3 image. An ROI that hangs off the edge comes back smaller than you asked for, without warning. Check `roi.shape`.

**7. Forgetting that an ROI is a view.** `roi = image[0:2, 0:2]` shares pixels with `image`. Writing `roi[:] = 0` changes the original image too. Use `roi = image[0:2, 0:2].copy()` when you need an independent copy.

## 🔍 Go deeper

<GoDeeper>

### Different books, different letters

The image grid is always the same: origin at the top-left, rows going down, columns going right. The letters used for the two directions are not.

- NumPy and OpenCV's Python API index `[row, column]`; OpenCV's points use (x, y) with x along the columns.
- Gonzalez and Woods write a digital image as an M × N array f(x, y) with the origin at the top-left, and use x for the row direction and y for the column direction [1, Sec. 2.4]. That is the opposite letter choice to OpenCV's points.

When you read a formula, first check which letter runs down the rows. Getting this wrong transposes the result.

### How the grid sits in memory

NumPy stores an image row by row (C order). For a grayscale `uint8` image of width W, pixel (r, c) is at offset

```text
offset = r × W + c
```

and for a 3-channel image, channel k of pixel (r, c) is at

```text
offset = (r × W + c) × 3 + k
```

You can see this in `image.strides`. For the 200 × 320 sample scene, `strides` is `(320, 1)`: moving one row skips 320 bytes, moving one column skips 1 byte. For a 4 × 5 colour image it is `(15, 3, 1)`. This row-by-row layout is why looping over rows in the outer loop is the natural order.

### Neighbourhoods, formally

The neighbours in section 25 have names [1, Sec. 2.5]:

- **4-neighbours**, N₄(p): up, down, left, right.
- **Diagonal neighbours**, N_D(p): the four corners.
- **8-neighbours**, N₈(p) = N₄(p) ∪ N_D(p).

Which set you use changes whether two pixels count as "connected", and so changes object counts. Chapter 3.6 covers this.

### Megapixels and aspect ratio

1 MP is 10⁶ pixels. 1920 × 1080 has an aspect ratio of 16:9 (1920 / 1080 = 1.78). 2448 × 2048 is about 1.2 : 1, closer to square, which suits many inspection tasks where the part is roughly square.

### Integer pixels and real positions

An index addresses a whole pixel. Libraries differ on whether a pixel's integer coordinate means its centre or its corner, and this matters when resizing, rotating or measuring to fractions of a pixel. Check the documentation of each function you use for sub-pixel work (16.4, 49.2).

</GoDeeper>

### Exercise 2 (coding)

Create a black 640 × 480 grayscale image. Make the box with top-left corner x = 50, y = 30, 200 pixels wide and 100 pixels high, white, using **slicing**. Then draw the same filled box on a second black image with `cv2.rectangle` (thickness `-1` fills it). Print how many pixels are white, and check the two images are identical.

<Solution>

```python
import cv2
import numpy as np

a = np.zeros((480, 640), dtype=np.uint8)      # shape is (height, width)
a[30:130, 50:250] = 255                       # rows y 30..129, columns x 50..249

b = np.zeros((480, 640), dtype=np.uint8)
cv2.rectangle(b, (50, 30), (249, 129), 255, -1)   # (x, y) corners, inclusive

print("white pixels:", np.count_nonzero(a), "of", a.size)
print("identical:", np.array_equal(a, b))
```

Output:

```text
white pixels: 20000 of 307200
identical: True
```

200 × 100 = 20,000 white pixels. The slice end (130, 250) is exclusive; the rectangle's second corner (249, 129) is inclusive.

</Solution>

### Exercise 3 (coding)

Load `sample-scene.png` in grayscale. Find the brightest pixel twice: with `np.argmax` + `np.unravel_index`, and with `cv2.minMaxLoc`. Print both results and show they point to the same pixel.

<Solution>

```python
import cv2
import numpy as np

img = cv2.imread("sample-scene.png", cv2.IMREAD_GRAYSCALE)
if img is None:
    raise FileNotFoundError("Could not read sample-scene.png. Check the path.")

r, c = np.unravel_index(np.argmax(img), img.shape)
_, max_val, _, (x, y) = cv2.minMaxLoc(img)

print("numpy  [row, col]:", int(r), int(c))
```

```text
numpy  [row, col]: 56 72
opencv (x, y):    72 56
same pixel: True 255 255.0
```
