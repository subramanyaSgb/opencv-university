There is **no universal answer**. A professional computer vision engineer chooses based on the problem.

<Panel title="Deep learning may be better when" tone="b">

- Complex appearance
- Difficult backgrounds
- Many object types

- Enough training data is available

And many real systems use **both**.

## Code

The difference in one sentence: **image processing returns an image; computer vision returns information.** The code below shows exactly that.

### 1. From scratch: one image, two kinds of result

```python
import numpy as np

img = np.array([
    [10,  10,  10,  10,  10,  10],
    [10, 200, 210,  10,  10,  10],
    [10, 205, 220,  10,  10,  10],
    [10,  10,  10,  10, 190,  10],
    [10,  10,  10,  10,  10,  10]], dtype=np.uint8)

# Image processing: brighten. Image in, image out.
brighter = np.clip(img.astype(np.int16) + 40, 0, 255).astype(np.uint8)
print("image processing result:", type(brighter).__name__, brighter.shape)

# Computer vision: is there a bright object, and where?
mask = img > 128
rows, cols = np.nonzero(mask)
print("bright pixels:", int(mask.sum()))
print("rows", rows.min(), "to", rows.max(), "| columns", cols.min(), "to", cols.max())
```

Output:

```text
image processing result: ndarray (5, 6)
bright pixels: 5
rows 1 to 3 | columns 1 to 4
```

- The brighten step gives back an array of the same shape: a new image.
- The second part gives back **numbers**: how many bright pixels, and the rows and columns they span.
- But the box "rows 1 to 3, columns 1 to 4" is wrong for a person to read: there are really **two** objects, a 2 × 2 blob and a single pixel. Finding separate objects needs connectivity, which OpenCV does in one call.

### 2. The OpenCV way: count separate objects

```python
import cv2

_, binary = cv2.threshold(img, 128, 255, cv2.THRESH_BINARY)
n, labels, stats, centroids = cv2.connectedComponentsWithStats(binary, connectivity=8)

print("objects:", n - 1)                 # label 0 is the background
for i in range(1, n):
    x, y, w, h, area = stats[i]
    print(f"object {i}: x={x} y={y} w={w} h={h} area={area}")
```

Output:

```text
objects: 2
object 1: x=1 y=1 w=2 h=2 area=4
object 2: x=4 y=3 w=1 h=1 area=1
```

- `cv2.threshold(...)` is image processing: it returns another image (black and white).
- `cv2.connectedComponentsWithStats(binary, connectivity=8)` is computer vision: it groups touching white pixels into objects and returns a count, a label image, and per-object statistics.
- `n` includes the background, so the object count is `n - 1`.
- Each `stats` row is `x, y, w, h, area`: an OpenCV box, so x (column) comes first.

### 3. On a real image: blur vs detect

Download [sample-color.png](/images/sample-color.png) into the folder you run Python from.

```python
import cv2

img = cv2.imread("sample-color.png")
if img is None:
    raise FileNotFoundError("Could not read sample-color.png. Check the path.")

# Image processing: image in, image out
blurred = cv2.GaussianBlur(img, (9, 9), 0)
print("blurred:", blurred.shape, blurred.dtype)

# Computer vision: image in, information out
gray = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)
_, mask = cv2.threshold(gray, 50, 255, cv2.THRESH_BINARY)
contours, _ = cv2.findContours(mask, cv2.RETR_EXTERNAL, cv2.CHAIN_APPROX_SIMPLE)
print("objects found:", len(contours))
for x, y, w, h in sorted(cv2.boundingRect(c) for c in contours):
    print(f"  box x={x} y={y} w={w} h={h}")
```

Output:

```text
blurred: (200, 320, 3) uint8
objects found: 4
  box x=20 y=165 w=281 h=21
  box x=28 y=53 w=85 h=85
  box x=135 y=45 w=61 h=101
  box x=225 y=45 w=71 h=101
```

- `cv2.GaussianBlur(src, ksize, sigmaX)` smooths the image. `(9, 9)` is the size of the neighbourhood; `0` lets OpenCV choose the blur strength from that size. The result has the same shape as the input.
- `cv2.findContours(mask, cv2.RETR_EXTERNAL, cv2.CHAIN_APPROX_SIMPLE)` traces the outline of each white region. `RETR_EXTERNAL` keeps only outer outlines; `CHAIN_APPROX_SIMPLE` stores just the corner points of straight runs.
- `cv2.boundingRect(contour)` returns the upright box `(x, y, w, h)` around one outline.
- Four boxes: the orange bar, the red disc, the green block and the blue triangle. Every step before `findContours` was image processing; counting and boxing is computer vision. There is no machine learning anywhere in this code.

## OpenCV API notes

Versions: OpenCV 4.13.0 (`opencv-python==4.13.0.92`), NumPy 2.5.3. Signatures are copied from the installed library's help text.

| Function | Python signature | Returns | Kind |
|---|---|---|---|
| `cv2.GaussianBlur` | `GaussianBlur(src, ksize, sigmaX[, dst[, sigmaY[, borderType[, hint]]]]) -> dst` | image | image processing |
| `cv2.threshold` | `threshold(src, thresh, maxval, type[, dst]) -> retval, dst` | threshold, image | image processing |
| `cv2.findContours` | `findContours(image, mode, method[, contours[, hierarchy[, offset]]]) -> contours, hierarchy` | list of outlines | computer vision |
| `cv2.boundingRect` | `boundingRect(array) -> retval` | `(x, y, w, h)` | computer vision |
| `cv2.connectedComponentsWithStats` | `connectedComponentsWithStats(image[, labels[, stats[, centroids[, connectivity[, ltype]]]]]) -> retval, labels, stats, centroids` | count, label image, stats | computer vision |

**Inputs and types.**

- `findContours` and `connectedComponentsWithStats` expect a single-channel 8-bit image in which objects are non-zero: usually the output of a threshold.
- `connectedComponentsWithStats` returns statistics for every label **including the background label** (label 0). `connectivity` is 8 (diagonal neighbours count as touching) or 4.
- Boxes and centroids from OpenCV are in (x, y) order. To read a pixel inside a box with NumPy, index `[y, x]`.

**Where these live in the documentation.** Blur is in *Image Filtering*; contours, bounding boxes and connected components are in *Structural Analysis and Shape Descriptors* [6]. OpenCV's `ml` module covers statistical classification, regression and clustering [7]; its `dnn` module runs neural-network inference only and does not train networks [8].

**Speed.** In one test on a 2-core cloud machine (OpenCV 4.13.0), the grayscale → threshold → contours → boxes pipeline above took a median of about 0.12 ms on the 320 × 200 image, with no GPU. That speed, and the absence of training data, is why classical pipelines remain common in controlled industrial settings. (Chapter 7.7 shows how to measure it yourself.)

## Where it fails

- **Hand-written rules break when conditions change.** The threshold of 50 in the code works because the background is dark and even. Change the lighting, background or camera, and the count goes wrong. *Instead:* control the scene (59.3), use adaptive methods (13.5), or learn the rules from data (Parts F and J).
- **Touching objects merge.** Contours and connected components count one object where two touch. Rods packed tightly in a bundle are exactly this case. *Instead:* morphology (23), distance transform and watershed (23.5, 27.4), or a trained detector (54).
- **Deep learning needs data and can fail silently.** A trained model needs many labelled images, and on images unlike its training data it may give confident wrong answers. *Instead:* collect representative data (58), monitor drift (58.5), and keep simple rule-based checks as a safety net.
- **Detection is not measurement.** A box around a billet does not give its length in millimetres. *Instead:* camera calibration and pixel-to-mm conversion (41, 49).
- **No method rescues a bad image.** Motion blur, glare or poor focus defeat both classical CV and deep learning. *Instead:* fix the camera, lens and lighting first (Module 2, 59).

## ⚠️ Common mistakes

**1. Equating computer vision with AI.** Most of this chapter's code is computer vision with no learning at all. Ask "Does a simple pipeline solve this in controlled conditions?" before reaching for a neural network.

**2. Jumping to deep learning before fixing the image.** Poor lighting and a moving camera make *every* method worse. Spend the first effort on the camera, lens and lighting.

**3. Using a heavy model where a threshold works.** A detector needs training data, a GPU or more CPU time, and maintenance. A fixed pipeline on a fixed scene can be faster, cheaper and easier to explain to the plant.

**4. Feeding a model differently from how it was trained.** Deep models expect the same size, channel order (often RGB, while OpenCV gives BGR) and value scaling as their training images. A mismatch quietly lowers accuracy.

**5. Counting every contour.** Noise specks become "objects". Filter by area or shape before counting (24.3).

**6. Forgetting the background label.** `connectedComponentsWithStats` returns `n` labels including the background. The object count is `n - 1`.

**7. Reading a confidence score as accuracy.** A detection with confidence 0.96 is the model's own score for that box, not a guarantee. Measure accuracy on labelled test images (54.5, 58.4).

## 🔍 Go deeper

<GoDeeper>

### A continuum, not two boxes

Gonzalez and Woods describe image processing and computer vision as ends of a continuum: low-level processes (image in, image out), mid-level processes (image in, attributes out: segmentation, description, recognition of individual objects), and high-level processes ("making sense" of recognized objects) [1, Ch. 1]. The threshold-then-count code above spans low and mid level.

### Vision as an inverse problem

Szeliski describes computer vision as recovering properties of the world, such as shape, illumination and the objects present, from one or more images. Because many different scenes can produce the same image, this is an *inverse problem*, and it needs models and assumptions to solve [2, Ch. 1]. Image processing has no such inverse step: its input and output are both images.

### Representations: from Marr to deep networks

David Marr's influential book *Vision* (1982) framed seeing as building a sequence of representations, from intensity changes and edges ("primal sketch") up to surfaces and full three-dimensional object models [3]. Deep convolutional networks learn a comparable progression from data: visualizations of trained networks show early layers responding to edges and colour blobs, middle layers to textures and parts, and later layers to whole objects [5].

### Learning, defined

A widely quoted definition: a program *learns* from experience E with respect to some task T and performance measure P if its performance at T, as measured by P, improves with experience E [4]. In the defect example, T = classify rods, E = labelled examples, P = the fraction classified correctly.

### Deep learning and the 2012 turning point

Deep learning uses networks with many layers that learn representations at several levels of abstraction directly from data [9]. In 2012 a deep convolutional network (later called AlexNet) won the ImageNet image-classification challenge by a large margin [10]. That result started the shift of many vision tasks to deep learning. Detectors such as YOLO, which predicts boxes and classes in a single pass over the image, followed [11].

### Exercise 2 (coding)

Load `sample-color.png`. Using threshold + `findContours`, count the objects whose area is above 4000 pixels, and print the area of each object. Explain why the area filter changes the count.

<Solution>

```python
import cv2

img = cv2.imread("sample-color.png")
if img is None:
    raise FileNotFoundError("Could not read sample-color.png. Check the path.")

gray = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)
_, mask = cv2.threshold(gray, 50, 255, cv2.THRESH_BINARY)
contours, _ = cv2.findContours(mask, cv2.RETR_EXTERNAL, cv2.CHAIN_APPROX_SIMPLE)
```

```text

objects above 4000 px: 3
```

The triangle (area 3500) falls below the limit, so 3 objects remain. In real systems an area filter removes noise specks; here it shows that the rule you choose decides the count. Choosing such limits by hand is classical CV; learning them from data would be ML.

### Exercise 3 (by hand)

Design, as a list of steps, a **classical** system that checks whether every rod in a bundle has been cut (each rod end visible as a bright circle). Mark each step IP or CV, and name one condition under which you would switch to deep learning.

<Solution>

1. Capture a frame with a fixed camera and fixed lighting (set-up).
2. Crop the ROI around the bundle face (**IP**).
3. Convert to grayscale and reduce noise (**IP**).
4. Threshold the bright rod ends (**IP**).
