## 3. Family 1: point-wise operations

Let's start with the easiest. A point operation works on **each pixel individually**. For example: *add 20 to every pixel.*

<MatrixTransform
  before={[[10, 20, 30], [40, 50, 60], [70, 80, 90]]}
  after={[[30, 40, 50], [60, 70, 80], [90, 100, 110]]}
  rule="+ 20"
  highlight={[[0, 0]]}
/>

Notice something important: **10 → 30**. The new value depends **only on 10**. It doesn't care what the neighbouring pixels are. That's why it is called a **point-wise operation**.

## 4. Mathematical idea

We can describe it very simply as:

```text
output pixel = function(input pixel)
```

## 5. Brightness adjustment is a point operation

## 6. But there is a problem: 8-bit images

Remember: an 8-bit grayscale value runs from **0 to 255**. What happens with **240 + 30 = 270**? 8-bit cannot represent 270. So the result has to be handled appropriately, often by **clipping / saturation**:

<Equation terms={[{ value: "240" }, { op: "+", value: "30" }, { op: "=", value: "270", label: "too big" }, { op: "→", value: "255", label: "clipped", result: true }]} />

## 7. Thresholding can also be viewed as a point operation

We define:

```text
if pixel > 100:  output = 255
else:            output = 0
```

Then **80 → 0**, **150 → 255**, **200 → 255**, **50 → 0**. For an image:

## 10. Why do we need neighbouring pixels?

Imagine a noisy image:

<PixelMatrix size="lg" values={[[100, 100, 100], [100, 0, 100], [100, 100, 100]]} highlight={[[1, 1]]} />

The centre pixel suddenly became **0**. It might be noise. If we only look at the centre, **0**, we don't know anything. But if we look at its neighbours, we can see: *almost everything around it is 100.* Therefore, perhaps the centre should also be close to 100.

This is the basic intuition behind **filtering**. On a real image with scattered noise pixels:

Imagine this:

## 24. A more professional view

As you become advanced, you'll discover that the three-family classification is not always perfectly rigid. For example:

- Some operations combine local and global information.
- Morphological operations depend on neighbourhoods but can produce global structures.
- Histogram equalization uses global statistics to transform individual pixels.
- Fourier filtering transforms the entire image into another representation and modifies it there.
- Modern deep-learning layers can perform operations that don't fit neatly into these beginner categories.

<Callout kind="key">

Don't treat the three families as strict mathematical laws. Treat them as a **mental framework for understanding image operations**.

</Callout>

## Code

One image, one operation from each family, first by hand with NumPy, then with OpenCV.

### 1. From scratch: the three families on a 3 × 3 image

```python
import numpy as np

img = np.array([[10, 20, 30],
                [40, 50, 60],
                [70, 80, 90]], dtype=np.uint8)

# Family 1, point: each output pixel uses one input pixel
point = np.clip(img.astype(np.int16) + 20, 0, 255).astype(np.uint8)
print(point)

# Family 2, neighbourhood: the centre output uses all 9 pixels around it
print("centre mean:", img[0:3, 0:3].mean())

# Family 3, global: a histogram counts values over the whole image
values, counts = np.unique(img, return_counts=True)
print("histogram:", dict(zip(values.tolist(), counts.tolist())))
print("pixels from 50 to 100:", np.count_nonzero((img >= 50) & (img <= 100)))
```

Output:

```text
[[ 30  40  50]
 [ 60  70  80]
 [ 90 100 110]]
centre mean: 50.0
histogram: {10: 1, 20: 1, 30: 1, 40: 1, 50: 1, 60: 1, 70: 1, 80: 1, 90: 1}
pixels from 50 to 100: 5
```

### 2. From scratch: a 3 × 3 mean filter with a loop

```python
noisy = np.full((5, 5), 100, dtype=np.uint8)
noisy[2, 2] = 0                                  # one noise pixel

smooth = noisy.copy()
for r in range(1, 4):                            # interior only, so the 3 × 3 window fits
    for c in range(1, 4):
        window = noisy[r - 1:r + 2, c - 1:c + 2].astype(np.int32)
        smooth[r, c] = round(window.sum() / 9)

print(smooth)
```

Output:

```text
[[100 100 100 100 100]
 [100  89  89  89 100]
 [100  89  89  89 100]
 [100  89  89  89 100]
 [100 100 100 100 100]]
```

- `noisy[r - 1:r + 2, c - 1:c + 2]` is the 3 × 3 window around (r, c).
- Every pixel whose window contains the 0 drops to 800 / 9 ≈ 89. The noise is weakened and spread out, not removed.

### 3. The OpenCV way

```python
import cv2

print(cv2.blur(noisy, (3, 3)))
print(cv2.medianBlur(noisy, 3))

hist = cv2.calcHist([img], [0], None, [256], [0, 256])
print(hist.shape, int(hist.sum()), int(hist[50, 0]))
```

Output:

```text
[[100 100 100 100 100]
 [100  89  89  89 100]
 [100  89  89  89 100]
 [100  89  89  89 100]
 [100 100 100 100 100]]
[[100 100 100 100 100]
 [100 100 100 100 100]
 [100 100 100 100 100]
 [100 100 100 100 100]
 [100 100 100 100 100]]
(256, 1) 9 1
```

- `cv2.blur(src, ksize)` is the mean filter. `(3, 3)` is the window size. It matches our loop exactly, and also handles the border pixels (see API notes).
- `cv2.medianBlur(src, ksize)` takes the **median** of each window. One odd pixel out of nine never reaches the middle of the sorted list, so the noise pixel vanishes completely.
- `cv2.calcHist(images, channels, mask, histSize, ranges)`: `[img]` is a list of images, `[0]` the channel, `None` means no mask, `[256]` bins, `[0, 256]` the value range. It returns a 256 × 1 `float32` array; `hist[50, 0]` is how many pixels equal 50.

### 4. On a real image: one call from each family

Download [sample-scene.png](/images/sample-scene.png) into the folder you run Python from.

```python
import cv2

img = cv2.imread("sample-scene.png", cv2.IMREAD_GRAYSCALE)
if img is None:
    raise FileNotFoundError("Could not read sample-scene.png. Check the path.")

brighter = cv2.add(img, 40)                               # point
blurred = cv2.GaussianBlur(img, (5, 5), 0)                # neighbourhood
hist = cv2.calcHist([img], [0], None, [256], [0, 256])    # global

patch = img[5:35, 228:238]                                # a small, nearly flat area
print("point:   pixel [100, 160]", img[100, 160], "->", brighter[100, 160])
print("neighbourhood: noise (std) in the patch",
      round(float(patch.std()), 1), "->", round(float(blurred[5:35, 228:238].std()), 1))
print("global:  bins", hist.shape[0], "| pixels", int(hist.sum()),
      "| above 200:", int(hist[201:].sum()))
```

Output:

```text
point:   pixel [100, 160] 17 -> 57
neighbourhood: noise (std) in the patch 6.1 -> 2.0
global:  bins 256 | pixels 64000 | above 200: 7800
```

- The point operation changes one pixel from its own value: 17 + 40 = 57.
- The neighbourhood operation lowers the pixel-to-pixel noise in a flat area from a standard deviation of about 6 to about 2.
- The global operation summarizes all 64,000 pixels; `hist[201:]` adds up the bins for values 201 to 255.

| `cv2.calcHist` | `calcHist(images, channels, mask, histSize, ranges[, hist[, accumulate]]) -> hist` | global |
| `cv2.equalizeHist` | `equalizeHist(src[, dst]) -> dst` | global statistics, applied per pixel |
| `cv2.dft` | `dft(src[, dst[, flags[, nonzeroRows]]]) -> dst` | global / transform |

**Borders.** A 3 × 3 window at the edge reaches outside the image. OpenCV fills in the missing pixels: `cv2.blur` and `cv2.GaussianBlur` reflect the image without repeating the edge pixel by default (`BORDER_REFLECT_101`), while `cv2.medianBlur` repeats the edge pixel. The neighbourhood lab in section 11 uses the same rules, so its numbers match OpenCV's.

**Kernel sizes.** `ksize` for `medianBlur` must be odd and greater than 1 (3, 5, 7 …). For `GaussianBlur` both numbers must be odd and positive, or `(0, 0)` to compute them from `sigmaX`.

**`calcHist` arguments are lists.** `[img]`, `[0]`, `[256]` and `[0, 256]` are lists even for one image, because the same function builds histograms of several images and channels.

**Speed.** Point operations visit each pixel once. A k × k neighbourhood filter does about k² work per pixel, so a 15 × 15 filter is far heavier than a 3 × 3 one; OpenCV speeds up box and Gaussian filters by filtering rows and columns separately (17.4). A Fourier transform of an N-pixel image costs on the order of N log N operations (30.2).

## Where it fails

- **Point operations cannot see context.** They cannot remove a noise pixel or find an edge, because they never look at the neighbours. *Instead:* a neighbourhood filter (Module 18) or edge detector (Module 22).
- **Neighbourhood filters blur what you want to keep.** A mean or Gaussian filter softens edges along with the noise, which hurts measurement. *Instead:* edge-preserving filters such as median or bilateral (18.3, 18.4), and the smallest kernel that does the job.
- **The mean filter is a poor cure for impulse noise.** Section 10's comparison shows it only spreads salt-and-pepper pixels into grey smudges. *Instead:* the median filter (18.3).
- **Global statistics hide local problems.** A histogram says how many pixels are bright, not where they are. A small hot spot can vanish into the overall distribution. *Instead:* compute statistics inside an ROI (1.2), or locally (adaptive thresholding, 13.5; CLAHE, 12.3).
- **Some operations fit no family neatly.** Resizing, rotating and warping move pixels rather than recompute their values. *Instead:* treat them as geometric transforms (Module 16).

## ⚠️ Common mistakes

**1. Using a point operation to fix noise.** Brightness and contrast changes make noise more visible, not less. Noise needs a neighbourhood filter.

**2. Even kernel sizes.** `cv2.medianBlur(img, 4)` fails: the window must have a centre pixel, so the size must be odd.

**3. Forgetting the border.** Near the edge, part of each window lies outside the image, and the result depends on the border rule. Measurements in the outer `k // 2` pixels deserve extra caution.

**4. Passing calcHist bare values.** `cv2.calcHist(img, 0, None, 256, [0, 256])` fails; every argument except `mask` must be a list: `cv2.calcHist([img], [0], None, [256], [0, 256])`.

**5. Using `[0, 255]` as the histogram range.** The upper bound is exclusive, so `[0, 255]` leaves out pixels equal to 255. Use `[0, 256]`.

**6. Assuming bigger kernels are better.** A 15 × 15 blur removes more noise but also erases fine detail and costs far more time. Increase the size only until the noise is acceptable.

**7. Treating the families as strict laws.** Histogram equalization is global *and* point-wise; morphology is local but can join whole objects. Use the families to choose a starting point, not to argue about labels.

### The textbook view

Gonzalez and Woods write spatial operations as g(x, y) = T[f(x, y)], where T acts on a neighbourhood of (x, y). When the neighbourhood is a single pixel (1 × 1), T becomes an *intensity transformation* s = T(r): a point operation. Larger neighbourhoods give *spatial filtering* [1, Ch. 3]. Frequency-domain processing is treated separately: transform the image, operate on the transform, transform back [1, Ch. 4].

Szeliski's image-processing chapter is organised along the same lines: point operators first, then linear filtering and other neighbourhood operators, then Fourier transforms, then pyramids and wavelets, then geometric transformations [2, Ch. 3].

### Neighbourhood operations as a weighted sum

A linear neighbourhood filter computes, for every pixel, a weighted sum of the window:

```text
g(x, y) = Σ  w(s, t) · f(x + s, y + t)
         s,t
```

The weights w are the kernel. Strictly, this formula is *correlation*; *convolution* flips the kernel first. For symmetric kernels such as the 1/9 average the two are identical. OpenCV's `filter2D` documentation states that the function computes correlation, not convolution [3]. Chapter 17.2 works through both step by step.

### Why the median beats the mean on impulse noise

The mean adds every value with equal weight, so one extreme value (0 or 255) shifts the result. The median only depends on the *order* of the values: if fewer than half the window's pixels are noise, the middle value is a clean one. This is why one noise pixel in a 3 × 3 window disappears completely under the median but only shrinks under the mean.

### Histogram equalization: global statistics, point-wise mapping

OpenCV's `equalizeHist` computes the histogram of the whole image, turns its running total into a lookup table, and then maps every pixel through that table [4]. The table is global; applying it is a point operation. That is the "doesn't fit one box" case in section 24 (Chapter 12.2).

### Reading the stripe spectrum

The stripes in section 17 repeat every 16 pixels across a 320-pixel-wide image, so they complete 320 / 16 = 20 cycles. The two outer dots in the Fourier magnitude sit 20 positions left and right of the centre; the centre dot is the image's average brightness. Finer stripes would push the dots further out. That is what "frequency representation" means (Chapter 30).

### Exercise 1 (by hand)

For the centre pixel of this window, compute (a) the 3 × 3 mean and (b) the 3 × 3 median. Which result is closer to the surrounding values, and why?

```text
100  102   98
101  255   99
 97  100  103
```

<Solution>

(a) Sum = 100 + 102 + 98 + 101 + 255 + 99 + 97 + 100 + 103 = 1055. Mean = 1055 / 9 = 117.2 → **117**.

(b) Sorted: 97, 98, 99, 100, **100**, 101, 102, 103, 255. Median = **100**.

The median (100) matches the neighbours; the mean (117) is pulled up by the single outlier 255.

### Exercise 2 (coding)

Load `sample-scene-saltpepper.png`. Count the pixels that are exactly 0 or exactly 255 before filtering, after `cv2.blur(img, (3, 3))`, and after `cv2.medianBlur(img, 3)`.

<Solution>

```python
import cv2
import numpy as np

img = cv2.imread("sample-scene-saltpepper.png", cv2.IMREAD_GRAYSCALE)
if img is None:
    raise FileNotFoundError("Could not read sample-scene-saltpepper.png. Check the path.")

def extremes(a):
    return int(np.count_nonzero((a == 0) | (a == 255)))

print("noisy :", extremes(img))
print("mean  :", extremes(cv2.blur(img, (3, 3))))
print("median:", extremes(cv2.medianBlur(img, 3)))
```

Output:

```text
noisy : 4203
mean  : 0
median: 5
```

Both filters almost eliminate pure black and white pixels. But the numbers hide the difference: the mean gets to 0 only by smearing each noise pixel into a grey smudge over 9 pixels, while the median removes the noise pixels and leaves the scene sharp (look at the section 10 comparison). By this count the mean even looks better. Choosing the right measure matters as much as choosing the filter.

</Solution>

### Exercise 3 (coding)

Using only the histogram of `sample-scene.png` (not the image itself), find the fraction of pixels brighter than 200 and the darkest value that occurs.

<Solution>

```python
import cv2
import numpy as np

img = cv2.imread("sample-scene.png", cv2.IMREAD_GRAYSCALE)
if img is None:
    raise FileNotFoundError("Could not read sample-scene.png. Check the path.")

hist = cv2.calcHist([img], [0], None, [256], [0, 256]).ravel()

```


7800 of 64,000 pixels lie above 200. Both answers come from the 256 histogram counts alone: once you have the histogram, global questions no longer need the pixels.
