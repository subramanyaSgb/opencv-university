# 40.1 Frame differencing

<Definition term="Frame differencing">finding change between two frames by subtracting them and thresholding — covered in full in 14.5. This chapter's new question: what happens when you count the resulting blobs as if they were objects?</Definition>

14.5 already showed that two-frame differencing marks mainly a moving uniform object's *edges*, not its whole body, and leaves a "ghost" where the object just was. This module is about tracking real objects across frames — which means the very first real question is: does one moving object produce one detected blob, or more?

14.5 measured motion in percent of pixels found. Tracking needs something more concrete: a list of detections — bounding boxes or centroids — one per real object, ideally. `cv2.connectedComponentsWithStats` (25.1) turns a binary mask into exactly that: a label, a bounding box and an area for every separate connected region.

## 2. A real, measured surprise

<BlobCountLab caption="Real cv2.absdiff + connectedComponentsWithStats on a synthetic two-object video. Step through the frames and compare the true object count with the detected blob count."/>

Two real uniform objects — one light, moving right; one dark, moving left — on a textured background, run through a real `cv2.VideoWriter` → `cv2.VideoCapture` round trip, with two-frame differencing and connected-components counting on every frame:

```text
true objects:    2 (every frame)
detected blobs:  4 (frame 5, frame 20 -- and nearly every other frame)
```

**Two real objects produce four detected blobs.** This is exactly 14.5's edge/ghost finding, now at the level that matters for tracking: each uniform object's own motion shows up as *two* separate connected regions (its leading edge and its trailing edge), not one. A naive "count the blobs" approach would report twice the real number of objects.

## 3. Why this matters for the rest of the module

Every tracking method from 40.4 onward (MeanShift/CamShift, Kalman, particle filters) needs *detections* to track — and 40.7's counting needs those detections to correspond to real objects, not edges. Section 2's real 2-for-1 over-count is not a one-off: it is the direct, structural consequence of differencing a *uniform* object against *itself* one frame later, which 14.5 already explained at the pixel level. Fixing it needs a detector that marks the object's whole body, not just where it changed — which is exactly what background subtraction (40.2) does differently.

```python
predicted_blobs = true_objects * blobs_per_object
```


### 2. OpenCV: a real video round trip, differencing, and blob counting

```python
# Needs the two_obj.mp4 test file generated by this chapter's own setup (see the text)
import cv2

cap = cv2.VideoCapture("two_obj.mp4")
prev = None
detected_counts = []
while True:
    ok, frame = cap.read()
    if not ok:
        break
    gray = frame[:, :, 0] if frame.ndim == 3 else frame
    if prev is not None:
        mask = (cv2.absdiff(gray, prev) > 25).astype(np.uint8) * 255
        mask = cv2.morphologyEx(mask, cv2.MORPH_CLOSE, np.ones((5, 5), np.uint8))
        n, labels, stats, centroids = cv2.connectedComponentsWithStats(mask)
        blobs = [s for s in stats[1:] if s[4] >= 20]       # area >= 20 px
        detected_counts.append(len(blobs))
    prev = gray
cap.release()
print("detected blobs, frames 5 and 20:", detected_counts[4], detected_counts[19])
```

Typical output (one machine, matching Section 2's real precomputed result):

```text
detected blobs, frames 5 and 20: 4 4
```

## OpenCV API notes

- **`cv2.connectedComponentsWithStats(mask)`** (25.1): returns `(n, labels, stats, centroids)`; `stats[i] = [x, y, w, h, area]` for label `i` (label 0 is the background). Filtering by `area` (Code section 2) removes single-pixel noise before counting.
- **`cv2.morphologyEx(mask, cv2.MORPH_CLOSE, kernel)`**: closes small gaps inside a blob before labelling — without it, a noisy edge can fragment into several tiny components instead of one clean blob (Module 16).
- **No new `cv2` call is needed for "turn a mask into detections"** — this chapter combines two calls already covered elsewhere (`absdiff`, 14.5; `connectedComponentsWithStats`, 25.1) in a new order, for a new purpose.

## Where it fails

- **The 2-blobs-per-object pattern breaks down further when objects are close together** — two nearby objects' edge-blobs can merge into one connected region, or a single object's own two edges can merge if it is small relative to its own motion per frame, making even "divide by 2" an unreliable correction.
- **Three-frame differencing (14.5) removes the ghost but can remove the whole uniform object too** — not a free fix for this chapter's over-count, as 14.5 already measured directly (0% found on the same kind of object).
- **This chapter's fix is diagnostic, not corrective** — it measures and explains the over-count; actually avoiding it needs a different detector (background subtraction, 40.2), not a cleverer way to post-process two-frame differencing's blobs.

## ⚠️ Common mistakes

<Callout kind="mistake">

- **Treating "number of connected components" as "number of objects"** without checking, as this chapter's own real test shows a 2x discrepancy for the simplest possible case (two separate uniform objects, no occlusion).
- **Skipping the area filter** before counting components — a handful of few-pixel noise specks easily doubles or triples a naive blob count on real, noisy footage.
- **Assuming the over-count is always exactly 2x** — Where it fails: merging and occlusion make the real relationship between blobs and objects scene-dependent, not a fixed ratio.

</Callout>

## 🔍 Go deeper

<GoDeeper>

### Why background subtraction (next chapter) does not have this problem

Two-frame differencing compares a frame only to its *immediate predecessor*, so a uniform object's unchanged interior always looks identical across that one-frame gap. Background subtraction instead compares each frame to a *model of the empty background* (14.5's "empty reference" and "running average" methods were simple versions of this) — against a background that never contains the object at all, the object's whole body differs from the background, not just its edges, so one real object produces one real foreground blob. 40.2 measures this directly.

</GoDeeper>
