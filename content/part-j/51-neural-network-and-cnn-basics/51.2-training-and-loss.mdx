# 51.2 Training and loss

<Definition term="Loss function">a single real number that measures how wrong a network's current output is — training is nothing but repeatedly nudging the weights in whichever direction makes that one number smaller.</Definition>

51.1 covered what a network computes once its weights are fixed. This chapter covers where those weights actually come from: a real **loss function** that scores how wrong the network currently is, and **gradient descent**, which repeatedly nudges every weight in the direction that makes that score smaller — verified here from scratch, including the one check that is easy to skip and easy to get wrong: whether the hand-derived gradient is actually correct.

## 1. An analogy

Imagine adjusting a shower's single hot/cold knob with your eyes closed, feeling only how far the water is from comfortable. Too cold — turn toward hot, a little. Still a bit cold — turn a little more, but less this time. Overshoot into too hot — turn back. Each adjustment uses only "how wrong am I, and in which direction" — never the exact right answer, only the local slope of wrong-ness. Gradient descent trains a neuron exactly this way: the loss is "how wrong," and the gradient is "which way, and how much, to turn each knob."

## 3. A real worked result: a single neuron, trained from nothing

Starting from all-zero weights (w = [0, 0], b = 0 — a neuron that has learned nothing yet, predicting p = 0.5 for everything), training a sigmoid neuron with binary cross-entropy loss by real gradient descent on 60 points split into two Gaussian blobs gives a loss that starts at **0.6931** — exactly ln 2, the real cross-entropy of guessing p = 0.5 for everything when half the labels are 0 and half are 1 — and falls to **0.0205** after 200 steps, with accuracy jumping from chance (50%) to a perfect 100% by iteration 40. Nothing about the data or the labels changed; only the weights moved, one small step at a time, each step strictly reducing the loss.

## 4. The step most tutorials skip: checking the gradient is actually right

Every one of those weight updates depends on a gradient computed by hand, via the chain rule. If that hand-derived formula has a bug, training can still *appear* to work — or quietly fail in a way that is hard to notice. The real, standard way to catch this is a **gradient check**: compute the gradient two completely different ways and see if they agree. The analytic route uses the hand-derived chain-rule formula; the numeric route nudges one weight by a tiny amount ε in each direction and measures how much the loss itself actually changed (a central finite difference). At an arbitrary point (w = [0.3, −0.2], b = 0.1), both routes give **[−0.584012, −0.423788]**, agreeing to **1.03 × 10⁻⁹** — strong, real evidence the hand-derived gradient used in Section 3 was correct all along.

## 5. A real, dramatic result: what a hidden layer makes possible

51.1's own real, verified fact was that stacked *linear* layers collapse to one linear layer. Training makes that fact bite: on a genuinely non-linearly-separable dataset (four blobs arranged so that diagonal corners share a label — no single straight line separates the two classes), a single logistic-regression neuron, trained for 2000 real gradient-descent steps, plateaus at **exactly 50% accuracy** — chance level, no better than guessing, however long it trains. A 2-layer network (2 inputs → 6 tanh hidden units → 1 sigmoid output), trained the identical way on the identical data, reaches **100% accuracy** (loss falling from 0.7720 to 0.0016 over 2000 steps). The only difference between the two runs is the hidden layer — direct, measured proof that depth plus nonlinearity is not a cosmetic choice but the real reason some problems are learnable at all.

## 6. Cross-checking against OpenCV's own trainable network

51.1 verified NumPy's forward pass against `cv2.ml.ANN_MLP`'s forward pass. This chapter closes the loop: training `cv2.ml.ANN_MLP` with its own real `BACKPROP` method, on the identical XOR-like data, for the identical 2000 iterations, independently reaches the identical real conclusion — **100% accuracy** — confirming the from-scratch implementation in Sections 3–5 is not a fluke of one particular NumPy script.

## 7. Industrial context: this loop, at scale

A production defect classifier (37, 54 onward) is trained by exactly this loop — forward pass, loss, gradient, update, repeat — just with millions of weights, far more data, and far more compute than this chapter's tiny examples. The loss function changes with the task (cross-entropy for classification here; other losses for regression or detection), and the network architecture changes (53 covers real structures), but the training *loop itself* is the one in Section 2, unchanged. The one new worry this introduces — a network fitting its training data perfectly while failing on new data — is 51.5's own subject.

## Mini exercise

**Q1.** Section 3's own training run started at loss = 0.6931 at iteration 0, before any weight update happened. Why exactly that number, and not some other value?

<Solution>

Because at iteration 0 the weights are all zero, so every input gives z = 0 and p = sigmoid(0) = 0.5 for every single point, regardless of its true label. The binary cross-entropy of predicting p = 0.5 for everything is −ln(0.5) = ln 2 ≈ 0.6931, exactly the chance-level loss any binary classifier starts at before it has learned anything — not a coincidence specific to this dataset.

</Solution>

## Code

### 1. NumPy: a single neuron, trained from scratch by gradient descent

```python
import numpy as np
import cv2

rng = np.random.default_rng(42)
n = 60
X0 = rng.normal(loc=[-1.5, -1.0], scale=0.8, size=(n // 2, 2))
X1 = rng.normal(loc=[1.5, 1.0], scale=0.8, size=(n // 2, 2))
X = np.vstack([X0, X1]).astype(np.float64)
y = np.concatenate([np.zeros(n // 2), np.ones(n // 2)])

def sigmoid(z):
    return 1 / (1 + np.exp(-z))

def bce_loss(p, y):
    eps = 1e-9
    return -np.mean(y * np.log(p + eps) + (1 - y) * np.log(1 - p + eps))

w = np.zeros(2)
b = 0.0
lr = 0.5
for it in range(201):
    z = X @ w + b
    p = sigmoid(z)
    loss = bce_loss(p, y)
    if it % 40 == 0:
        acc = np.mean((p > 0.5) == y)
        print(f"iter {it:3d}: loss={loss:.4f}, accuracy={acc:.3f}")
    grad_z = (p - y) / n
    grad_w = X.T @ grad_z
    grad_b = grad_z.sum()
    w -= lr * grad_w
    b -= lr * grad_b
print(f"final weights w={w.round(4)}, b={b:.4f}")
```

Output:

```text
iter   0: loss=0.6931, accuracy=0.500
iter  40: loss=0.0517, accuracy=1.000
iter  80: loss=0.0347, accuracy=1.000
iter 120: loss=0.0275, accuracy=1.000
iter 160: loss=0.0233, accuracy=1.000
iter 200: loss=0.0205, accuracy=1.000
final weights w=[3.1874 2.2546], b=0.5154
```

### 2. NumPy: checking the gradient by finite differences

```python
def loss_at(w_, b_):
    p_ = sigmoid(X @ w_ + b_)
    return bce_loss(p_, y)

w_test = np.array([0.3, -0.2])
b_test = 0.1
eps = 1e-6
analytic_grad_w = X.T @ ((sigmoid(X @ w_test + b_test) - y) / n)
numeric_grad_w = np.zeros(2)
for i in range(2):
    w_plus = w_test.copy(); w_plus[i] += eps
    w_minus = w_test.copy(); w_minus[i] -= eps
    numeric_grad_w[i] = (loss_at(w_plus, b_test) - loss_at(w_minus, b_test)) / (2 * eps)
print("Gradient check at w=[0.3,-0.2], b=0.1:")
print(f"analytic grad_w = {analytic_grad_w.round(6)}")
print(f"numeric  grad_w = {numeric_grad_w.round(6)}")
print(f"max abs difference: {np.max(np.abs(analytic_grad_w - numeric_grad_w)):.2e}")
```

Output:

```text
Gradient check at w=[0.3,-0.2], b=0.1:
analytic grad_w = [-0.584012 -0.423788]
numeric  grad_w = [-0.584012 -0.423788]
max abs difference: 1.03e-09
```

### 3. NumPy: what a hidden layer makes learnable

The dataset below places four Gaussian blobs at the corners of a square, with diagonally opposite corners sharing a label — a classic non-linearly-separable arrangement: no single straight line can put both label-0 corners on one side and both label-1 corners on the other.

```python
rng2 = np.random.default_rng(5)
m = 80
centers = np.array([[-1.5, -1.5], [1.5, 1.5], [-1.5, 1.5], [1.5, -1.5]])
labels_c = np.array([0, 0, 1, 1])
Xh = []
yh = []
for c, lab in zip(centers, labels_c):
    pts = rng2.normal(loc=c, scale=0.5, size=(m // 4, 2))
    Xh.append(pts)
    yh.append(np.full(m // 4, lab))
Xh = np.vstack(Xh)
yh = np.concatenate(yh)

rng3 = np.random.default_rng(9)
Wi = rng3.normal(scale=0.5, size=(2, 6))
bi = np.zeros(6)
Wo = rng3.normal(scale=0.5, size=(6, 1))
bo = np.zeros(1)

lr = 0.5
print("2-layer network (2->6 tanh ->1 sigmoid), backprop on a non-linearly-separable (XOR-like) dataset:")
for it in range(2001):
    z1 = Xh @ Wi + bi
    a1 = np.tanh(z1)
    z2 = a1 @ Wo + bo
    p = sigmoid(z2).ravel()
    loss = bce_loss(p, yh)
    if it % 400 == 0:
        acc = np.mean((p > 0.5) == yh)
        print(f"iter {it:4d}: loss={loss:.4f}, accuracy={acc:.3f}")
    grad_z2 = ((p - yh) / m).reshape(-1, 1)
    grad_Wo = a1.T @ grad_z2
    grad_bo = grad_z2.sum(axis=0)
    grad_a1 = grad_z2 @ Wo.T
    grad_z1 = grad_a1 * (1 - a1 ** 2)
    grad_Wi = Xh.T @ grad_z1
    grad_bi = grad_z1.sum(axis=0)
    Wo -= lr * grad_Wo; bo -= lr * grad_bo
    Wi -= lr * grad_Wi; bi -= lr * grad_bi
acc_final = np.mean((p > 0.5) == yh)
print(f"final accuracy: {acc_final:.3f}")

w_lin = np.zeros(2)
b_lin = 0.0
for it in range(2001):
    p_lin = sigmoid(Xh @ w_lin + b_lin)
    grad_z = (p_lin - yh) / m
    w_lin -= lr * (Xh.T @ grad_z)
    b_lin -= lr * grad_z.sum()
acc_lin = np.mean((p_lin > 0.5) == yh)
print(f"single logistic-regression neuron (no hidden layer) on the same data: final accuracy={acc_lin:.3f}")
```

Output:

```text

iter    0: loss=0.7720, accuracy=0.500
iter  400: loss=0.0105, accuracy=1.000
iter  800: loss=0.0049, accuracy=1.000
iter 1200: loss=0.0030, accuracy=1.000
iter 1600: loss=0.0021, accuracy=1.000
iter 2000: loss=0.0016, accuracy=1.000
final accuracy: 1.000
```

### 4. OpenCV: cv2.ml.ANN_MLP's own BACKPROP reaches the same conclusion

```python
Xh32 = Xh.astype(np.float32)
yh32 = yh.astype(np.float32)
Yh = (np.stack([1 - yh32, yh32], axis=1) * 2 - 1).astype(np.float32)

ann = cv2.ml.ANN_MLP_create()
ann.setLayerSizes(np.array([2, 6, 2]))
ann.setActivationFunction(cv2.ml.ANN_MLP_SIGMOID_SYM, 1, 1)
ann.setTrainMethod(cv2.ml.ANN_MLP_BACKPROP, 0.1, 0.1)

flags = cv2.ml.ANN_MLP_NO_INPUT_SCALE | cv2.ml.ANN_MLP_NO_OUTPUT_SCALE

ann.train(td, flags)
_, pred = ann.predict(Xh32)
pred_label = (pred[:, 1] > pred[:, 0]).astype(np.float32)
acc_cv2 = np.mean(pred_label == yh32)
```


## OpenCV API notes

- **`cv2.ml.ANN_MLP.train(trainData, flags)`** (Code section 4) runs OpenCV's own real backpropagation, not a toy; this chapter's own result shows it reaching the identical conclusion as the from-scratch implementation, independently.
- **`setTrainMethod(cv2.ml.ANN_MLP_BACKPROP, dw_scale, momentum_scale)`** sets plain backprop with momentum; `ANN_MLP_RPROP` and `ANN_MLP_ANNEAL` (not used here) are alternative, often faster training methods available on this build.
- **No `cv2` function is needed for 51.1's own chain-rule gradient derivation or this chapter's gradient check** — those are real mathematics, verified directly in NumPy; `cv2.ml.ANN_MLP` is used here only as an independent, real cross-check of the end result.

## Where it fails

- **A single neuron (or any stack of purely linear layers, 51.1) cannot learn a non-linearly-separable problem, however long it trains** — Section 5's own real, measured 50% ceiling, not a matter of more iterations or a better learning rate.
- **A hand-derived gradient can be silently wrong without a gradient check** — Section 4's own real verification step; skipping it risks training that looks plausible but is quietly using the wrong direction for some weights.
- **This chapter's gradient descent used a fixed learning rate and no momentum, batching, or adaptive step sizes** — real production training (51.2's own industrial context, Section 7) typically uses more sophisticated optimizers; the core loop is identical, but convergence speed and stability can differ substantially.

## ⚠️ Common mistakes

<Callout kind="mistake">

- **Assuming more training iterations will eventually fix a model that cannot represent the right function at all** — Section 5's own real result: the single neuron's 50% ceiling does not improve with more of the identical training, because the problem is architectural, not a training-duration problem.
- **Skipping the gradient check and trusting a hand-derived backprop formula on faith** — Section 4's own real, standard safeguard.
- **Forgetting that a too-high learning rate affects different architectures differently** — a learning rate that trains a single neuron smoothly can genuinely destabilize a deeper network trained on the identical data (Exercise 3), because the sigmoid output's gradient self-limits in a way a multi-layer chain of gradients does not.
- **Confusing accuracy with loss as the thing gradient descent directly minimizes** — gradient descent in this chapter always minimizes the loss (binary cross-entropy); accuracy is reported alongside it as a separate, more interpretable measure, and the two do not always move in lockstep step by step.

</Callout>

## 🔍 Go deeper

<GoDeeper>

### Why cross-entropy, and not squared error, for classification

Binary cross-entropy's gradient with respect to z is simply `(p − y)` (used directly in Code sections 1 and 3) — a clean, well-behaved signal that stays large while the prediction is confidently wrong and shrinks smoothly as it becomes correct; mean squared error on a sigmoid output instead multiplies by an extra `p(1−p)` term that can shrink the gradient towards zero even while the prediction is still badly wrong, a real, known reason cross-entropy is the standard choice for classification.

### Backpropagation is the chain rule, applied layer by layer

Section 5's own `grad_a1 = grad_z2 @ Wo.T` followed by `grad_z1 = grad_a1 * (1 - a1**2)` is backpropagation in miniature: the chain rule applied once per layer, working backward from the loss to the earliest weights — exactly the algorithm Rumelhart, Hinton and Williams popularized in 1986, scaled up by modern frameworks to networks with billions of weights.

</GoDeeper>

### Exercise 1 (by hand)

Based on Section 3's own result (loss falls from 0.6931 to 0.0205 over 200 iterations, with accuracy already at 100% by iteration 40), would you expect training for many more iterations to keep improving accuracy much further?

<Solution>

Not much, in terms of accuracy — it is already 100% by iteration 40 and stays there. The loss can keep falling (the model becoming more *confident* in its already-correct predictions, pushing p closer to 0 or 1), but accuracy itself has no further room to improve on this dataset once every point is already classified correctly.

</Solution>

### Exercise 3 (thinking)

Section 3's own learning rate was 0.5. Train the single neuron from Code section 1 with lr = 5.0 (ten times larger) for just the first 10 iterations, then do the same for the 2-layer network from Code section 3. Based on the real result, does a too-high learning rate affect both architectures the same way?

<Solution>

No — a real, honest, architecture-dependent difference. Running the single neuron at lr = 5.0 gives losses `[0.6931, 0.0222, 0.0212, 0.0204, 0.0197, 0.019, 0.0184, 0.0179, 0.0174, 0.017]` — it still falls smoothly, even faster than Section 3's own lr = 0.5 run, because the sigmoid output's gradient naturally shrinks as predictions approach certainty, self-limiting how large a step a high learning rate can actually cause. Running the 2-layer network at the identical lr = 5.0 gives `[0.772, 1.1257, 1.1378, 0.9702, 0.7033, 0.9365, 1.6421, 1.1999, 1.1827, 2.3902]` — the loss genuinely spikes up to 2.3902 (worse than where it started) before later recovering, because gradients chained back through a hidden layer are not self-limiting the same way. A learning rate safe for a single neuron is not automatically safe for a deeper network on the identical data.

</Solution>

```python
    Wo2 -= lr * grad_Wob; bo2 -= lr * grad_bob
    Wi2 -= lr * grad_Wib; bi2 -= lr * grad_bib
acc2 = np.mean((pb > 0.5) == yh)
print(f"2 hidden units: final accuracy={acc2:.3f}")
```

Output:

```text
2 hidden units: final accuracy=1.000
```

Just 2 hidden units are already enough to solve this particular XOR-like problem — Section 5's own 6-unit choice was not a minimum requirement, only a comfortable, easily-trainable size.
