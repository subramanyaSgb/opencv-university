# 51.5 Overfitting

<Definition term="Overfitting">a network's loss on data it was trained on keeps improving while its loss on data it has never seen gets worse — memorizing the specific training examples, including their noise, instead of learning the real underlying rule.</Definition>

36.4 and 36.5 already warned about this for SVMs and decision trees, and both pointed here for the real, measured version in a trained network. 51.2's own training loop and 51.3's own generalization test both previewed this chapter directly. This chapter reproduces the real phenomenon from scratch — including the moment training actively starts making things worse on new data — and verifies two real, independent remedies.

## 1. An analogy

A student who memorizes the exact answer key to last year's practice exam will score perfectly on *that* exam, having learned nothing transferable. Handed this year's exam, testing the identical material with different questions, the memorizing student does worse than one who understood the underlying material, even though the memorizer's practice-exam score looked better the whole time. A network can do exactly this with its own training data.

## 3. A real, textbook overfitting curve

Take a deliberately oversized network (60 hidden units) and a deliberately small, slightly noisy training set (40 points, 10% of the labels flipped). Training it, with no safeguards at all, for 5000 real gradient-descent steps gives:

```text
epoch     0: train_loss=0.6984 val_loss=0.6036 train_acc=0.725 val_acc=0.727
epoch   500: train_loss=0.3345 val_loss=0.5082 train_acc=0.875 val_acc=0.723
epoch  1000: train_loss=0.2172 val_loss=0.8269 train_acc=0.950 val_acc=0.693
epoch  2000: train_loss=0.1017 val_loss=1.3829 train_acc=0.975 val_acc=0.657
epoch  3500: train_loss=0.0562 val_loss=1.9222 train_acc=1.000 val_acc=0.657
epoch  5000: train_loss=0.0365 val_loss=2.3204 train_acc=1.000 val_acc=0.640
```

Training accuracy climbs to a perfect 100% — the network has memorized every one of the 40 training points, including the 10% whose labels were simply wrong. Validation loss, on data it never trained on, does the opposite: it falls for the first few hundred steps, then rises continuously for the rest of training, and validation accuracy never again reaches its own very first value (0.727 at epoch 0). More training, past a certain point, made the network measurably worse at the real task.

## 4. A real, dramatic remedy: L2 regularization

Adding one term to the loss — a penalty proportional to the sum of the squared weights (so large weights cost something, pushing the network toward simpler solutions) — and retraining the identical network on the identical data gives a completely different real curve:

```text
epoch     0: train_loss=0.6984 val_loss=0.6036 train_acc=0.725 val_acc=0.727
epoch   500: train_loss=0.4340 val_loss=0.4401 train_acc=0.775 val_acc=0.807
epoch  1000: train_loss=0.4282 val_loss=0.4386 train_acc=0.800 val_acc=0.803
epoch  2000: train_loss=0.4198 val_loss=0.4396 train_acc=0.800 val_acc=0.807
epoch  3500: train_loss=0.4186 val_loss=0.4400 train_acc=0.800 val_acc=0.800
epoch  5000: train_loss=0.4186 val_loss=0.4400 train_acc=0.800 val_acc=0.800
```

Train loss and validation loss now converge together and *stay* together — the network settles at 80% training accuracy (it can no longer memorize the 10% of mislabeled points) and, far more importantly, a real **80.0–80.7%** validation accuracy throughout, instead of the unregularized run's final **64.0%**. The identical architecture, the identical data, one extra term in the loss: a measured 16-point real swing in final validation accuracy.

## 5. A second, independent remedy: stopping in time

Section 3's own unregularized run never needed regularization to be rescued, had it simply stopped sooner: its own checkpoint at epoch 500 (val_loss = 0.5082, val_acc = 0.723) is dramatically better than training all the way to epoch 5000 (val_loss = 2.3204, val_acc = 0.640) — with no regularization at all. Watching the validation loss during training and stopping once it stops improving (**early stopping**) is a real, independent remedy to the identical problem, achieved purely by *when* you stop, not by changing the model or the loss.

## 6. Checking the regularization term itself

Adding a new term to the loss means a new term in the gradient — this chapter's own `l2 * W` added directly to each weight's gradient. Checked against an independent finite-difference estimate of the *full* regularized loss (binary cross-entropy plus the L2 penalty), the analytic and numeric gradients agree to **3.97 × 10⁻¹⁰** — the regularization term is being applied correctly, not just plausibly.

## 7. Industrial context: this is where the formal methodology lives

This chapter used just enough of a train/validation split to show the real phenomenon. The formal methodology — how to build splits properly, cross-validation, avoiding leakage between training and evaluation data — is covered in depth in 58.2 ("Splits"), building on this chapter's own real demonstration of *why* that methodology matters in the first place. 36.4's and 36.5's own classical-ML overfitting warnings and this chapter's neural-network version are the same underlying risk, seen through two different kinds of model.

## Code

### 1. NumPy: reproducing the real overfitting curve

```python
import numpy as np
import cv2

def sigmoid(z):
    return 1 / (1 + np.exp(-z))

def bce_loss(p, y):
    eps = 1e-9
    return -np.mean(y * np.log(p + eps) + (1 - y) * np.log(1 - p + eps))

rng = np.random.default_rng(50)

def sample(n, rng):
    half = n // 2
    X0 = rng.normal(loc=[-0.8, -0.8], scale=1.2, size=(half, 2))
    X1 = rng.normal(loc=[0.8, 0.8], scale=1.2, size=(n - half, 2))
    X = np.vstack([X0, X1])
    y = np.concatenate([np.zeros(half), np.ones(n - half)])
    return X, y

X_train, y_train = sample(40, rng)
flip = rng.random(40) < 0.1
y_train = np.where(flip, 1 - y_train, y_train)
X_val, y_val = sample(300, np.random.default_rng(51))

def init_model(hidden, seed):
    r = np.random.default_rng(seed)
    Wi = r.normal(scale=0.5, size=(2, hidden))
    bi = np.zeros(hidden)
    Wo = r.normal(scale=0.5, size=(hidden, 1))
    bo = np.zeros(1)
    return Wi, bi, Wo, bo

def forward(X, Wi, bi, Wo, bo):
    z1 = X @ Wi + bi
    a1 = np.tanh(z1)
    z2 = a1 @ Wo + bo
    p = sigmoid(z2).ravel()
    return a1, p

def train(hidden, l2, epochs, seed=7, lr=0.3):
    Wi, bi, Wo, bo = init_model(hidden, seed)
    n = len(X_train)
    for epoch in range(epochs + 1):
        a1, p = forward(X_train, Wi, bi, Wo, bo)
        if epoch % 500 == 0:
            _, p_val = forward(X_val, Wi, bi, Wo, bo)
            print(f"epoch {epoch:5d}: train_loss={bce_loss(p, y_train):.4f} val_loss={bce_loss(p_val, y_val):.4f} "
                  f"train_acc={np.mean((p>0.5)==y_train):.3f} val_acc={np.mean((p_val>0.5)==y_val):.3f}")
        grad_z2 = ((p - y_train) / n).reshape(-1, 1)
        grad_Wo = a1.T @ grad_z2 + l2 * Wo
        grad_bo = grad_z2.sum(axis=0)
        grad_a1 = grad_z2 @ Wo.T
        grad_z1 = grad_a1 * (1 - a1 ** 2)
        grad_Wi = X_train.T @ grad_z1 + l2 * Wi
        grad_bi = grad_z1.sum(axis=0)
        Wo -= lr * grad_Wo; bo -= lr * grad_bo
        Wi -= lr * grad_Wi; bi -= lr * grad_bi

print("NO regularization:")
train(60, 0.0, 5000)
```

### 3. NumPy: checking the L2 gradient term by finite differences

```python
l2 = 0.01
Wi0, bi0, Wo0, bo0 = init_model(5, 3)

def total_loss(Wi_, bi_, Wo_, bo_, l2_):
    _, p_ = forward(X_train, Wi_, bi_, Wo_, bo_)
    return bce_loss(p_, y_train) + 0.5 * l2_ * (np.sum(Wi_ ** 2) + np.sum(Wo_ ** 2))

a1c, pc = forward(X_train, Wi0, bi0, Wo0, bo0)
n = len(X_train)
grad_z2c = ((pc - y_train) / n).reshape(-1, 1)
analytic_grad_Wo00 = (a1c.T @ grad_z2c + l2 * Wo0)[0, 0]

eps = 1e-6
Wo_plus = Wo0.copy(); Wo_plus[0, 0] += eps
Wo_minus = Wo0.copy(); Wo_minus[0, 0] -= eps
numeric_grad_Wo00 = (total_loss(Wi0, bi0, Wo_plus, bo0, l2) - total_loss(Wi0, bi0, Wo_minus, bo0, l2)) / (2 * eps)
print(f"analytic={analytic_grad_Wo00:.6f}, numeric={numeric_grad_Wo00:.6f}, diff={abs(analytic_grad_Wo00-numeric_grad_Wo00):.2e}")
```

Output:

```text
analytic=-0.178744, numeric=-0.178744, diff=3.97e-10
```

## OpenCV API notes

- **No `cv2` function trains a regularized network or performs early stopping** — like 51.2's own note, `cv2.ml.ANN_MLP` is a basic, dense-only trainer; L2 regularization and validation-based stopping are standard features of real deep learning frameworks, outside this course's pinned OpenCV dependency.
- **`cv2.ml.ANN_MLP`'s `setTermCriteria`** can cap the maximum number of training iterations, which is a crude relative of early stopping (a fixed budget rather than monitoring validation loss), but does not itself watch a held-out set the way Section 5's own real remedy does.

## Where it fails

- **This chapter's train/validation split was deliberately minimal** — one fixed split, no cross-validation, no repeated trials; 58.2 covers the formal methodology this chapter intentionally did not.
- **Too little regularization barely helps** — a real, verified exercise result: 10x less weight decay (0.001 instead of 0.01) let overfitting mostly return (validation accuracy 66.0%, close to the unregularized run's 64.0%).
- **Regularization strength and architecture size both matter together** — this chapter fixed the network at 60 hidden units; a different size would need a different regularization strength to show the identical real effect.
- **Early stopping needs an actual validation set to watch** — it is not a free remedy that works without held-out data, the same real requirement L2 regularization's own verification needed.

## ⚠️ Common mistakes

<Callout kind="mistake">

- **Trusting training accuracy alone as a measure of a network's quality** — Section 3's own real result: 100% training accuracy coincided with the network's worst real-world (validation) performance of the entire run.
- **Assuming more training epochs can only help** — Mini exercise: a direct, real counterexample.
- **Using a regularization strength that is too small to matter** — Where it fails: a real, verified result showing 10x too little weight decay barely changed the outcome.
- **Forgetting that more data is itself a real remedy, not just a "nice to have"** — Exercise 4's own real result: more training data reduced overfitting without touching the model or the loss function at all.

</Callout>

## 🔍 Go deeper

<GoDeeper>

### Why L2 regularization is called "weight decay"

Adding `l2 * W` to the gradient and then subtracting `lr * (gradient)` is algebraically the same as multiplying every weight by `(1 - lr * l2)` before the usual gradient step — every weight genuinely "decays" toward zero a little on every single step, independent of what the data says, which is exactly why large weights (and the sharply-bending decision boundaries they allow) become more expensive to maintain.

### Other real regularization techniques

Dropout (randomly zeroing some hidden units during training, different ones each step) and data augmentation (15.6's own classical techniques, extended for deep learning in 58.3) are two other standard, real techniques that reduce overfitting through entirely different mechanisms than L2's weight penalty — forcing a network not to rely on any single unit too heavily, and directly enlarging the effective training set, respectively.

</GoDeeper>
